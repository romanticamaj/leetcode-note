# C++ 心法：預防整數溢位 (Integer Overflow Prevention)

在 C++ 中，當兩個 `int` 型別的變數相乘時，其結果預設也會是 `int` 型別。如果這個乘積超過了 `int` 能表示的最大範圍（通常是 2^31 - 1），就會發生**整數溢位 (Integer Overflow)**，導致結果錯誤（通常會變成一個負數或非預期的正數）。

---

## 1. 問題根源：隱性型別提升 (Implicit Type Promotion)

C++ 的型別規則決定了運算結果的型別。當運算子兩邊的型別相同時（例如 `int * int`），結果也會是該型別。計算機會**先完成計算，然後才將結果賦值給目標變數**。如果在計算過程中就已經溢位，那麼即使目標變數是 `long long`，接收到的也將是已經溢位的錯誤結果。

---

## 2. 錯誤的解決方式：乘法後轉型

這是一個非常常見的陷阱。

```cpp
int a = 100000;
int b = 100000;

// ❌ 錯誤：溢位發生在乘法階段
// a * b 的結果（10,000,000,000）已經超過 int 上限
// 溢位後的錯誤結果被轉換為 long long
long long result = a * b;
// result 可能會是 1410065408 (取決於系統)，而不是 10000000000
```

---

## 3. ✅ 正確的解決方式：運算前轉型

要避免溢位，必須在進行乘法運算**之前**，將其中至少一個運算元 (operand) 提升到一個更大的型別，如 `long long`。這樣，C++ 的型別提升規則會確保整個運算的結果都是在 `long long` 的範圍內計算的。

### 方法一：使用 `static_cast` (推薦)

這是最清晰、最 C++ 的做法，明確表達了你的意圖。

```cpp
int a = 100000;
int b = 100000;

// ✅ 正確：先將 a 轉型為 long long
long long result = static_cast<long long>(a) * b;
// 現在 result 是 10000000000
```

### 方法二：乘以 `1LL`

這是一個在競賽編程中常見的簡潔技巧。`1LL` 是一個 `long long` 型別的字面量 (literal)。將任何整數乘以 `1LL`，會將其提升為 `long long`。

```cpp
int a = 100000;
int b = 100000;

// ✅ 正確：透過乘以 1LL 將 a 提升為 long long
long long result = 1LL * a * b;
// 現在 result 是 10000000000
```

---

## 4. 核心心法與總結

> **先轉型，再運算 (Cast First, Then Operate)**

| 操作                  | 說明                  | 結果        |
| :-------------------- | :-------------------- | :---------- |
| `(long long) (a * b)` | 先乘法 (溢位)，後轉型 | ❌ **錯誤** |
| `(long long)a * b`    | 先將 `a` 轉型，後乘法 | ✅ **正確** |
| `1LL * a * b`         | 先將 `a` 轉型，後乘法 | ✅ **正確** |

在任何可能導致中間結果超過 `int` 範圍的計算中（特別是乘法），都要養成**預先轉型**的習慣，這是避免隱藏性溢位錯誤的關鍵。
