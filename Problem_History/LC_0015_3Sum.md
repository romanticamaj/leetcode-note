# 15. 3Sum：從暴力枚舉到經典的難度基準

**記憶線索：先固定一部分選擇，再把剩餘搜尋換成更便宜的查詢；判定存在與列出全部答案，是不同的問題。**

查證日期：2026-10-20。

## 題目情境與查證結論

[LeetCode 15](https://leetcode.com/problems/3sum/) 要找三個不同 index，使其值加總為 0，並列出所有不重複的 value triplet。輸入允許重複值，同一位置不能重複使用。

3SUM 早於 LeetCode，是演算法教學與計算幾何研究中的經典問題。目前確認有教科書直接收錄同型問題，但**未確認最早發明者、LeetCode 的直接取題來源或首次上架日期**。某書收錄、某篇論文建立研究框架，不等於作者發明本題。

## 經典教材如何討論？

### Sedgewick、Wayne：Algorithms, 4th Edition，§1.4

官方教材以 3-sum 示範執行時間分析與演算法改善：從三層枚舉，轉成排序後固定兩個數，再以 binary search 找補數。`ThreeSumFast` 的時間為 O(n² log n)。同章官方網頁的 **Web Exercise 21：Sum of three** 則提供三集合版本：固定一個集合的元素，線性掃描另外兩個排序集合，得到 O(n²) 方法。

| 方法 | 時間 | 被替換的工作 |
|---|---|---|
| 三層枚舉 | O(n³) | 逐一檢查所有三元組 |
| 排序＋固定兩個值＋binary search | O(n² log n) | 用對數時間查詢取代第三層枚舉 |
| 排序＋固定一個值＋雙指標掃描 | O(n²) | 利用順序關係整批排除配對 |

這支持「先建立正確暴力法，再辨識可改善的搜尋」這條推導路線；表中方法並非宣稱同一段正文逐一實作全部版本。

**教材假設與 LC 15 不同**：官方 `ThreeSumFast` 要求輸入值互異，遇到重複值會拋出例外。它可計數或列出三元組，但沒有處理 LC 15 所要求的「輸入有重複值、合法位置不同、輸出值組合去重」。

來源：[§1.4 官方章節](https://algs4.cs.princeton.edu/14analysis/)、[ThreeSumFast 官方說明](https://algs4.cs.princeton.edu/code/javadoc/edu/princeton/cs/algs4/ThreeSumFast.html)。

### Elements of Programming Interviews：The 3-Sum Problem

作者公開的 Java 節錄版，§14.1、印刷頁 **74**，將此題放在 **Greedy Algorithms and Invariants**。解法是排序後固定一個元素，把剩餘目標交給線性的 Two Sum 雙指標搜尋，整體 O(n²)。章節位置與頁碼僅適用於這份節錄版。

它強調的正確性依據是搜尋區間不變量：若合法配對存在，仍有一組保留在目前區間中。當兩端之和太小時，最左值搭配目前範圍內任何值都不夠大，因此可淘汰最左值；太大時則可淘汰最右值。

**這個版本只判定是否存在，且明確允許重複使用同一個位置**。不能把其程式中的位置範圍、指標相遇條件直接搬到 LC 15，也不能用它代替輸出去重的證明。

來源：[作者公開 Java 節錄](https://elementsofprogramminginterviews.com/sample/epilight_java_new.pdf)、[作者官方題目索引](https://elementsofprogramminginterviews.com/solutions-alpha/)。

## 可確認的研究歷史

### 1995：3SUM-hard 成為計算幾何的研究框架

Anka Gajentaan、Mark H. Overmars，*On a class of O(n²) problems in computational geometry*，刊於 **Computational Geometry 5(3)，165–185，1995**。

論文以「是否存在三個數加總為 0」為基準，建立 **3SUM-hard** 的歸約框架，把多種幾何問題的難度與 3SUM 連結。這是研究史的重要節點，不能當作題目最早出現的證明。

§3、印刷頁 **169** 也給出 O(n²) 方法：對三集合版本 a+b=c，先排序 B、C；固定 a 後，利用 B+a 與 C 都有序，同步遍歷以判定是否有共同元素。這是利用有序性消除反覆搜尋的早期明確文獻。

3SUM-hard 的歸約本身並不證明一般模型下必須花 Ω(n²)；它表達的是：若某個被歸約到的問題有更快演算法，3SUM 也能隨之加速。

來源：[原始論文](https://people.csail.mit.edu/virgi/6.s078/papers/gajovermars.pdf)、[出版社書目與 DOI](https://doi.org/10.1016/0925-7721(95)00022-2)。

### 2014：判定問題的次平方時間突破

Allan Grønlund、Seth Pettie 的 *Threesomes, Degenerates, and Love Triangles* 提出實數 3SUM 的 o(n²) 演算法，改善包含對數因子；例如其中的隨機化界為 O(n²(log log n)²/log n)。

要區分 **o(n²)** 與 **O(n^(2−ε))，固定 ε>0**：前者包含只改善對數因子的情況，不自動代表後者。理論文獻中的計算模型與問題版本也必須一起閱讀。

來源：[2014 原始論文](https://arxiv.org/abs/1404.0799)。

### 2026：新的 truly subquadratic 預印本

Josh Alman、Virginia Vassilevska Williams 於 **2026-10-05** 公開 *Truly Subquadratic 3SUM and Truly Subcubic APSP via Triangles in Sparse Lopsided Graphs*。摘要宣稱對多項式大小整數的 3SUM 判定問題，提供確定性的 O(n^1.9992) 演算法。

此處記錄的是查證當日可見的**新預印本主張**，不是本筆記對證明的獨立驗證，也不宣稱它是所有模型下的最新最佳界。它不直接提供 LC 15 全部答案列舉版本的次平方演算法。

來源：[2026 預印本及提交紀錄](https://arxiv.org/abs/2610.06783)。

## 判定、列舉與去重，分別難在哪裡？

| 版本 | 要求 | 額外需要釐清的事情 |
|---|---|---|
| 判定 | 是否至少有一組解 | 合法元素／位置的定義；找到即可停止 |
| 列舉 index 組合 | 列出所有合法位置組合 | 同值不同位置是否視為不同答案 |
| LC 15 | 列出全部不同的 value triplet | 不同位置的相同值可配對，但等價輸出只能保留一組 |

LC 15 的困難不只在補數查詢。**合法性看 index，輸出等價性看 value**；去重必須同時保留足夠的位置機會、避免重複輸出。

以下是數學推導，不是對某篇歷史文獻的歸屬：在以 n 為參數、值域可隨 n 成長的通常漸近模型下，不同零和 triplet 的數量最壞為 Θ(n²)。上界是固定兩個值後補數唯一；下界可取整數區間 [−m,m]，讓兩個不同正數取自 [1,⌊m/2⌋]，第三個數取其和的負值，可得到 Θ(m²) 組不同答案，且 n=2m+1。

因此，**明確列出全部答案最壞就需要 Ω(n²) 輸出時間**。排序＋雙指標的 O(n²) 是此列舉問題在通常模型下的最壞漸近最優界；這不等於證明判定版本也有相同下界。

## 與解題心法的連結

- [Brute Force 關鍵設計](../Algorithms/Brute_Force/README.md)：先固定選擇、建立完整枚舉，再替換昂貴的搜尋。
- Hash lookup 路線利用「補數存在性」降低第三層成本；需註明預期查詢時間，並自行維護合法位置與輸出去重。
- Two pointers 路線利用排序後的單調性淘汰候選；排序同時方便去重，但去重的正確性仍需另行說明。
- No-sort 是另一個待探索版本；本篇只記錄背景，不在此給出其完整實作。
