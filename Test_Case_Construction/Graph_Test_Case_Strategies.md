# 圖結構的系統化測試案例設計

在設計與測試圖論相關的演算法時，建立一套系統化的測試案例至關重要。本文件融合了「G-E-C」框架（通用、邊界、角落）與圖的結構特性，提供一個全面的測試案例設計心法。

---

## 指導原則：G-E-C 框架

1. **通用案例 (Generic Cases)**：驗證核心邏輯的「快樂路徑」。
2. **邊界案例 (Edge Cases)**：測試問題的約束與極限，例如空圖、單一節點等。
3. **角落案例 (Corner Cases)**：結合多個邊界條件或特殊結構，挑戰演算法的隱藏假設。

---

## 圖的測試案例分類心法

我們將圖的測試案例從三個維度進行分解：**結構維度**、**權重與屬性維度**和**問題特定維度**。

### 1. 結構維度 (Structural Dimension)

這個維度關注圖的拓撲結構與連接性。

| 分類               | 類型                                 | 說明                                   | 測試目的                             |
| :----------------- | :----------------------------------- | :------------------------------------- | :----------------------------------- |
| **通用 (Generic)** | **小型隨機圖 (Small Random Graph)**  | 包含 3-5 個節點和一些邊的普通圖。      | 驗證演算法的基本邏輯是否正確。       |
| **邊界 (Edge)**    | **空圖 (Empty Graph)**               | 沒有任何節點。                         | 處理 `null` 或空容器輸入。           |
|                    | **單一節點圖 (Single-Node Graph)**   | 只有一個節點，沒有邊。                 | 處理最小的非空圖。                   |
|                    | **雙節點圖 (Two-Node Graph)**        | 兩個節點，可能有一條邊或沒有。         | 測試最簡單的連接關係。               |
|                    | **無邊圖 (Graph with No Edges)**     | 多個節點，但沒有任何邊（全為孤立點）。 | 測試演算法在完全不連通情況下的行為。 |
| **角落 (Corner)**  | **鏈狀圖 (Line Graph / Path Graph)** | 節點排列成一條線，類似鏈結串列。       | 測試深度優先搜尋的極端情況。         |
|                    | **環狀圖 (Cycle Graph)**             | 節點形成一個單一的環。                 | 檢查環的偵測與處理能力。             |
|                    | **星狀圖 (Star Graph)**              | 一個中心節點連接到所有其他節點。       | 測試單一節點度數極大的情況。         |
|                    | **完全圖 (Complete Graph / Clique)** | 每個節點都與所有其他節點相連。         | 測試邊密度極大的情況，檢查性能。     |
|                    | **不連通圖 (Disconnected Graph)**    | 包含多個獨立的連通分量。               | 測試演算法是否能處理多個組件。       |
|                    | **二分圖 (Bipartite Graph)**         | 節點可以被分成兩組，組內沒有邊。       | 測試需要顏色標記或分組的演算法。     |
|                    | **有向無環圖 (DAG)**                 | 有向圖，但沒有任何環。                 | 拓撲排序等演算法的基礎。             |

### 2. 權重與屬性維度 (Weight & Attribute Dimension)

這個維度關注邊或節點的數值屬性。

| 分類               | 類型                                 | 說明                           | 測試目的                                 |
| :----------------- | :----------------------------------- | :----------------------------- | :--------------------------------------- |
| **通用 (Generic)** | **正權重 (Positive Weights)**        | 所有邊的權重都是正數。         | Dijkstra 等演算法的標準情況。            |
| **邊界 (Edge)**    | **無權重 (Unweighted)**              | 所有邊的權重可視為 1。         | 測試 BFS 等演算法的適用性。              |
|                    | **零權重邊 (Zero-Weight Edges)**     | 存在權重為 0 的邊。            | 檢查演算法是否會陷入無限迴圈或處理不當。 |
| **角落 (Corner)**  | **負權重邊 (Negative-Weight Edges)** | 存在負權重邊，但沒有負權環。   | Bellman-Ford 或 SPFA 的測試案例。        |
|                    | **負權環 (Negative-Weight Cycles)**  | 存在一個或多個總權重為負的環。 | 測試演算法是否能偵測到這種無解情況。     |
|                    | **重複權重 (Duplicate Weights)**     | 多條邊有相同的權重。           | 測試對權重排序或比較的穩定性。           |

### 3. 問題特定維度 (Problem-Specific Dimension)

這個維度根據具體問題的目標來設計。

- **遍歷 (Traversal - BFS/DFS)**:
  - 起點和終點是同一個節點。
  - 起點和終點不連通。
  - 圖是 `null` 或空的。

- **最短路徑 (Shortest Path)**:
  - 起點和終點之間有多條路徑。
  - 起點和終點不連通。
  - 存在負權環（若演算法需處理）。

- **拓撲排序 (Topological Sort)**:
  - 存在多個有效的拓撲序。
  - 圖中存在環（無法排序）。
  - 圖不連通。

- **最小生成樹 (MST)**:
  - 存在多個權重相同的邊，可能產生多個 MST。
  - 圖不連通（應為每個連通分量產生一個森林）。

---

## 總結：系統化設計流程

1. **從結構維度出發**：先選擇一個**通用**結構（小型隨機圖），再覆蓋**邊界**（空圖、單節點）和**角落**（環狀、不連通、完全圖等）。
2. **疊加權重維度**：在選定的結構上，測試**通用**（正權重）、**邊界**（無權重）和**角落**（負權重、負權環）的情況。
3. **結合問題維度**：最後，根據題目要求（如最短路徑、拓撲排序），設計特定的起點、終點和目標，確保所有邏輯分支都被覆蓋。
