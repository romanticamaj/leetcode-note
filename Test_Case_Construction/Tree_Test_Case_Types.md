# 樹結構的系統化測試案例設計

在設計與測試樹相關的演算法時，建立一套系統化的測試案例至關重要。本文件融合了「G-E-C」框架（通用、邊界、角落）與樹的結構特性，提供一個更全面的測試案例設計心法。

---

## 指導原則：G-E-C 框架

1. **通用案例 (Generic Cases)**：驗證核心邏輯的「快樂路徑」。
2. **邊界案例 (Edge Cases)**：測試問題的約束與極限，例如空、單一元素等。
3. **角落案例 (Corner Cases)**：結合多個邊界條件或特殊結構，挑戰演算法的隱藏假設。

---

## 樹的測試案例分類心法

我們將樹的測試案例從三個維度進行分解：**結構維度**、**數值維度**和**問題特定維度**。

### 1. 結構維度 (Structural Dimension)

這個維度關注樹的形狀和拓撲結構。

| 分類               | 類型                                  | 說明                                                         | 測試目的                                                           |
| :----------------- | :------------------------------------ | :----------------------------------------------------------- | :----------------------------------------------------------------- |
| **通用 (Generic)** | **完全二元樹 (Complete Binary Tree)** | 除最後一層外全滿，且最後一層節點靠左排列。Heap 的基礎結構。  | 測試結構良好、接近平衡的樹。                                       |
|                    | **完美二元樹 (Perfect Binary Tree)**  | 所有非葉節點都有兩個子節點，且所有葉節點在同一層。           | 測試最為對稱和飽和的結構。                                         |
|                    | **不平衡樹 (Unbalanced Tree)**        | 左右子樹高度差異較大，是偏斜樹的一般化情況。                 | 測試演算法在非理想、非對稱結構下的穩健性。                         |
|                    | **隨機結構樹 (Random Tree)**          | 節點分佈不規則，無特定規律。                                 | 模擬真實世界中更常見的通用情況。                                   |
| **邊界 (Edge)**    | **空樹 (Empty Tree)**                 | `root == nullptr`。                                          | 處理 `null` 輸入的基礎情況。                                       |
|                    | **單一節點樹 (Single-Node Tree)**     | 僅有一個根節點。                                             | 處理最小非空結構，遞迴的終止條件。                                 |
|                    | **雙節點樹 (Two-Node Tree)**          | 根節點只有一個左子或右子。                                   | 測試最簡單的父子關係。                                             |
| **角落 (Corner)**  | **偏斜樹 (Skewed Tree)**              | 每個節點最多只有一個子節點，退化成鏈結串列。分為左偏和右偏。 | 測試遞迴深度的最壞情況，檢查演算法是否會因不平衡而超時或堆疊溢位。 |

### 2. 數值維度 (Value Dimension)

這個維度關注節點上儲存的值的特性。

| 分類               | 類型                                | 說明                                                        | 測試目的                                                              |
| :----------------- | :---------------------------------- | :---------------------------------------------------------- | :-------------------------------------------------------------------- |
| **通用 (Generic)** | **唯一值樹**                        | 所有節點的值都不同。                                        | 標準的「快樂路徑」，避免重複值帶來的複雜性。                          |
| **邊界 (Edge)**    | **單一值樹**                        | 所有節點的值都相同。                                        | 測試演算法對重複值的處理，特別是在路徑問題中。                        |
|                    | **極端值**                          | 節點值包含 `INT_MAX`, `INT_MIN`, `0`, `-1` 等。             | 檢查數值計算中的整數溢位或邊界錯誤。                                  |
| **角落 (Corner)**  | **重複值樹 (Tree with Duplicates)** | 節點值有重複，但分佈在不同位置。                            | 測試演算法是否能正確處理相同值的節點，尤其是在 BST 或路徑查找問題中。 |
|                    | **特定順序值**                      | 例如，在 BST 中，節點值預先排序或逆序排序（會導致偏斜樹）。 | 測試結構與數值結合的角落情況。                                        |

### 3. 問題特定維度 (Problem-Specific Dimension)

這個維度根據具體問題的目標來設計測試案例。

- **路徑總和 (Path Sum) 問題**:
  - 目標和 `targetSum` 為正、負、零。
  - 存在多條符合條件的路徑。
  - 路徑恰好在葉節點結束，或在中間節點就已滿足條件。
  - 沒有任何路徑符合條件。

- **最低共同祖先 (LCA) 問題**:
  - 兩個節點互為父子關係。
  - 兩個節點在樹的兩側。
  - 其中一個節點是根節點。
  - 兩個節點是同一個節點。

- **二元搜尋樹 (BST) 問題**:
  - 輸入的樹不滿足 BST 的定義。
  - 對一個空的 BST 進行操作。
  - 操作的目標值恰好是根節點、葉節點或不存在。

## 總結：系統化設計流程

在面對一個樹的演算法問題時，可以遵循以下流程來設計全面的測試案例：

1. **從結構維度出發**：先選擇一個**通用**結構（如隨機樹），再覆蓋**邊界**（空樹、單節點）和**角落**（偏斜樹）。
2. **疊加數值維度**：在選定的結構上，測試**通用**數值（唯一值）、**邊界**（全相同、極端值）和**角落**（部分重複）的情況。
3. **結合問題維度**：最後，根據題目要求，設計針對性的輸入（如 `targetSum` 的值），確保所有邏輯分支都被覆蓋。

通過這種多維度的組合，可以系統性地構建出一套高品質的測試案例，有效驗證演算法的正確性和穩健性。
