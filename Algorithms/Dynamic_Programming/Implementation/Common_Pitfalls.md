# DP 常見陷阱與修正策略

理論是清晰的，但實作過程充滿了陷阱。本章節聚焦於解決這些最常見的卡點。

## 陷阱一：Backtracking 未窮舉所有決策

- **症狀：** 解法遺漏了某些正確答案。
- **核心問題：** 在每個狀態節點，沒有劃分出所有可能的、互斥的選擇。
- **修正心法：**
  > **枚舉所有互斥且完備的選擇 (MECE Principle):**
  > 在每個狀態節點，必須劃分出所有可能的、不重疊的決策，確保它們共同構成了完整的選擇空間。常見模式有：
  >
  > - **「選/不選」模式：** 用於子集/子序列問題。
  > - **「遍歷選項」模式：** 用於組合/構成問題。

### 陷阱二：Top-Down 的 Cache Key 未包含完整狀態

- **症狀：** Memoization 產生錯誤結果。
- **核心問題：** 忽略了除了主要進度變數（如 `index`）之外，還有其他「約束變數」會影響子問題的解。
- **修正心法：**
  > **採用「狀態唯一性試金石」**：審視回溯函式的每個參數，並提問：「固定 `index`，只改變這個參數，是否會影響函式的返回值？」
  >
  > - **會** -> 此參數是**狀態定義參數**，必須納入 Cache Key。
  > - **不會** -> 此參數是**路徑依賴參數**，不應納入 Cache Key。

### 陷阱三：混合決策模式導致重複窮舉

- **症狀：** 演算法結果可能正確，但效能遠低於預期，甚至超時。
- **核心問題：** 在單一遞迴層級中，混合了「選/不選」和「遍歷選項」兩種決策模式。
- **範例（錯誤）：**

```cpp
  // 考慮 coin[i]
  // 決策一：不選 coin[i]
  solve(i + 1, amount);
  // 決策二：遍歷所有選項（包括 coin[i]）
  for (int k = i; k < n; ++k) {
      solve(k, amount - coins[k]);
  }
```

- **分析：** 「決策二」中的 `k` 從 `i` 開始遍歷，其 `k = i+1` 的情況已經隱含了「不選 `coin[i]`」的決策。這導致「不選 `coin[i]`」這個分支被重複探索，破壞了 MECE 原則，使狀態轉移不再簡潔。
- **修正心法：**
  > **堅守一種決策模式：** 在一個狀態節點，只能選擇一種劃分方式。要麼是乾淨的「選 `item[i]` vs. 不選 `item[i]`」，要麼是純粹的「遍歷所有可用選項 `c`」。不要將兩者混用。

### 陷阱四：混淆局部狀態與全域最優解 (Confusing Local State with Global Optimum)

這是 DP 設計中最 subtle 也最致命的錯誤之一，它源於對 `collect` 與 `combine` 兩種思維模式的混淆。

- **症狀：** 狀態轉移方程設計得異常複雜，或是在 base case 和邊界條件上反覆出錯。
- **核心問題：** 試圖將「全域最優解」硬塞進一個只適合承載「局部屬性」的 DP 狀態定義中。

#### 案例分析：221. Maximal Square

**問題：** 在一個由 `0` 和 `1` 組成的矩陣中，找到只包含 `1` 的最大正方形面積。

一個常見的錯誤起點是試圖用 `combine` 思維來一步到位：

> **錯誤的 `combine` 嘗試：**
>
> - **混合狀態定義:** `dp(i, j)` = 在以 `(i, j)` 為左上角的**整個子矩陣**中，能找到的最大正方形面積。
> - **為何這很難實現？**
>   - 為了計算 `dp(i, j)`，你似乎需要 `dp(i+1, j)` (下方子矩陣的最大值) 和 `dp(i, j+1)` (右方子矩陣的最大值)。
>   - 但這兩個子問題的解**並非獨立**！`dp(i+1, j)` 和 `dp(i, j+1)` 的計算範圍有重疊區域 (`(i+1, j+1)` 開始的子矩陣)，直接取 `max` 會重複計算或遺漏資訊。
>   - 此外，你還需要知道「以 `(i,j)` 為左上角」的正方形大小，這本身就是一個需要 `min` 操作的遞迴。
>   - **結論：** 將「局部屬性」（以 (i,j) 開頭的正方形）和「全域最優」（子矩陣中的最大值）混在一個狀態定義裡，導致轉移關係不再清晰，違反了最優子結構的簡潔性。

#### 正確的設計：`collect` 思維 (分離局部與全域)

更清晰、更穩健的做法是採用 `collect` 思維，嚴格區分局部狀態和全域答案。

**路線 A (標準做法，建議):**

1. **定義一個「純粹的」局部狀態 (Local State):**

   - `dp(i, j)` = 以 `(i, j)` **為右下角**的最大正方形**邊長**。
   - 這個定義非常單純，只關心 `(i, j)` 這一點。

2. **設計局部狀態的轉移方程:**

   - 如果 `matrix[i][j] == 0`，則 `dp(i, j) = 0`。
   - 如果 `matrix[i][j] == 1`，一個以 `(i, j)` 為右下角的正方形能否擴展，取決於其左方、上方、左上方三個方向是否也能形成正方形。因此：
     `dp(i, j) = min(dp(i-1, j), dp(i, j-1), dp(i-1, j-1)) + 1`

3. **在計算過程中「收集」全域最優解:**

   - 在計算每個 `dp(i, j)` 的同時，用一個單獨的變數 `max_so_far` 來追蹤全局最大值。
   - `max_so_far = max(max_so_far, dp(i, j))`

4. **最終答案:**
   - `max_so_far * max_so_far`。

**修正心法：**

> **保持狀態定義的純粹性 (Keep State Definition Pure):**
> 當一個問題的最優解可能出現在任何位置（如最大子數組和、最大正方形）時，通常應該：
>
> 1. 讓 `dp` 狀態代表一個**與當前位置 `i` 相關的、易於計算的局部屬性** (e.g., "以 `i` 結尾的最大和" 或 "以 `(i,j)` 為右下角的最大正方形")。
> 2. 使用一個**外部變數**在遍歷過程中「收集」這些局部解中的最大值，作為全域最優解。
>
> 這種 `collect` 思維避免了將全域最優的複雜邏輯耦合進狀態定義中，讓狀態轉移方程保持簡潔和優雅。
