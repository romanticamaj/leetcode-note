# 狀態壓縮技巧

狀態壓縮是動態規劃以及回溯法等演算法中一項至關重要的優化技術。其目標是降低狀態表示的維度或大小，從而顯著改善空間複雜度，有時也能提升時間複雜度。

本文件整合了來自不同情境的各種狀態壓縮策略。

---

## 1. 核心原則：從解的性質設計狀態

狀態壓縮的潛力通常源於待解決問題的根本性質。

- **最優化 vs. 計數/列舉：**

  - **最優化問題 (Optimization Problems):** 尋求最小值、最大值或可行性（「能否完成？」）的問題，通常具有最大的狀態壓縮潛力。這是因為解的具體路徑無關緊要。例如，如果多種數字組合都能加總到目標值，那麼在最優化情境下它們是等價的。
  - **計數/列舉問題 (Counting/Enumeration Problems):** 這類問題需要區分不同的有效解，因此常需要更詳細的狀態資訊（例如用 `index` 來防止重複計算組合），這限制了壓縮的可能性。

- **排列 vs. 組合：**
  - **排列 (Permutation，順序有關):** 如果元素的順序很重要，狀態通常可以更簡單，因為不需要額外資訊（如 `index`）來處理重複。
  - **組合 (Combination，順序無關):** 如果順序不重要，通常需要在狀態中加入 `index` 來強制一個人為的順序以避免重複計算，這使得狀態壓縮變得更困難。

> **關鍵結論：** 對於最優化問題，特別是那些類似於排列的問題，你通常可以從狀態中捨棄像 `index` 這樣的維度，因為目標是最優值，而不是路徑。這是狀態壓縮的主要機會。
>
> **以 Coin Change 問題為例：**
>
> - **最優值問題 (LeetCode 322. Coin Change):** "Return the fewest number of coins that you need to make up that amount."
>   - 這裡我們關心的是「最少硬幣數」，不關心是哪幾種硬幣組合。`[1, 2, 2]` 和 `[2, 1, 2]` 都是 3 枚硬幣，是等價的。這是一個「排列」性質的最優值問題，因此狀態可以壓縮為 `dp(amount)`。
> - **計數問題 (LeetCode 518. Coin Change 2):** "Return the number of combinations that make up that amount."
>   - 這裡我們關心的是「有幾種組合」。`[1, 2, 2]` 和 `[2, 2, 1]` 必須被視為同一種組合。為了避免重複計算，我們必須引入人為的順序，因此狀態需要是 `dp(index, amount)`。
>
> (參考: `DP_State_Design_from_Solution_Properties.md`, `01-DP_Problem_Solving_Framework.md`)

## 2. 技術：滾動陣列 (Rolling Array) 進行空間優化

當前狀態 `dp[i][...]` 的計算僅依賴於有限數量的先前狀態（例如 `dp[i-1][...]`）時，此技術適用於自底向上的 DP。

- **概念：** 我們只保留下一次計算所必需的行或列，而不是儲存整個 DP 表。
- **範例：** 如果 `dp[i][j]` 僅依賴於 `dp[i-1][...]`，一個二維表格 `dp[N][M]` 可以被壓縮成一個一維陣列 `dp[M]`。
- **效果：** 大幅降低空間複雜度，例如從 O(N\*M) 降至 O(M)。

> (參考: `02-DP_TopDown_to_BottomUp.md`)

## 3. 技術：吸收維度 (Absorbing Dimensions)

在多維 DP 中，一個狀態維度有時可以被「吸收」到遞迴函式的內部邏輯中，而不是作為狀態定義的一部分。

- **概念：** 一個狀態參數，特別是代表當前步驟「選擇」的參數，可以由函式內部的一個迴圈來處理。該迴圈遍歷所有可能的選擇，計算它們的局部價值，並將其與對*下一個*狀態的遞迴呼叫結合起來。
- **範例 (LeetCode 2218):**
  - **初步狀態構想：** `dp(i, k, p)`，其中 `i` 是堆的索引，`k` 是剩餘的硬幣數，`p` 是從第 `i` 堆中拿取的硬幣數。
  - **壓縮後狀態：** `dp(i, k)`。
  - **被吸收的邏輯：** 在 `dp(i, k)` 函式內部，一個迴圈遍歷 `p`。拿取 `p` 個硬幣的價值在本地計算，並與 `dp(i + 1, k - p)` 的結果結合。`p` 這個維度由迴圈處理，而不是由狀態處理。

> **心法：** `狀態定義子問題，回傳值解決子問題。`
> (參考: `04-Multi_Dimensional_DP_Playbook.md`)

## 4. 技術：使用位元遮罩 (Bitmask) 進行狀態表示

當狀態涉及追蹤一個小集合（例如 N <= 20）中已使用/已訪問的項目時，位元遮罩是一種強大的狀態壓縮技術。

- **核心思想：** 使用單一整數 (`mask`) 的位元來表示一個集合的狀態。第 `i` 位為 `1` 表示第 `i` 個項目已被使用；為 `0` 則表示尚未使用。
- **優點：**

  - **空間效率高：** 一個 `int` 最多可追蹤 32 個項目。
  - **時間效率高：** 狀態的更新與檢查是透過快速的位元運算完成。
  - **可雜湊：** 整數遮罩可直接作為雜湊表（hash map）的鍵，用於記憶化搜尋。

- **常用操作：**
  - **檢查第 `i` 個項目是否已使用：** `(mask & (1 << i)) != 0`
  - **將第 `i` 個項目標記為已使用：** `mask |= (1 << i)`
  - **取消標記第 `i` 個項目（回溯時）：** `mask &= ~(1 << i)` 或 `mask ^= (1 << i)`

這種技術在解決排列、旅行商問題 (TSP) 或需要追蹤節點訪問狀態的圖論問題中非常常見且強大。

> (參考: `State_Compression_with_Bitmask.md`, `Bit_Manipulation_Playbook.md`, `01-Backtracking_Templates_and_Patterns.md`)
