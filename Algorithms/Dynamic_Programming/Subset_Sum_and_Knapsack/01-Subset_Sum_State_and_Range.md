# Subset Sum：Adding a Variable、目標與值域

**不要先猜二維陣列。先問：「選了目前項目後，剩餘問題改變了什麼？」**

本篇從正整數 Subset Sum 推導 recurrence 與 memoization。下一篇再將同一個問題放進 table；最佳化版本在第三篇延伸。

## 1. 先定義要回答的問題

給定 n 個正整數 a[0..n)，每個輸入位置最多選一次，判斷是否存在子集總和恰好為 T，其中 T≥0。

這是可行性問題，回傳 bool。相同值的不同位置仍是不同項目，不能直接去重；每個項目是「選或不選」，不是可以重複取用的面額。

T 是原始問題的固定目標。它可能由題面直接給定，也可能由前置轉換算出；先說清楚轉換的等價性，才開始設計 DP。

## 2. 暴力法先把選擇說清楚

固定處理順序，面對 a[i] 時有兩個選擇：不選，或選一次。兩種情況都前進到 i+1，因此不會重複使用同一位置。

完整子集都能依序表示成一串選／不選；直接展開最多有 2^n 個完整選擇。這是後續改善的正確搜尋基礎，而不是先背一張表。

接著嘗試只用 `F(i)` 表示「從 i 開始能否完成問題」。問題出現了：**處理到同一個 i，不同的先前選擇可能留下不同的待完成總和。**

可用項目相同，不代表剩餘問題相同；只記進度會把不同問題混在一起。

## 3. Adding a Variable：把選擇的效果放進 recurrence

選取 a[i] 會讓「還需要湊出的數值」減少 a[i]；不選則不改變它。缺少的資訊就是剩餘目標 r。

定義：**`F(i,r)`＝只用 a[i..n)，每個位置最多一次，能否恰好湊出 r。**

| 變數 | 意義 | 作用 |
|---|---|---|
| i | 尚未處理項目的起點 | 決定剩餘可用項目 |
| r | 剩餘必須湊出的總和 | 決定還需要完成什麼 |
| T | 原始固定目標 | 決定初始呼叫 `F(0,T)` |

遞迴不是「加了一個陣列維度」才成立；而是**子問題本來就需要這個變數，陣列稍後才用來儲存它**。

```text
F(i,0) = true                         // 不必再選任何項目
F(n,r) = false，當 r > 0              // 項目用完但還沒湊滿

不選：F(i+1,r)
選取：F(i+1,r-a[i])，僅當 a[i] ≤ r
F(i,r) = 不選 OR 選取
```

每個合法子集恰好屬於「含 a[i]」或「不含 a[i]」，兩類完整涵蓋可能性；i 每次增加，遞迴也必定終止。

## 4. 從 input 與目標，推導數值 range

**起手式：我的選擇改變哪個量？這個量根據 input，最少、最多能到哪裡？**

本模型從 r=T 開始；元素為正，選取只會減少 r，且不遞迴進負餘額，因此需要儲存的範圍是 `0..T`。i 的語義範圍則是 `0..n`，其中 i=n 是終止狀態。

這個範圍是安全包絡，不要求每個整數都真的可達。若 T 大於所有元素總和，可先判定不可行；但「能算出總和」仍不保證它很小。

若改用已累積總和，範圍與捨棄理由也要跟著語義推導：正整數使超過 T 的總和無法再降回來。若元素可為負數，或每個數可選正負號，就不能照搬此理由。

**先定義數值，再證明 range，最後才映射成 index。** 若數學值域是 [L,U]，才考慮以 x-L 對應到 [0,U-L]；檢查邊界必須發生在存取之前。

這與答案二分都會探索數值空間，但「恰好湊出 x」通常不單調；有 range 不代表可用二分。

## 5. 為什麼可以 memoize？

兩條不同的選取歷史若到達同一 `(i,r)`，它們接下來能用的項目相同，還需要的總和也相同。因此後續的布林答案相同，過去如何走到這裡可以忘掉。

**先證明狀態等價，再共用答案。** 不能只因為兩個數字能當下標，就假定後續問題相同。

每個狀態算完後，記住 true 或 false。快取還必須區分「尚未算過」與「已算過且不可行」，否則 false 狀態可能被反覆展開。

memoization 只消除相同子問題的重算；它不會自動處理錯誤的狀態定義、越界或沒有進度的依賴。

## 6. 先估計規模，再選儲存方式

至多有 `(n+1)(T+1)` 個狀態，每格只處理兩種選擇。一般二維方案時間與表格空間為 O(n(T+1))，遞迴另需 O(n) 堆疊；終止狀態可以直接回傳、不存表。

Top-down 可能只走到部分狀態，但若預先配置並初始化整張表，仍需負擔整張表的成本。範圍大而可達狀態少時可考慮稀疏快取，卻不能先假設可達狀態一定少。
