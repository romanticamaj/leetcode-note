# 從 Memoization 到 Table／Bottom-up

**狀態語義與計算順序是兩個設計決定。先保留 recurrence，只改由誰安排計算；熟悉後再改狀態。**

延續正整數 Subset Sum：每個位置最多使用一次，判斷是否恰好湊出 T。第一篇已定義 `F(i,r)` 為只用 a[i..n) 能否湊出 r，原始答案為 `F(0,T)`。

## 1. Cache 已經是在儲存一張狀態表

Memoization 的動作是：遇到 `(i,r)` 時，若已有結果就取用，否則先算需要的子問題，再記住答案。依賴由 recurrence 決定，遞迴呼叫替我們安排求值。

Tabulation 則事先安排計算順序，讓每格需要的答案都已備妥。**表格本身不會替我們定義子問題，也不會自動給出正確順序。**

## 2. 第一個轉換：保留 suffix 狀態

沿用 `F(i,r)`，它依賴：

```text
F(i+1,r)
F(i+1,r-a[i])，當 a[i] ≤ r
```

因此先準備 i=n 的空 suffix：`F(n,0)=true`，其餘 r>0 為 false。接著按照 i=n-1、n-2、…、0 計算，每列的 r 可以走 0..T。

算目前列時，右側的下一個 suffix 列 i+1 已經完成；因為只讀不同列，這時 r 的掃描方向不影響 0/1 使用限制。答案仍在 `F(0,T)`。

**這已經是 bottom-up：從已知 base case，依相依關係建構答案。** 從右往左填不代表它是 top-down；suffix／prefix 描述狀態，top-down／bottom-up 描述求值方式。

## 3. 第二個設計：改用「前 i 個項目」

如果希望從左往右處理項目，可另外定義：

> **`P(i,w)`＝只用前 i 個項目 a[0..i)，是否存在總和恰好為 w 的子集。**

這是重新定義狀態，不只是將原公式的 i+1 改成 i-1。此時 i 是已處理的數量，而非目前元素的 index；目前要納入的元素是 a[i-1]。

第 0 列自然代表空問題：

```text
P(0,0) = true
P(0,w) = false，當 w > 0
```

依最後一個項目 a[i-1] 是否被選，得到：

```text
不選：P(i-1,w)
選取：P(i-1,w-a[i-1])，僅當 a[i-1] ≤ w
P(i,w) = 不選 OR 選取
```

依 i=1..n 填表，答案在 `P(n,T)`。第一個項目也使用相同轉移，不必另外手動設定「只選第一個項目」的格子。

**多一列不是填一排無效哨兵，而是明確表示零個項目的合法子問題。** 它有數學意義，才讓邊界一致。

## 4. 同樣一張 prefix 表，也能 push 或 pull

固定目前項目 x=a[i-1]：

| 觀點 | 枚舉哪個總和？ | 處理方式 |
|---|---|---|
| Pull：收集來源 | 本列想得到的 w | 從前列 w 與 w-x 收集可行性 |
| Push：推送後果 | 前列已可達的 j | 把可行性送到本列 j 與 j+x |

兩者都由第 i-1 列送到第 i 列，使用目前項目一次。`P(i-1,j)=false` 時可略過推送，因為沒有可達狀態可傳；這只是省略無效工作，目的地下標仍需檢查。

Bool 以 OR 合併多個來源；若之後改成計數，則對互斥選擇的方法數做加法。相同目的地不代表相同選擇，尤其值為 0 的計數問題要另外留意。

## 5. 填表前，先確認這四件事

| 問題 | 本篇 prefix 定義的答案 |
|---|---|
| 每格是什麼問題？ | 使用前 i 個項目，恰好湊出 w |
| 空問題在哪裡？ | 第 0 列，只有 w=0 可行 |
| 算目前格前需要誰？ | 第 i-1 列，因此先填較少項目的列 |
| 原始問題在哪裡？ | 使用全部 n 個項目，目標 T，即 P(n,T) |

## ⚠️ 不要一次更換所有設計

- 先將 suffix recurrence 改成 bottom-up，再考慮 prefix，避免同時換語義、索引與方向。
- 不把空集合可達性與「目前目標是否已完成」混為一談；`P(0,0)` 不等於 `P(0,T)`。
- 不用賦值右側的比較式保護左側存取。下標不合法時，寫入 false 一樣越界。
- 先保留二維表釐清讀寫層次；一維壓縮會讓目前列與前列共用空間，更新順序需要重新證明。

## ⏱️ 成本與下一步

兩種二維 bottom-up 都有 O(n(T+1)) 個格子，每格常數個選擇，時間與表格空間皆為 O(n(T+1))；省去的是遞迴呼叫堆疊，不是自動省去物品軸。
