# 分析篇：偽多項式時間與 NP-completeness

**數值 range 可能遠大於寫下它所需的位元長度。DP 可以精確且實用，卻不一定是一般多項式時間解法。**

本篇可獨立閱讀。考慮正整數 Subset Sum：從 n 個數選取子集，判斷總和是否恰好為 T；標準 DP 以項目進度與總和／剩餘目標建立表格，成本為 O(n(T+1))。當 T≥1 時，常簡寫成 O(nT)。

## 1. T 是數值；b 是表示它所需的位元數

正整數 T 若用 b 個二進位位元表示：

```text
b = floor(log₂ T) + 1
2^(b-1) ≤ T < 2^b
```

寫下 T 約需 b 個位元，但為 `0..T` 每個值開一格卻需要 T+1 格。因此這個 range 的長度可達 Θ(2^b)，DP 的 O(nT) 也就可能達到數量級 n·2^b。

完整輸入還包含所有 a[i]。令 L 表示整份二進位輸入的長度，概略為：

```text
L = Θ(n + log₂(T+1) + Σ log₂(a[i]+1))
```

一般的「多項式時間」要求成本受 L 的固定次方約束。不能只看 n，也不能把 T 的數值當成表示 T 的輸入長度。

## 2. 為什麼叫 pseudo-polynomial？

O(nT) 對數值 T 是多項式，但不能保證對完整輸入長度 L 也是多項式；這類依賴輸入長度與輸入整數數值大小的多項式成本，稱為**偽多項式時間**。

它描述成本，不描述答案品質：Subset Sum DP 仍然精確，不是近似。它也不是證明每筆輸入都需指數時間的下界，更不能據此排除其他演算法。

Knapsack 同理：容量 C 需要約 log₂C 個位元表示，但 O(nC) 的表格依賴 C 本身。標準格數分析以單格操作 O(1) 為模型；若儲存巨大價值或任意精度計數，還需計入算術的位元成本。

## 3. 「推導安全範圍」與「範圍很小」是兩件事

| 動作 | 意義 |
|---|---|
| 從輸入、選擇效果與目標推導 range | 保證該探索的狀態沒有被漏掉 |
| 在正確性理由下裁切 range | 捨棄不可能對答案有用的狀態 |
| 題目限制總和或容量很小 | 讓依賴數值大小的成本可負擔 |

**不是我們鎖住 range，演算法才變成偽多項式；它本來就依賴數值範圍，限制只是讓這個方法跑得動。**

用輸入總和 S 當上界，也不自動讓方法變快：若輸入元素可以很大，S 仍可以很大。由 input 算得出的數值，不一定被輸入長度的多項式約束。

若在某個受限輸入家族中 T≤L^c，c 為固定常數，則這個 O(nT) DP 在該家族上確實是多項式。有限測資規模內實用，不等於一般問題已得到多項式時間解法。

## 4. NP：Yes 答案可在多項式時間內驗證

一個判定問題屬於 NP，表示每個 Yes instance 都有一份長度為輸入長度多項式、可在多項式時間驗證的證明。等價地，它可由非確定性機器在多項式時間內判定。

Subset Sum 的證明是 n 個選／不選位元。拿到它後，只需加總被選的數，再與 T 比較；即使計入大整數加總與比較，成本仍是輸入長度的多項式，不用逐格走過 0..T。

**驗證一份已給定的選擇，不等於找出該選擇。** NP 也不表示已證明無法快速求解。

## 5. NP-hard：已知難題可歸約到目前問題

證明 B 是 NP-hard，可以從已知 NP-hard 的 A 出發，在多項式時間內將 A 的任意輸入轉成 B，並保留 Yes／No 答案：

```text
A ≤ₚ B
若 B 能快速求解，A 也能先轉換、再呼叫 B 而快速求解。
```

方向是「已知難題 → 待證明問題」。找到任意兩題間的歸約，或看到暴力搜尋有 2^n 個子集，都不足以證明 NP-hard。

經典定理為 **`3-SAT ≤ₚ Subset Sum`**：以整數位數編碼變數選擇與子句限制，構造可達目標，使邏輯公式可滿足，若且唯若子集和有解；數值可能很大，但整份二進位編碼仍維持多項式長度。完整構造見本篇來源，這裡不將歸約定理當成顯然成立。

Subset Sum 因此是 NP-hard，再結合它屬於 NP，得到 **NP-complete**。

## 6. Subset Sum 如何歸約到 0/1 Knapsack？

Knapsack 的判定版問：是否存在子集，重量不超過 C，且價值至少為 V？證明可同樣使用選取位元，快速驗證兩個限制，因此它屬於 NP。

給定 Subset Sum 的 a[i]、T，令重量與價值都等於 a[i]，容量 C=T、要求價值 V=T。此時：

```text
總重量 ≤ T，且總價值 ≥ T
因重量與價值相同，恰好等價於選取總和 = T。
```

這是多項式轉換，所以 `Subset Sum ≤ₚ Knapsack`。Knapsack 判定版也就是 NP-complete。

但前一篇「最大價值是多少」是**最佳化問題，稱 NP-hard**；NP-complete 正式用於判定版。判定、最佳化與方法數計數，不能不加區分地共用分類。

## 7. 有 DP，為什麼仍不矛盾？

標準二進位編碼的 Subset Sum 與 0/1 Knapsack 判定版是**弱 NP-complete**，同時具有偽多項式 DP。

NP-completeness 並未證明 P≠NP。已知的是：若任一 NP-complete 問題有一般多項式時間演算法，則 P=NP；若 P≠NP，就不存在這種一般解法。

O(nT)／O(nC) DP 不保證按完整輸入位元長度計算的多項式成本，所以沒有推翻 NP-completeness。數值限制小時，仍然可以有效使用。
