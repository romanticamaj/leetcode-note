# 多維動態規劃心法手冊

## tl;dr

1. **暴力搜尋 (Exhaustive Search)**
   - 定義狀態 `state` 來探索所有可能性。
   - 建構子問題的遞迴關係。
2. **Top-Down DP (Memoization)**
   - **狀態優化**：最小化 `state` 的維度，避免記錄冗餘資訊。
   - **空間壓縮**：將某些狀態維度吸收到函式內部的運算中，而不是作為 `state` 的一部分。
3. **Bottom-Up DP (Tabulation)**
   - **迭代方向**：根據狀態依賴性決定迴圈順序。
   - **表格大小與初始值**：根據狀態範圍與基礎案例設定。
   - **答案定位**：確認最終解在表格中的位置。
   - **變數命名**：保持清晰以避免錯誤。

`狀態定義子問題，回傳值解決子問題`

---

## 1. 核心挑戰：輸入 + 限制條件

多維 DP 的一個常見模式包含：

- **輸入 (Inputs)**：一個或多個資料結構（如陣列、字串），大小為 `n`、`m` 等。
- **限制 (Constraint)**：一個限制性因素，通常是整數 `k`（例如：操作次數、目標總和）。

DP 函式的狀態幾乎總是輸入的索引與當前限制值的組合。一個典型的狀態是 `dp(i, k)`，代表從 `input[i]` 開始處理，且剩下 `k` 次操作的子問題的最佳解。

---

## 2. 狀態設計：最小化的藝術

一個好的 DP 解答，其基礎在於一個最小化但又完整的狀態表示。

### 原則：狀態不應記錄路徑

一個常見的陷阱是將 **當前的解路徑** 或 **已做出的選擇** 包含在狀態中，這會導致狀態空間爆炸。

- **錯誤的狀態**: `dp(i, k, current_sum)`
- **正確的狀態**: `dp(i, k)`

**為什麼？** `current_sum` 是已走路徑的「結果」，而不是描述「子問題」本身。最佳解是透過在狀態 `(i, k)` 做出 **選擇**，並將其價值 **組合到「下一個」狀態的最佳解** 上來建構的。

**關鍵心法**：`狀態定義子問題，回傳值解決子問題`。兩者要分開。

### 空間壓縮 / 狀態簡化 技巧：透過吸收維度來進行狀態壓縮

通常，一個初步的狀態設計可能包含多個索引，例如 `dp(i, j, k)`，其中 `i` 是主要維度（例如，要處理哪個項目），而 `j` 代表在該維度內的操作（例如，要選擇多少個項目 `i`）。

壓縮的關鍵在於**將 `j` 維度吸收到函式的內部邏輯中**，而不是將其作為一個正式的狀態參數。

- **過程**：

  1. 定義一個維度較少的狀態，例如 `dp(i, k)`。
  2. 在 `dp(i, k)` 函式內部，建立一個迴圈來迭代被吸收維度（`j`）的所有可能選擇。
  3. 計算這些選擇的價值（例如，一個 `runningSum`）。
  4. 將這個計算出的價值與對下一個狀態（`dp(i + 1, ...)`）的遞迴呼叫結合起來。

- **範例 (LeetCode 2218)**：
  - **初步想法**：`dp(i, k, p)`，其中 `p` 是要從第 `i` 堆中拿取的硬幣數量。
  - **壓縮後的狀態**：`dp(i, k)`。
  - **被吸收的邏輯**：在 `dp(i, k)` 內部，我們透過一個迴圈來遍歷 `p`（從 0 到 `piles[i].size()`）。拿取 `p` 個硬幣的價值（`runningSum`）是在本地計算的，並與 `dp(i + 1, k - (p + 1))` 的結果結合。`p` 這個維度由迴圈處理，而不是由狀態處理。

## 3. Top-Down 到 Bottom-Up：實戰指南

將遞迴（帶有記憶化）的解法轉換為迭代（帶有表格）的解法是一項關鍵技能。

### 轉換的四點檢查清單

1. **確定迭代方向**：

   - 查看遞迴呼叫。如果 `dp(i, k)` 呼叫 `dp(i + 1, ...)`，你的 `i` 迴圈必須從 `n - 1` 迭代到 `0`。
   - 如果 `dp(i, k)` 呼叫 `dp(..., k - 1)`，你的 `k` 迴圈必須從 `1` 迭代到 `k`。
   - 目標是確保子問題在被需要之前已經被解決。

2. **定義表格大小與初始值**：

   - **表格大小**：由狀態範圍決定，通常是 `(n + 1) x (k + 1)`。`+1` 的空間有助於優雅地處理邊界條件。
   - **初始值設定**：
     - **Top-Down (Memoization)**：`cache` 通常用一個無效值（如 `-1`）來填充，表示該狀態尚未計算過。這是判斷是否需要遞迴計算的依據。
     - **Bottom-Up (Tabulation)**：`dp` 表格的初始值直接對應遞迴的基礎案例（Base Case）。例如，如果遞迴中 `dp(i, 0)` 回傳 `0`，那麼在表格中就將所有 `dp[i][0]` 設為 `0`。

3. **定位最終答案**：

   - 答案是原始問題的解。如果你的初始遞迴呼叫是 `dp(0, k)`，那麼表格中的最終答案就是 `table[0][k]`。

4. **使用清晰的變數名稱**：
   - 區分迴圈計數器（`i`, `j`, `p`）和問題的限制條件（`n`, `k`）。

## 4. 概念模型：將 DP 視為圖遍歷

將狀態空間視為一張圖，可以幫助釐清兩種方法之間的差異。

| 方法                       | 圖論類比               | 描述                                                                                     |
| :------------------------- | :--------------------- | :--------------------------------------------------------------------------------------- |
| **Top-Down (Memoization)** | **狀態空間圖上的 DFS** | 從目標狀態 `(0, k)` 開始，遞迴地探索路徑。`cache` 防止重複計算節點。它只探索可達的狀態。 |
| **Bottom-Up (Tabulation)** | **拓撲排序**           | 從基礎案例（沒有出邊的節點）開始，系統性地以尊重依賴關係的順序計算所有狀態。             |

**自我修正提示**：如果你不確定你的狀態設計，試著視覺化 bottom-up 表格。如果你無法定義一個清晰的迭代順序，你的狀態可能缺少一個關鍵的依賴關係，或者存在循環依賴。
