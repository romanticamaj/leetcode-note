# 從 Top-Down 到 Bottom-Up：DP 轉換的通用藍圖

將 Top-Down DP (Memoization) 轉換為 Bottom-Up DP (Tabulation) 是深化問題理解的關鍵一步。這不僅是程式碼的改寫，更是思維模式的根本轉變。本文件提供一個從泛化原則出發的系統性藍圖，指導你完成這個轉換。

---

## 核心原則：視角轉換與依賴分析

轉換失敗的根源，往往是試圖「直譯」遞迴公式，而忽略了兩種方法論的視角差異：

- **Top-Down (遞迴) 視角：** 「從我 (`state`) **出發**，未來能達成的最佳解是什麼？」—— 關注**未來**。
- **Bottom-Up (迭代) 視角：** 「要**到達**我 (`state`)，可以從哪些**過去**的已知最佳狀態轉移而來？」—— 關注**過去**。

成功的轉換，始於對 Top-Down 解法中「狀態依賴性」的深刻分析。

---

## DP 轉換三步曲

### 第一步：分析 Top-Down 的狀態依賴性

審視你的 Top-Down 函式簽名，例如 `solve(index, param_A, param_B, ...)`。`index` 通常是主要進度指標，而 `param_A`, `param_B` 等則是**約束條件**。這些約束條件決定了狀態依賴的模式。

- **模式一：固定依賴 (Fixed Dependency)**

  - **特徵：** 遞迴呼叫的參數變化是固定的、可預測的。例如，`solve(i)` 只呼叫 `solve(i+1)` 和 `solve(i+k)`。函式簽名中除了進度指標 `i` 外，沒有其他**狀態定義參數**。
  - **本質：** 子問題的結構不隨路徑改變。

- **模式二：可變依賴 (Variable / Full History Dependency)**
  - **特徵：** 函式簽名中存在一個或多個**狀態定義參數**，其值會影響子問題的解。例如 `solve(i, prev_idx)` 或 `solve(i, capacity)`。
  - **本質：** 子問題的解依賴於「如何到達當前狀態」的歷史路徑，因此需要額外維度來定義狀態。

### 第二步：為 Bottom-Up 重新定義狀態

這是整個轉換過程中最具創造性、也最關鍵的一步。目標是設計一個 `dp` 表（通常是一維或二維陣列），其維度足以捕捉所有必要的狀態資訊。

- **對於「固定依賴」：**

  - 狀態定義通常可以**直接映射**。如果 Top-Down 是 `solve(i)`，那麼 Bottom-Up 的 `dp[i]` 通常也代表「從位置 `i` 出發（或到位置 `i` 為止）的最優解」。

- **對於「可變依賴」：**
  - **必須重新設計狀態**。直接使用 Top-Down 的多維狀態（如 `dp[i][prev_idx]`）雖然可行，但往往不是最優的。
  - **關鍵技巧：降維與意義濃縮**。思考如何用更少的維度來表達相同的約束。一個非常強大的模式是：
    > **將 `dp[i]` 定義為「在考慮到元素 `i` 時，滿足特定條件的最優解」。**
  - 這個「特定條件」通常就是將原先的額外狀態參數（如 `prev_idx`）隱含在定義中。例如，將 `dp[i]` 定義為「以 `nums[i]` **結尾**的最長遞增子序列長度」，就成功地將 `prev_idx` 的資訊濃縮到了 `dp[i]` 的定義裡。

### 第三步：確定迭代順序與邊界

Bottom-Up 的迭代順序並非固定不變，它完全由**狀態轉移的依賴方向**決定。

- **迭代的黃金法則：**

  > **在計算 `dp[i]` 時，它所依賴的所有 `dp[j]` 狀態都必須是已知的、計算完畢的。**

- **推導迭代順序：**

  1. 寫下你的 Bottom-Up 狀態轉移方程。例如 `dp[i] = f(dp[i-1], dp[i-2])`。
  2. 觀察依賴關係：要計算 `dp[i]`，需要 `dp[i-1]` 和 `dp[i-2]`。
  3. 確定迭代方向：因此，`i` 必須從 `0` 或 `2` 開始，**從小到大**進行迭代。

  反之，如果轉移方程是 `dp[i] = f(dp[i+1], dp[i+k])`：

  1. 觀察依賴關係：要計算 `dp[i]`，需要 `dp[i+1]` 和 `dp[i+k]`。
  2. 確定迭代方向：因此，`i` 必須從 `n-1` 開始，**從大到小**進行迭代。

- **最終解的聚合：**
  - 狀態的定義也決定了最終解的位置。
  - 如果 `dp[i]` 代表「考慮到 `0..i` 的最優解」，最終解很可能是 `dp[n-1]`。
  - 如果 `dp[i]` 代表「以 `i` **結尾**的最優解」，則最終解通常是 `max(dp[0], ..., dp[n-1])`。

## 案例研究：應用轉換藍圖

### 案例 A：Brainpower 問題 (固定依賴)

1. **狀態依賴分析：** Top-Down `solve(i)` 只依賴 `solve(i+1)` 和 `solve(i + brainpower + 1)`。這是典型的**固定依賴**。
2. **狀態定義：** Bottom-Up `dp[i]` 可直接沿用 Top-Down 的定義：「從索引 `i` 開始能獲得的最大分數」。
3. **迭代順序：** 轉移方程為 `dp[i] = max(dp[i+1], points[i] + dp[i + brainpower + 1])`。`dp[i]` 依賴於 `i` 更大的索引，因此迭代必須**從 `n-1` 到 `0`**。
4. **最終解：** 我們求解的目標是 `solve(0)`，對應 `dp[0]`。

```cpp
// Bottom-Up for Fixed Dependency
vector<long long> dp(n + 1, 0LL); // n+1 for easier boundary handling
for (int i = n - 1; i >= 0; i--) {
    long long solve_it = questions[i][0] + dp[min(n, i + questions[i][1] + 1)];
    long long skip_it = dp[i + 1];
    dp[i] = max(solve_it, skip_it);
}
return dp[0];
```

### 案例 B：Longest Increasing Subsequence (可變依賴)

1. **狀態依賴分析：** Top-Down `solve(i, prev_idx)` 依賴於 `prev_idx`，這是一個**可變依賴**參數。
2. **狀態重新定義：** 這是關鍵。我們不能使用 `dp[i][prev_idx]`。我們將其降維並濃縮意義，定義 `dp[i]` 為「以 `nums[i]` **結尾**的最長遞增子序列的長度」。
3. **迭代順序：**
   - 轉移方程為 `dp[i] = max(dp[i], dp[j] + 1)`，其中 `j < i`。
   - `dp[i]` 依賴於所有 `j < i` 的 `dp[j]`。因此，外層迴圈必須**從 `0` 到 `n-1`**，以確保在計算 `dp[i]` 時，所有需要的 `dp[j]` 都已計算完畢。
4. **最終解：** 全局最優解是所有「以某個元素結尾」的最優解中的最大值，即 `max(dp)`。

```cpp
// Bottom-Up for Variable Dependency
vector<int> dp(n, 1);
for (int i = 0; i < n; ++i) {
    for (int j = 0; j < i; ++j) {
        if (nums[i] > nums[j]) {
            dp[i] = max(dp[i], dp[j] + 1);
        }
    }
}
return n == 0 ? 0 : *max_element(dp.begin(), dp.end());
```
