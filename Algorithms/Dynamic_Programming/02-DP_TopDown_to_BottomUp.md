# 從 Top-Down 到 Bottom-Up：DP 轉換的系統化指南

將 Top-Down DP (Memoization) 轉換為 Bottom-Up DP (Tabulation) 是深化問題理解、提升效能的關鍵一步。這不僅是程式碼的改寫，更是思維模式的根本轉變。本文件提供一個從核心原則出發的系統性指南，指導你完成這個轉換。

---

## 1. 核心思維轉變：從「提問」到「建構」

兩種方法論：

- **Top-Down (遞迴) 視角：** 這是一種「提問式」或「需求驅動」的方法。`solve(i)` 函式像一個管理者，它提問：「我需要 `solve(i+1)` 和 `solve(i+2)` 的答案才能解決我自己的問題。」它不關心子問題的答案如何得來，只要拿到結果即可。這是一種**由上而下的分解**。

- **Bottom-Up (迭代) 視角：** 這是一種「建構式」或「打地基」的方法。它從最微不足道的基礎案例（base case）開始，像工人一樣，一步步地、踏實地計算出 `dp[n-1]`, `dp[n-2]`, ...，直到建構出我們最終需要的答案 `dp[0]`。這是一種**由下而上的合成**。

這個核心差異也解釋了兩種轉換路徑的思維模式：

- **路徑一 (Iterative Top-Down):** 迭代的計算順序雖然是 `n-1 -> 0`，但其邏輯 `dp[i] = f(dp[i+1], ...)` 仍然是在回答「從 `i` 出發的最佳解」這個**未來導向**的問題。我們稱之為**迭代式 Top-Down**。
- **路徑二 (Iterative Bottom-Up):** 迭代的計算順序是 `0 -> n-1`，其邏輯 `dp[i] = f(dp[i-1], ...)` 是在回答「到達 `i` 的最佳解」這個**過去導向**的問題。我們稱之為**迭代式 Bottom-Up**。

---

## 2. 兩種轉換路徑

將遞迴解法轉為迭代時，有兩種主要思路來設計 DP 表和迴圈方向：

### 路徑一：Iterative Top-Down (沿用遞迴定義)

這是從 Top-Down 最自然的改寫方式，狀態轉移方程幾乎可以照搬，不易出錯。

- **狀態定義:** `dp[i]` 的意義與遞迴函式 `solve(i)` 完全相同。例如，如果 `solve(i)` 代表「從索引 `i` 到結尾所能得到的最佳解」，那麼 `dp[i]` 也代表同樣的意義。
- **迴圈方向:** 迭代的順序與遞迴的求解順序**相反**。遞迴是從 `solve(0)` 一路呼叫到 `solve(n-1)` (base case)，然後回傳結果。因此，迭代必須從 base case 開始計算，即從 `i = n-1` 迴圈到 `0`，這樣在計算 `dp[i]` 時，所有它依賴的子問題（如 `dp[i+1]`）都已經被算出來了。

### 路徑二：Iterative Bottom-Up (重新定義狀態與方向)

此方法更符合人的直覺（從左到右），但需要更仔細的思考。

- **狀態定義:** 將 `dp[i]` 的意義反過來定義，例如，`dp[i]` 代表「在 `0` 到 `i` 的範圍內所能得到的最佳解」。
- **迴圈方向:** 迴圈可以從 `i = 0` 迭代到 `n-1`。
- **挑戰:** 這種方式通常需要更仔細地思考狀態轉移方程，因為它可能涉及索引的轉換或對 base case 的重新設計，相對容易出錯。

**結論：** 對於初學者或在面試場合，**路徑一 (Iterative Top-Down) 是更推薦的、更不容易出錯的改寫路徑。**

---

## 3. Bottom-Up 實作的藝術

### 處理索引合法性：哨兵 (Sentinels) 的妙用

Top-Down 遞迴可以透過 `if (i >= n) return 0;` 這樣的邊界判斷，優雅地處理越界問題。但在 Bottom-Up 的迴圈中，每次都判斷 `i-1`、`j-1` 是否合法會讓程式碼變得冗長。

- **解決方案：** 使用**哨兵 (Sentinels)**，即在 DP 表的尺寸上加一（例如，`vector<int> dp(n + 1, 0)`）。
- **優點：**
  - `dp[0]` 或 `dp[n]` 可以作為一個統一的、無效的基礎案例。
  - 迴圈內的狀態轉移方程可以寫得非常簡潔，無需處理 `i=0` 的邊界情況。
  - 例如，`dp[i]` 可以依賴 `dp[i-1]`，當 `i=1` 時，`dp[0]` 就是一個已知的、安全的基礎值。

### 決定填表順序：畫出依賴箭頭

Bottom-Up 的迭代順序並非固定不變，它完全由**狀態轉移的依賴方向**決定。

- **黃金法則：** 在計算 `dp[i][j]` 時，它所依賴的所有狀態都必須是已知的、計算完畢的。
- **推導技巧：**
  1. **畫出 DP 表格：** 畫出一個二維表格代表 `dp[i][j]`。
  2. **寫下轉移方程：** 例如，`dp[i][j] = dp[i-1][j] + dp[i][j-1]`。
  3. **畫出依賴箭頭：** 這個方程告訴我們，要計算 `(i, j)`，需要其**上方** `(i-1, j)` 和**左方** `(i, j-1)` 的值。所以在圖上，從 `(i-1, j)` 和 `(i, j-1)` 畫箭頭指向 `(i, j)`。
  4. **確定迴圈：** 觀察所有箭頭的方向，它們共同構成了一個從左上到右下的流動。這就決定了你的 `for` 迴圈必須是 `for i = 0..m` 和 `for j = 0..n`。

如果轉移方程是 `dp[i] = f(dp[i+1], dp[i+k])`，那麼依賴箭頭是從右指向左，迴圈就必須從 `n-1` 迭代到 `0`。這個簡單的視覺化技巧可以消除所有關於迴圈方向的困惑。

### 識別有效狀態與空間優化

在許多二維 DP 問題中（例如 `dp[i][j]`），並非所有 `(i, j)` 組合都是有效的狀態。一個常見的模式是只有表格的**上半部分**或**下半部分**有意義（例如，當 `j >= i` 時）。

- **精確迴圈範圍：**
  - **識別模式：** 首先要從問題的約束中識別出無效狀態。例如，在「最長回文子序列」問題中，`dp[i][j]` 代表子字串 `s[i...j]` 的解，因此 `j` 必須永遠大於等於 `i`。
  - **調整迴圈：** 與其寫 `for i=0..n, for j=0..n` 然後在迴圈內部加 `if (j < i) continue;`，不如直接將迴圈改為 `for i=0..n, for j=i..n`。這讓程式碼更簡潔，意圖也更清晰。

- **通往空間優化之路：**
  - **觀察依賴：** 識別有效狀態區域後，結合「依賴箭頭」技巧，可以清晰地看到狀態轉移是否只依賴前一列或前一行。
  - **狀態壓縮：** 如果 `dp[i][...]` 的計算只依賴 `dp[i-1][...]`，那麼整個二維表格 `dp[N][M]` 就可以被壓縮成一個一維陣列 `dp[M]`。這就是所謂的「滾動陣列」或空間優化技術，能將空間複雜度從 O(N\*M) 降至 O(M)。

這個步驟不僅是為了微小的效能提升，更是對問題結構深刻理解的體現。
