# Subset Sum：候選進度 × 數值範圍與偽多項式時間

**把「選過哪些物品」的歷史，壓成「還能選哪些物品、還需要多少」；確認數值範圍可負擔後，再把唯一子問題放進表格。**

本篇從正整數的 Subset Sum 與 0/1 Knapsack 出發，說明為什麼指數級搜尋可以轉成數值狀態 DP，以及為什麼 O(nT) 稱為偽多項式（Pseudo-polynomial，也譯虛擬多項式）。不需要先記住查表程式。

本篇屬於 [Knapsack DP 筆記](../Problem_Types/Knapsack_DP.md)；背包是模型家族，偽多項式是複雜度描述，兩者不是互斥分類。

## 1. 先定義問題，不先猜表格

Subset Sum 問：給定 n 個正整數，每個輸入位置最多選一次，能否選出總和恰好為 T 的子集？相同數值的不同位置仍是不同物品，不能直接去重丟掉數量。
0/1 Knapsack 則給每個物品重量與價值，在容量限制內最大化總價值；Subset Sum 是其特例：令重量與價值都等於原數值，容量為 T，判斷最優值是否等於 T。

候選物品個數 n 與目標數值 T 是不同的規模。前者控制可選物品，後者限制搜尋中可能需要記錄的累積量或餘額。

## 2. 從暴力法找出「可以忘記的歷史」

固定順序，每個物品有選／不選兩種決策。直接展開最多有 2^n 個完整選擇；沿路維護餘額時，完整搜尋樹有 O(2^n) 個節點，並非每次都必須重算整份子集的和。

接著問：兩條不同的歷史，到達同一個位置，而且剩餘目標相同，未來還有差別嗎？

**如果未來可用物品與待完成目標都相同，後續可行性就相同；過去究竟怎麼選，可以忘掉。**
這才是共用答案的理由。先定義這個等價關係，再加入 cache；不是因為數值能當陣列索引，就直接假設可以共用。

## 3. 由剩餘問題定義兩個狀態軸

| 狀態軸 | 語義 | 為什麼不能省略？ |
|---|---|---|
| `i`：候選進度 | 只允許使用輸入位置 `[i,n)` 的物品 | 決定哪些物品還能用，避免同一物品重複選取 |
| `r`：remaining | 剩下必須恰好湊出的數值 | 即使可用物品相同，不同目標也可能有不同答案 |

`F(i,r)` 表示「只用 `[i,n)` 的物品，每個最多一次，能否湊出 r」，回傳布林可行性。

- **已湊滿**：r = 0 時成功，不必再選任何物品。
- **已用完**：i = n 且 r > 0 時失敗。
- **不選目前物品**：問 `F(i+1,r)`。
- **選目前物品**：僅當數值不超過 r 時，問 `F(i+1,r-a[i])`。
- 任一分支可行，該狀態就可行；兩者皆否才不可行。

兩種選擇都推進到 i+1，所以每個物品最多使用一次，遞迴也必定終止。依序把所有子集分為「含目前物品」與「不含目前物品」，這兩類完整涵蓋可能性。
`sum` 與 `remaining` 可以作為互換的表示法，但狀態必須選定一個明確語義，轉移與 base case 跟著它推導。

## 4. 數值範圍，讓狀態數可以估計

在上述正整數模型中，從目標 T 開始，只把合法的非負餘額存入表：

- i 有 n+1 種進度，r 有 T+1 種值。
- 狀態數至多 `(n+1)(T+1)`；base case 也可以不存進 cache。
- 每個狀態只處理選／不選兩個分支，單次轉移成本 O(1)。
- 因此標準二維 DP 為 **O(nT) 時間、O(nT) 表格空間**；T = 0 也納入時可寫 O(n(T+1))。Top-down 另有 O(n) 遞迴堆疊。

Top-down 只計算走到的狀態，但若先配置並初始化整張二維表，這份 O(n(T+1)) 的成本仍存在。Bottom-up 則安排每個狀態的計算順序；能索引表格，不代表已證明依賴順序正確。

## 5. 「候選 × 值域」究竟在數什麼？

不要把「物品」、「狀態」與「每個狀態的選擇」混成同一件事。

| 問題形式 | 狀態數 | 每個狀態的直接工作 | 總成本 |
|---|---|---|---|
| 0/1 選／不選，數值目標為 T | O(nT)，候選進度是狀態軸 | 兩個分支，O(1) | O(nT) |
| 所有候選可重用，只有餘額決定未來，且每次數值嚴格減少 | O(T) | 若每個狀態枚舉全部 n 個候選，則 O(n) | O(nT) |
| 每個物品最多一次，另有兩個獨立數值限制 | O(nT₁T₂) | 若每個狀態仍只有常數個分支，則 O(1) | O(nT₁T₂) |

**時間 = 各狀態處理成本的總和；常見估計是「狀態數 × 每個狀態的轉移成本」。**
兩個方法都寫成 O(nT)，n 卻可能來自不同地方；不能據此把 0/1 的 index 省掉，也不能漏算重用模型每個狀態枚舉全部候選的成本。

## 6. 什麼條件下，「數值有界」真的能幫上忙？

數值範圍可控是重要訊號，但還需逐項確認：

1. **狀態充分**：相同 key 是否真的有相同的可用選項與後續答案？若仍受已選物品集合影響，光記餘額就不夠。
2. **數值離散且範圍可控**：要數的是餘額、總和、容量或差值的完整範圍，不只看單一元素大小。
3. **總維度可負擔**：每個數值軸各自不大，乘起來仍可能太大；先估計格數、單格大小與轉移次數。
4. **依賴有進度**：0/1 的 index 推進；只用餘額的遞迴則需其他嚴格進度。沒有進度的循環不能只靠加 cache 解決。
5. **狀態值符合輸出**：判定存 bool、計數存方法數、最佳化存最值；列舉所有解還有必要輸出成本，不能由小表格推得總時間很小。

若含負數，餘額可能增加，不能沿用「r < 0 就失敗」或只開 `[0,T]`；要重新推導完整範圍與轉移。若含零且允許重用，也需重新檢查終止與計數語義。
若範圍很大但可達狀態很少，可以考慮稀疏儲存；它只省掉沒出現的狀態，不保證可達狀態總數變成多項式。

## 7. 為什麼是偽多項式，而非一般多項式？

數值 T 與表示 T 所需的輸入長度不同。二進位表示約需 `log₂(T+1)` 個位元；用 b 個位元可以表示數量級為 2^b 的值。
因此 O(nT) 對數值 T 是多項式，卻可能隨該數值的編碼長度 b 指數增長。**偽多項式描述的是這種依賴數值大小的成本，不是答案不精確，也不是近似演算法。**
不能因此聲稱每一筆輸入都要花指數時間；當 T 足夠小，或所有數值能由輸入長度的多項式約束時，這個 DP 可以很實用。

MIT 6.006 的教材直接以「剩餘物品後綴＋剩餘容量」定義背包子問題，再由 O(nT) 個狀態、每個 O(1) 工作推出時間；另比較容量數值與二進位輸入長度，說明偽多項式的名稱。[2008 Lecture 21，第 5 頁](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2008/bfbad56de149e6245cc371bc918982cb_lec21.pdf#page=5)、[2020 Recitation 19，第 1 頁](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/7232b0ff982f501556118a8552654762_MIT6_006S20_r19.pdf#page=1)。

## 8. 與 NP-Completeness、空間壓縮及值域 DP 的界線

- **NP-Completeness**：標準正整數 Subset Sum 判定問題是弱 NP-Complete；有偽多項式 DP，不代表已找到按二進位輸入長度計算的一般多項式演算法。這兩件事並不矛盾。0/1 Knapsack 的最佳化版本稱 NP-hard，談 NP-complete 時要明確指定其判定版本。
- **有界不等於可負擔**：不能只說目標有上限就保證 DP 可行，也不能只憑 T 的門檻判斷；必須一起計算 n、其他狀態軸、轉移與記憶體。
- **一維 rolling array**：只是把物品進度改由迴圈輪次隱含，並未在語義上取消每個物品最多一次的限制。更新方向需保證讀取正確輪次的結果；詳見 [實作指南](02-Implementation_Guide.md)。
- **兩種「值域」觀點**：這裡的數值軸是累積目標／餘額；[按原始數值分組的值域 DP](../State_Design/03-On_Value_Space.md) 則研究原始值之間的衝突。不能因為都以數字索引，就認為兩者可以共用同一種狀態或拋棄 index。

## ✅ 辨識口訣與檢查清單

**先定剩餘問題 → 確認哪些歷史可忘 → 保留候選限制與數值目標 → 估計狀態範圍 → 計入每格轉移 → 再決定是否查表。**

- [ ] 能用一句話說明 `F(i,r)`，並證明相同 key 的後續問題相同。
- [ ] 知道 n 是候選進度的狀態數，還是每個狀態要試的選擇數。
- [ ] 已推導完整數值範圍，確認負數、零、重用與恰好／至多的語義。
- [ ] 已估計所有維度乘積、每格成本、初始化、堆疊與輸出成本。
- [ ] 能說明 O(nT) 為何依賴數值，而非只依賴它的編碼長度。
