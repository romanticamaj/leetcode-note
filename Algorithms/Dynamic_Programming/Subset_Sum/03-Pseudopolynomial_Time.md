# 偽多項式時間：數值大小、輸入長度與 NP-complete

**O(nT) 對數值 T 是多項式，卻不一定對「寫下輸入所需的位元數」是多項式。**

本篇以正整數 Subset Sum 與 0/1 Knapsack 說明：為什麼 DP 可以實用，卻不推翻 NP-completeness；以及「推導 range」與「題目限制 range 很小」有何不同。不需要先看解題程式碼。

## 1. 先區分問題、演算法與輸入限制

| 層次 | 問的是什麼？ |
|---|---|
| 問題 | 是否存在恰好湊出 T 的子集？是否存在符合重量與價值門檻的背包選擇？ |
| 演算法 | 目前採用的方法，需要多少時間與空間？ |
| 輸入限制 | 元素數、數值、總和與容量，允許有多大？ |

**某個 DP 不是多項式時間，不等於已證明這個問題沒有其他多項式演算法。** 同樣地，某份限制下的測資能快速解，也不代表一般問題已被快速解決。

## 2. 數值 T，不是輸入長度

設輸入以二進位編碼。正整數 T 所需的位元數為：

```text
b = floor(log₂ T) + 1
2^(b-1) ≤ T < 2^b
```

因此，b 個位元就能寫下數量級為 2^b 的 T；但如果為每個整數 0..T 建立一格，卻需要 T+1 格。

完整 Subset Sum 輸入還包含 n 個數字。令 L 為整份輸入的位元長度，概略為：

```text
L = Θ(n + log₂(T+1) + Σ log₂(a[i]+1))
```

式中已將每個元素與分隔等基本編碼成本計入；常數與具體編碼方式不影響本篇的區分。**一般「多項式時間」要求成本受 L 的某個固定次方約束，不只看 n，也不能把一個大整數的數值當成它的輸入長度。**

## 3. 為什麼 O(nT) 叫偽多項式？

標準 Subset Sum DP 以「物品進度 × 目標總和」建立狀態，至多 O(n(T+1)) 格，每格處理選／不選。一般寫成 O(nT)，這裡先假設 T≥1。

因為 T 可達 Θ(2^b)，這份成本可能達到：

```text
O(nT) = O(n · 2^b)
```

這說明該成本界依賴的是數值大小，而不只是表示數值所需的位元數，不能作為一般多項式時間保證。這類對輸入長度與輸入整數的數值大小呈多項式依賴的演算法，稱為 **pseudo-polynomial time／偽多項式時間**。

「偽」描述複雜度的衡量方式；DP 仍然計算精確答案，不是近似演算法。它也不是每筆輸入都必須花指數時間的下界，更不排除其他演算法在某些輸入上更快。

上面的標準格數分析通常以單格操作 O(1) 為模型；若表格儲存任意精度的計數或價值，還需計入其位元長度與算術成本。Subset Sum 的布林表本身不需儲存巨大計數。

## 4. 推導 range，不會自動讓 range 變小

| 動作 | 能保證什麼？ | 不能保證什麼？ |
|---|---|---|
| 從輸入推導安全上下界 | 不漏掉必要狀態，避免探索無關範圍 | 範圍一定小到能配置或遍歷 |
| 依目標裁切不可能有用的狀態 | 在正確性理由成立時減少工作 | 新範圍一定對輸入位元長度呈多項式 |
| 題目限制總和／容量很小 | 偽多項式 DP 可能在指定規模內實用 | 一般問題已得到多項式時間解法 |

**不是「我們鎖住範圍，所以演算法才變成偽多項式」。這個 DP 本來就依賴數值範圍；限制讓該範圍可負擔，才使它適合使用。**

即使把 T 改成由輸入計算出的總和 S，也沒有消除這件事：若元素可以很大，S 一樣可以很大。「由輸入算出來」不代表「數值被輸入長度的多項式限制」。

若 T≤L^c，其中 c 是固定常數，則 O(nT) 在這個受限輸入家族上確實是多項式。小數值限制的作用，是讓本來依賴數值大小的成本得到控制。

## 5. NP-complete 的判斷，是另一條證明

### 屬於 NP：給定選擇後，可以快速驗證

對判定問題的 Yes instance，若存在一份長度為輸入長度多項式、可在多項式時間內驗證的證明，該問題屬於 NP。這等價於非確定性機器能在多項式時間內求解。

Subset Sum 的證明可以是 n 個選／不選位元；驗證者只需加總所選數值並與 T 比較。Knapsack 判定版則檢查重量與價值門檻。二進位加總與比較的位元成本也仍是多項式，不需要遍歷 0..T。

### NP-hard：將已知難題歸約到目前問題

經典結果是 `3-SAT ≤ₚ Subset Sum`：可在多項式時間內轉換，使原邏輯公式可滿足，若且唯若轉換後的子集和問題有解。完整的數字編碼構造見來源教材；這裡不把這個定理當成顯然成立。

方向必須是 **已知 NP-hard 的 A → 待證明的 B**。若 B 可快速求解，便可先轉換、再解 B，從而快速解 A；所以 B 至少與 A 一樣難。任意兩題之間存在歸約，或看到暴力法有 2^n 個選擇，都不足以證明 NP-hard。

### Subset Sum 如何歸約到 Knapsack？

給定 Subset Sum 的 a[i] 與 T，令每件物品的重量、價值都等於 a[i]，容量 W=T、要求價值 V=T。Knapsack 判定版同時要求：

```text
總重量 ≤ T，而且總價值 ≥ T
因重量與價值相同，等價於選取總和恰好為 T。
```

轉換只需複製數值，編碼長度保持多項式。因此 `Subset Sum ≤ₚ Knapsack`；兩者都屬於 NP，兩個判定問題便都是 NP-complete。

標準二進位編碼版本通常稱為**弱 NP-complete**；有偽多項式演算法正是此處重要的特徵。0/1 Knapsack 的「最大價值是多少」是最佳化問題，稱 NP-hard；NP-complete 正式用於判定版本。計數版本也不能直接套用判定問題的分類。

## 6. 為什麼兩件事不矛盾？

NP-complete 並不等於「已證明不存在多項式演算法」。已知的是：**若一般 NP-complete 問題有多項式時間演算法，則 P=NP；若 P≠NP，則不存在這種一般解法。**

O(nT) DP 沒有提供按二進位輸入長度計算的多項式保證，所以不會推翻 NP-completeness。當數值限制很小，它仍然是有效且精確的方法。

## ✅ 使用數值 DP 前的檢查

- [ ] 區分項目數 n、數值目標 T、T 的位元數 b，以及完整輸入長度 L。
- [ ] 從選擇的效果定義數值狀態，再證明安全範圍；不先猜陣列大小。
- [ ] 實際估計所有維度的格數、轉移、初始化與記憶體，而不只說「有上限」。
- [ ] 能說清楚：數值範圍小讓方法實用，不是限制一個 range 就證明一般多項式時間。
- [ ] 不用目前演算法的成本，冒充所有演算法都無法突破的下界。
