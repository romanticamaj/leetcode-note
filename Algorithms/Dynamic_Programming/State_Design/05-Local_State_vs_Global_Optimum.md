# 局部狀態與全域追蹤設計心法

## 🧠 核心哲學

DP 狀態定義決定「答案在哪裡」：
- **答案位置確定**：`dp[n-1]` 就是答案（如爬樓梯、背包）
- **答案位置不確定**：答案需從所有 `dp[i]` 或 `max(dp[0]...dp[n-1])` 中尋找

## 關鍵判斷：何時需要外部追蹤？

### 不需要外部追蹤

**特徵**：問題本質是「處理完所有元素/到達終點的狀態」

**心法識別**：
- 問題問「到達 n」或「使用完所有」
- `dp[i]` 自然表示「前 i 個元素的累積結果」
- 答案天然在 `dp[n-1]` 或最後一個狀態

**範例**：爬樓梯、0-1 背包、最短路徑到終點

### 需要外部追蹤

**特徵**：最優解可能出現在**任何位置或區間**

**心法識別**：
- 問題問「任意子串/子數組」或「矩陣中任意位置」
- `dp[i]` 表示「與位置 i 相關的局部屬性」
- 最優解需要在遍歷中比較所有 `dp[i]`

**範例**：最長回文子串、最大子數組和、最大正方形

## 狀態類型選擇：Boolean vs Numeric

| 選擇 | 判斷標準 | 範例 | 追蹤內容 |
|------|---------|------|---------|
| Boolean | 值可從**索引**計算 | 回文（長度=j-i+1） | 位置索引 |
| Numeric | 值需**遞推**計算 | 正方形邊長、最大和 | 最優值 |

## 決策流程

```
最優解位置確定？
 ├─ 是 → dp[i]="前i個結果"，答案在dp[n-1]
 └─ 否 → dp[i]="與i相關屬性"，需外部追蹤
          ↓
     值可從索引計算？
      ├─ 是 → Boolean + 追蹤位置
      └─ 否 → Numeric + 追蹤最優值
```

## 外部追蹤設計模式

### Boolean State + 位置追蹤

- **追蹤什麼**：`start`, `end`, `maxLen`
- **更新時機**：當 `dp[i][j] == true` 時
- **答案提取**：用位置從原始數據提取

### Numeric State + 值追蹤

- **追蹤什麼**：`maxValue`, `minValue`
- **更新時機**：比較 `dp[i]` 與已追蹤值
- **答案提取**：直接返回追蹤的值

## 遍歷順序優化

### 利用單調性

**觀察**：遍歷順序若保證單調性（如長度遞增），可省略比較

**標準邏輯**：`if (當前 > 最優) 更新`  
**優化邏輯**：`if (條件成立) 直接更新`（無需比較）

**應用**：區間 DP 按長度遞增時，遇到 true 直接記錄即可

## 常見設計陷阱

### ❌ 混淆局部與全域

**錯誤**：`dp[i][j]` = "子矩陣 [i:m][j:n] 中的最大值"
- 同時包含「從 (i,j) 開始」和「整個範圍最優」
- 例：`dp[0][0]` 需知道整個矩陣的最大值，但這正是最終答案本身

**問題**：子問題有重疊但非獨立、轉移方程複雜、邊界難處理

### ✅ 分離設計

**正確**：`dp[i][j]` = "以 (i,j) 為特定位置的屬性"
- 狀態純粹，只關注一個位置
- 例：`dp[2][3]` = "以 (2,3) 為右下角的最大正方形邊長"，與其他位置無關

**優勢**：轉移方程簡潔、外部變數收集全域最優

## 設計檢查清單

- [ ] 最優解位置是否確定？
- [ ] `dp[i]` 代表局部屬性還是全域最優？
- [ ] 值能從索引計算嗎？（能→Boolean）
- [ ] 是否混合多種語義在一個狀態？
- [ ] 遍歷順序有單調性可利用嗎？

## 複雜度影響

**分離設計不增加複雜度**：
- 時間：O(狀態數) + O(1)更新 = O(狀態數)
- 空間：O(狀態數) + O(1)追蹤變數

**但顯著提升**：正確性、可讀性、可維護性

## 典型問題分類

**需外部追蹤**：LC 5（回文子串）、LC 53（最大子數組）、LC 221（最大正方形）  
**不需追蹤**：LC 70（爬樓梯）、LC 322（零錢兌換）、LC 300（最長遞增子序列）
