# 動態規劃的黃金路徑：從回溯到最佳解的系統化推導

本文件旨在闡述一個系統性的思維框架，用以解決適合使用動態規劃 (Dynamic Programming) 的問題。透過從一個簡單的暴力解法開始，並逐步進行迭代優化，我們能夠在清晰理解底層邏輯的基礎上，最終得到最佳解。

--

## tl;dr

1. **暴力搜尋 (Exhaustive Search / Brute-Force Recursion)**
   - 定義狀態 `state` 來探索所有可能性。
   - 建構子問題的遞迴關係。
2. **Top-Down DP (Memoization)**
   - **狀態優化**：最小化 `state` 的維度，避免記錄冗餘資訊。
   - **空間壓縮**：將某些狀態維度吸收到函式內部的運算中，而不是作為 `state` 的一部分。
3. **Bottom-Up DP (Tabulation)**
   - **迭代方向**：根據狀態依賴性決定迴圈順序。
   - **表格大小與初始值**：根據狀態範圍與基礎案例設定。
   - **答案定位**：確認最終解在表格中的位置。
   - **變數命名**：保持清晰以避免錯誤。

`狀態定義子問題，回傳值解決子問題`

## DP 的哲學：為何動態規劃可行？

在開始解題前，必須先理解動態規劃的兩個核心前提，它們是所有 DP 解法的基石。

### (1) 最優子結構 (Optimal Substructure)

- **定義：** 一個問題的全域最優解，可以由其子問題的最優解構成。
- **核心判斷：** 當前狀態的最優解，是否能透過「當前選擇」與「後續子問題的最優解」組合而成？
- **重要性：** 如果不滿足此條件，問題本身不適合用 DP 解決，可能需要退回至回溯法或貪心法等其他策略。

### (2) 重疊子問題 (Overlapping Subproblems)

- **定義：** 在遞迴求解的過程中，許多相同的子問題會被反覆計算。
- **目的：** DP 的核心目的就是透過快取 (caching) 或列表 (tabulation) 來避免重複計算這些子問題，從而提升效率。

## 黃金推導路徑：從遞迴到迭代的演進

### Recursive Approach (遞迴解法)

#### 階段一：暴力遞迴 (Brute-force Recursion)

- **目標：** 不計代價地解決問題，正確性優先。
- **方法：** 寫一個純粹的遞迴函式，探索所有可能性。這個函式定義了問題的「狀態」和「選擇」。
- **核心產出：** 這一步就誕生了最原始、最核心的「遞迴關係式」。例如 `fib(n) = fib(n-1) + fib(n-2)`。這個關係式是正確的，但效率極低，因為它會重複解決相同的子問題。

#### 階段二：由上而下 DP (Top-Down DP / Memoization)

- **觸發條件：** 識別出「最優子結構」與「重疊子問題」。
- **關鍵轉變：`collect` vs. `combine` 思維**
  - **`combine` 思維 (返回最優解):** 這是最常見的模式。遞迴函式 `return` 子問題的最優解，父問題直接利用這個回傳值來建構自己的解。例如，在爬梯子問題中，`solve(i)` 返回從第 `i` 階爬到頂端的方法數。
  - **`collect` 思維 (返回局部屬性):** 然而，並非所有問題都適合 `combine` 思維。有時，硬把全域最優解塞進單一 DP 狀態的語意中，反而會讓狀態轉移變得異常複雜。在這種情況下，維持 `collect` 思維更為明智。
    - **策略：** 讓 DP 狀態 `dp[i]` 只代表一個**局部屬性**，並在遞迴或迭代的過程中，用一個**全域變數**來「收集」或更新全域最優解。
    - **範例 (221. Maximal Square):** `dp[i][j]` 代表「以 `(i, j)` 為右下角的最大正方形邊長」。我們在計算每個 `dp[i][j]` 的同時，用一個 `max_so_far` 變數來更新全局的最大邊長。如果試圖讓 `dp[i][j]` 代表「在 `0..i`, `0..j` 矩陣中的最大正方形」，狀態轉移會變得非常困難。
  - **結論：** 兩種思維模式都是重要的工具，應根據題型判斷。`combine` 更為常見，但當狀態定義變得彆扭時，應考慮 `collect` 模式。
- **實現：** 在暴力回溯的基礎上，增加一個快取 (cache) 來儲存已解的子問題，避免重複計算。

### Iterative Approach (迭代解法)

#### 階段三：由下而上 DP (Bottom-Up DP / Tabulation)

- **目標：** 消除遞迴呼叫的堆疊開銷，轉為迭代形式。
- **優點：** 效能通常更佳，且是通往最終空間優化的必經之路。

##### 從 Top-Down 到 Bottom-Up 的思維轉換

將遞迴解法轉為迭代時，有兩種主要思路來設計 DP 表和迴圈方向：

1. **直接沿用遞迴的狀態定義 (更直觀):**

   - **狀態定義:** `dp[i]` 的意義與遞迴函式 `solve(i)` 完全相同。例如，如果 `solve(i)` 代表「從索引 `i` 到結尾所能得到的最佳解」，那麼 `dp[i]` 也代表同樣的意義。
   - **迴圈方向:** 迭代的順序與遞迴的求解順序**相反**。遞迴是從 `solve(0)` 一路呼叫到 `solve(n-1)` (base case)，然後回傳結果。因此，迭代必須從 base case 開始計算，即從 `i = n-1` 迴圈到 `0`，這樣在計算 `dp[i]` 時，所有它依賴的子問題（如 `dp[i+1]`）都已經被算出來了。
   - **優點:** 這是從 Top-Down 最自然的改寫方式，狀態轉移方程幾乎可以照搬，不易出錯。

2. **重新定義狀態以符合直覺的迴圈方向:**
   - **狀態定義:** 也可以將 `dp[i]` 的意義反過來定義，例如，`dp[i]` 代表「在 `0` 到 `i` 的範圍內所能得到的最佳解」。
   - **迴圈方向:** 迴圈可以從 `i = 0` 迭代到 `n-1`，這通常更符合人的直覺。
   - **挑戰:** 這種方式通常需要更仔細地思考狀態轉移方程，因為它可能涉及索引的轉換或對 base case 的重新設計，相對容易出錯。

**結論：** 兩種方式都可以。對於初學者或在面試場合，**第一種方式（沿用遞迴定義，反向迭代）是更推薦的、更不容易出錯的改寫路徑。**

#### 階段四：空間優化 (Space Optimization)

- **觀察：** 如果 `dp[i]` 的計算只依賴於前 `k` 個狀態（如 `dp[i-1]` 和 `dp[i-2]`），則無需儲存整個 DP 表。
- **實現：** 使用固定數量的變數來模擬一個**滾動陣列 (Rolling Array)**，以儲存必要的先前狀態。
- **效果：** 將空間複雜度從 `O(n)` 降至 `O(k)` 或 `O(1)`，達成最優解。

## 實現的藝術：狀態定義與基礎案例

### (1) 狀態定義 (State Definition)

> **前置閱讀：** 在深入探討狀態定義的細節之前，強烈建議先閱讀 [DP 狀態設計精要](./State_Design_Essentials.md)，以建立「問題狀態」與「決策空間」的核心觀念。

- **核心：** `dp[i]` 的物理意義是什麼？這是 DP 中最重要的一步。它將直接決定遞迴關係式和基礎案例。
- **常見定義：**
  - **Top-Down 常用：** `dp[i]` 代表「從索引 `i` 到結尾所能得到的最佳解」。
  - **Bottom-Up 常用：** `dp[i]` 代表「在 `0` 到 `i` 的範圍內所能得到的最佳解」。

### (2) 遞迴關係式的設計 (Designing the Recurrence Relation)

在定義了狀態 `dp[i]` 的意義後，下一步就是建立狀態之間的轉移關係，即遞迴關係式。這是 DP 的核心邏輯。設計的出發點通常有兩種視角：

1. **子問題組合視角 (Subproblem Combination):**

   - **核心思想：** 與分治法 (Divide and Conquer) 或減治法 (Decrease and Conquer) 類似，思考 `problem(n)` 的解如何由 `problem(n-1)`, `problem(n-2)` 等子問題的解組合而成。
   - **適用場景：** 當問題結構清晰，可以直觀地分解成規模更小的相同問題時。
   - **範例 (Fibonacci):** `fib(n) = fib(n-1) + fib(n-2)`。
   - **範例 (爬梯子):** 到達第 `n` 階的方法數，等於「從第 `n-1` 階爬上來的方法數」加上「從第 `n-2` 階爬上來的方法數」。`ways(n) = ways(n-1) + ways(n-2)`。

2. **決策選擇視角 (Choice / State Transition):**
   - **核心思想：** 從暴力窮舉 (Brute Force) 的思路出發，分析在每個狀態下，我們可以做出哪些「決策」，以及每個決策會將我們帶到哪個「後續狀態」。
   - **適用場景：** 這是更通用、更強大的設計方法，適用於幾乎所有 DP 問題。它迫使你思考狀態轉移的本質。
   - **推導步驟：**
     1. **定義狀態 `dp(i, ...)`：** 思考在處理到第 `i` 個元素時，你需要知道什麼才能做出最優決策。
     2. **列舉決策：** 在這個狀態下，你有幾種選擇？例如，對於 `nums[i]`，你可以「選」或「不選」；對於當前位置，你可以往「左」或「右」走。
     3. **寫出轉移方程：** 對於每種決策，寫出它所對應的遞迴呼叫。最終的 `dp(i, ...)` 就是在所有決策的結果中，取最優的那個（例如 `max`, `min`, 或 `sum`）。
   - **範例 (0/1 背包):**
     - **狀態:** `dp(i, w)` = 從前 `i` 個物品中選，放入容量為 `w` 的背包，能得到的最大價值。
     - **決策 (對於第 `i` 個物品):**
       - **不選:** 解等於 `dp(i-1, w)`。
       - **選 (如果放得下):** 解等於 `value[i] + dp(i-1, w - weight[i])`。
     - **轉移方程:** `dp(i, w) = max(不選的結果, 選的結果)`。

**心法總結：** 當問題結構直觀時，可以嘗試「子問題組合」視角。但當問題複雜時，回歸到「決策選擇」視角，從暴力窮舉的思維出發來推導狀態轉移方程，是最穩健的途徑。

### (3) 基礎案例 (Base Case) 的設計哲學

- **A. 明確的 Base Case (Explicit Base Case):**
  - **定義：** 當問題規模小到可以直接給出答案時（如 `n=0` 或 `n=1`），將其作為遞迴的終點。這是最直觀的思路。
- **B. 虛擬的 Base Case (Virtual Base Case):**
  - **目標：** 為了讓一個遞迴公式能統一應用於所有索引，避免在程式碼中出現 `if (i == 0)` 等特判。
  - **實現：** 人為地定義在「無效」索引（如 `i < 0`）處的狀態值為 `0` 或其他中性值。

> **心法：** 一個優雅的 DP 設計，會用**虛擬的 Base Case** 來統一所有狀態的計算公式。

### (4) 定位最終答案 (Locating the Final Answer)

在 Bottom-Up DP 中，計算完成後，最終答案不一定總是在 `dp` 表的最後一個位置。根據狀態定義的不同，答案可能出現在三個地方：

1. **直接定位於特定單元格**

   - **描述：** 這是最常見的情況。如果 `dp[i]` 的定義是「解決從 `0` 到 `i` 的子問題」，那麼原始問題（從 `0` 到 `n-1`）的解通常就是 `dp[n-1]`。如果狀態定義是「解決從 `i` 到 `n-1` 的子問題」，那麼解就是 `dp[0]`。
   - **範例：**
     - **Climbing Stairs:** `dp[n]` 就是到達第 `n` 階的方法數。
     - **0/1 Knapsack:** `dp[N][W]` 就是用 `N` 個物品填滿容量 `W` 的背包的最大價值。

2. **在計算過程中記錄全域最優解**

   - **描述：** 當 `dp[i]` 只代表一個「局部屬性」時（例如，「以 `i` 結尾」的最優解），全域最優解必須在整個 DP 計算過程中，透過一個額外的變數來追蹤。
   - **範例：**
     - **Longest Increasing Subsequence:** `dp[i]` 代表「以 `nums[i]` 結尾」的最長遞增子序列長度。最終答案是 `max(dp[0], dp[1], ..., dp[n-1])`。
     - **Maximum Subarray:** `dp[i]` 代表「以 `nums[i]` 結尾」的最大子陣列和。最終答案是所有 `dp[i]` 中的最大值。

3. **在 DP 表的某個範圍內尋找**
   - **描述：** 有時，問題的解對應於 DP 表的最後一行或最後一列中的最優值。
   - **範例：**
     - **Edit Distance:** `dp[i][j]` 代表 `word1` 的前 `i` 個字元和 `word2` 的前 `j` 個字元的最小編輯距離。最終答案是 `dp[m][n]`。但如果問題是「`word1` 的前 `i` 個字元轉換成 `word2` 的**任何**子字串的最小距離」，那麼答案可能就是 `min(dp[i][0], dp[i][1], ..., dp[i][n])`。

## 複雜度優化視角

從時間與空間複雜度的角度，這個演進路徑可以總結為：

1. **暴力回溯 (Brute-Force Backtracking):**

   - 時間：指數級，如 `O(2^n)`。
   - 空間：遞迴深度，如 `O(n)`。

2. **由上而下 DP (Top-Down DP / Memoization) & 由下而上 DP (Bottom-Up DP / Tabulation):**

   - **時間優化：** 透過快取或 DP 表，避免了對重疊子問題的重複計算，將時間複雜度從指數級降至多項式級（如 `O(n)` 或 `O(n*m)`）。這是最關鍵的效能提升。
   - 空間：`O(n)`，用於儲存快取或 DP 表。

3. **空間優化 (Space Optimization):**
   - **空間優化：** 在 Bottom-Up 的基礎上，如果狀態轉移只依賴於固定的前幾個狀態，則可以透過滾動陣列將空間複雜度從 `O(n)` 優化至 `O(k)` 或 `O(1)`。
