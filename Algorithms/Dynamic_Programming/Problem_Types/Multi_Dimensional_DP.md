# 多維動態規劃心法手冊

## 1. 核心挑戰：輸入 + 限制條件

多維 DP 的一個常見模式包含：

- **輸入 (Inputs)**：一個或多個資料結構（如陣列、字串），大小為 `n`、`m` 等。
- **限制 (Constraint)**：一個限制性因素，通常是整數 `k`（例如：操作次數、目標總和）。

DP 函式的狀態幾乎總是輸入的索引與當前限制值的組合。一個典型的狀態是 `dp(i, k)`，代表從 `input[i]` 開始處理，且剩下 `k` 次操作的子問題的最佳解。

---

## 2. 狀態設計：最小化的藝術

一個好的 DP 解答，其基礎在於一個最小化但又完整的狀態表示。

### 原則：狀態不應記錄路徑

一個常見的陷阱是將 **當前的解路徑** 或 **已做出的選擇** 包含在狀態中，這會導致狀態空間爆炸。

- **錯誤的狀態**: `dp(i, k, curr_solution)`
- **正確的狀態**: `dp(i, k)`

**為什麼？** `curr_solution` 是已走路徑的「結果」，而不是描述「子問題」本身。最佳解是透過在狀態 `(i, k)` 做出 **選擇**，並將其價值 **組合到「下一個」狀態的最佳解** 上來建構的。

**關鍵心法**：`狀態定義子問題，回傳值解決子問題`。兩者要分開。

---

## 3. Top-Down 到 Bottom-Up：實戰指南

將遞迴（帶有記憶化）的解法轉換為迭代（帶有表格）的解法是一項關鍵技能。

### 轉換的四點檢查清單

1. **確定迭代方向**：

   - 查看遞迴呼叫。如果 `dp(i, k)` 呼叫 `dp(i + 1, ...)`，你的 `i` 迴圈必須從 `n - 1` 迭代到 `0`。
   - 如果 `dp(i, k)` 呼叫 `dp(..., k - 1)`，你的 `k` 迴圈必須從 `1` 迭代到 `k`。
   - 目標是確保子問題在被需要之前已經被解決。

2. **定義表格大小與初始值**：

   - **表格大小**：由狀態範圍決定，通常是 `n x k`。`(n + 1) x (k + 1)` 的空間有助於優雅地處理邊界條件。
   - **初始值設定**：
     - **Top-Down (Memoization)**：`cache` 通常用一個無效值（如 `-1`）來填充，表示該狀態尚未計算過。這是判斷是否需要遞迴計算的依據。
     - **Bottom-Up (Tabulation)**：`dp` 表格的初始值直接對應遞迴的基礎案例（Base Case）。例如，如果遞迴中 `dp(i, 0)` 回傳 `0`，那麼在表格中就將所有 `dp[i][0]` 設為 `0`。

3. **定位最終答案**：
   - 答案是原始問題的解。如果你的初始遞迴呼叫是 `dp(0, k)`，那麼表格中的最終答案就是 `table[0][k]`。

4. **使用清晰的變數名稱**：
   - 區分迴圈計數器（`i`, `j`, `p`）和問題的限制條件（`n`, `k`）。
