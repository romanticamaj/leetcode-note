# Matrix DP 解題心法：從網格到圖論

本心法提供一個系統性的四階段框架，用於解決矩陣動態規劃（Matrix DP）問題。此框架不僅適用於簡單的網格遍歷，也同樣適用於以鄰接矩陣表示的抽象圖論問題。

---

## 🧠 核心哲學：DP 即結構化狀態空間的遍歷

Matrix DP 是一種將問題分解為子問題網格的技術。矩陣中的每個儲存格 `dp[i][j]` 代表一個特定子問題的解。其核心思想是透過迭代，利用已解決的子問題來建構更大問題的解。

此方法適用於：

- **網格遍歷 (Grid Traversal):** 在二維網格上尋找路徑、成本或計數。
- **鄰接矩陣問題 (Adjacency Matrix Problems):** 解決如最短路徑（Floyd-Warshall）或可達性等圖論問題。
- **序列對齊 (Sequence Alignment):** 如編輯距離等，其狀態由兩個序列的索引定義的問題。

---

## 🧩 四階段解題框架

遵循這四個階段，系統性地解構並解決任何 Matrix DP 問題。

### Stage 1: Exhaustive Search (Brute-Force Recursion)

**目標：** 在不考慮效率的情況下，定義問題的遞迴結構。這是所有優化的基礎。

1. **狀態定義 (State Definition):** 識別定義一個唯一子問題所需的最小參數。對於矩陣問題，這通常是座標 `(i, j)`。
2. **遞迴關係 (Recurrence Relation):** 定義問題的解如何由其子問題建構。這包括：
   - **選擇 (Choices):** 可能的下一步是什麼？（例如，向右移動、向下移動）。
   - **組合 (Combination):** 子問題的結果如何組合？（`min`、`max`、`+`）。
3. **基本情況 (Base Cases):** 定義遞迴的終止條件。
   - **越界 (Out-of-Bounds):** 返回一個中性值（例如，計數問題返回 `0`，最小成本問題返回 `infinity`）。
   - **到達目標 (Target Reached):** 返回一個初始值（例如，計數問題返回 `1`，成本問題返回 `grid[i][j]`）。

### Stage 2: Top-Down DP (Memoization)

**目標：** 透過快取結果來優化暴力解，以避免重複計算。

1. **建立快取 (Create a Cache):** 宣告一個與狀態空間維度相同的快取（例如，二維陣列）。
2. **初始化快取 (Initialize Cache):** 用一個哨兵值（例如 `-1`）填充快取，以表示該狀態尚未計算。
3. **實現快取邏輯 (Implement Cache Logic):**
   - **檢查 (Check):** 在計算之前，檢查當前狀態的結果是否已在快取中。如果是，則直接返回。
   - **儲存 (Store):** 計算結果後，在返回之前將其儲存在快取中。

### Stage 3: Bottom-Up DP (Tabulation)

**目標：** 將遞迴解轉換為迭代解，消除遞迴開銷，並為空間優化提供清晰的路徑。

1. **表格初始化 (Table Initialization):** 建立一個與狀態空間大小相同的 DP 表（通常是二維陣列）。
2. **基本情況植入 (Base Case Seeding):** 直接初始化表格的基本情況（例如 `dp[0][0]` 或第一行/第一列）。
3. **迭代順序 (Iteration Order):** 設計迴圈，使其遍歷狀態的順序符合遞迴關係的依賴性。如果 `dp[i][j]` 依賴於 `dp[i-1][j]` 和 `dp[i][j-1]`，則必須從左上到右下進行迭代。
4. **填寫表格 (Fill the Table):** 在迴圈內部應用遞迴關係來填寫表格。

### Stage 4: Space Optimization

**目標：** 減少自底向上解法的記憶體使用量。

1. **分析依賴性 (Analyze Dependencies):** 識別計算當前狀態需要多少先前的行或列。如果 `dp[i][j]` 僅依賴於前一行（`i-1`）和當前行（`i`），則可以壓縮空間。
2. **實現壓縮 (Implement Compression):**
   - **`O(n)` 空間:** 使用一維陣列儲存前一行的結果，並在計算當前行時進行更新。
   - **`O(1)` 空間 (原地修改):** 如果可能，直接修改輸入網格作為 DP 表。當原始網格值在使用一次後不再需要時，這是可行的。

## ⚠️ 常見陷阱與檢查清單

- **初始化:** 您是否正確初始化了基本情況和越界值（例如，最小路徑問題中的 `infinity`）？
- **迭代順序:** 在自底向上法中，您的迴圈順序是否確保了依賴項在需要之前已經被計算？
- **迭代起點與基本情況的脫節 (Iteration Start vs. Base Case Mismatch):** 即使基本情況定義在 `(0,0)`，迭代也必須從 `(0,0)` 開始，以確保 `(1,0)` 和 `(0,1)` 能正確讀取基本情況的值。迴圈的起點必須與基本情況的計算順序一致。
- **差一錯誤 (Off-by-One Errors):** 您的陣列索引和迴圈邊界是否正確，尤其是在使用填充（padding）時？
- **空間優化:** 在壓縮空間時，您是否正確管理了“前一個”和“當前”狀態值，以避免過早覆蓋所需的數據？

## ⏱️ 複雜度分析總結

| 方法                      | 時間複雜度 | 空間複雜度             | 主要特點                   |
| ------------------------- | ---------- | ---------------------- | -------------------------- |
| 1. Exhaustive Search      | `O(c^n)`   | `O(n)` (遞迴深度)      | 定義問題結構               |
| 2. Top-Down (Memoization) | `O(M*N)`   | `O(M*N)` (快取 + 堆疊) | 從遞迴的直觀過渡           |
| 3. Bottom-Up (Tabulation) | `O(M*N)`   | `O(M*N)` (表格)        | 迭代式，無遞迴開銷         |
| 4. Space Optimized        | `O(M*N)`   | `O(N)` 或 `O(1)`       | 最高效，需要謹慎的狀態管理 |
