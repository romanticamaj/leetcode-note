# 回溯法的數學化視角：狀態空間樹與 N 元組

當我們用程式碼實現回溯法時，我們是在隱性地構建和遍歷一個「決策樹」。在演算法理論中，這個樹有一個更正式的名稱：**狀態空間樹 (State-Space Tree)**。將回溯過程數學化，有助於我們更深刻地理解其本質。

## tl;dr: 核心思想

- **狀態空間樹 (State-Space Tree)**：是回溯法探索的所有可能狀態的抽象表示。樹的每個節點都是一個**部分解 (Partial Solution)**。
- **N 元組 (n-tuple)**：許多問題的**完整解**可以被表示為一個 n 元組 `S = (x₁, x₂, ..., xₙ)`，其中 `xᵢ` 是在第 `i` 步做出的選擇。
- **回溯的過程**：可以看作是從一個空的部分解 `S₀` 開始，逐步構建更長的解 `S₁`, `S₂`, ...。如果發現當前的部分解 `Sᵢ` 無法延伸到一個完整解，就退回到 `Sᵢ₋₁`，並嘗試為 `xᵢ` 選擇一個不同的值。這個過程本質上就是對狀態空間樹的**深度優先搜索 (DFS)**。

---

## 1. 狀態空間樹 (State-Space Tree)

狀態空間樹不是一個預先存在的資料結構，而是由回溯演算法的執行過程所隱性定義的。

- **根節點 (Root Node)**：代表問題的初始狀態，通常是一個空解 `S₀`。
- **節點 (Node)**：樹中的任一節點代表一個**部分解候選** `Sₖ = (x₁, x₂, ..., xₖ)`。節點的深度 `k` 代表已經做出了 `k` 個決策。
- **邊 (Edge)**：從父節點 `Sₖ` 到子節點 `Sₖ₊₁` 的一條邊，代表在 `Sₖ` 的基礎上，做出了一個新的決策 `xₖ₊₁`。
- **路徑 (Path)**：從根節點到任一節點的路徑，唯一地定義了一個部分解。
- **葉節點 (Leaf Node)**：代表一個**終端狀態**。它可能是一個完整的有效解，也可能是一個無法再延伸的「死胡同」。

回溯演算法的任務，就是在這棵龐大的、隱性的樹上，透過 DFS 找到所有通往「有效解」葉節點的路徑。

## 2. 將解表示為 N 元組

我們可以將許多組合優化問題的解，形式化地表示為一個 n 元組 `S = (x₁, x₂, ..., xₙ)`，它需要滿足一組約束條件 `P(S)`。

- `xᵢ` 是在第 `i` 個決策步驟中，從選擇集合 `Cᵢ` 中選出的一個值。
- 一個**部分解** `Sₖ = (x₁, x₂, ..., xₖ)` 是**可行的 (promising)**，如果它有可能被擴展成一個完整解。

### 數學化的回溯過程

1. **開始**：從空解 `S₀` 開始。
2. **延伸 (Extend)**：假設我們有一個可行的部分解 `Sₖ₋₁ = (x₁, ..., xₖ₋₁)`。我們嘗試為第 `k` 個位置選擇一個值 `xₖ`。
3. **迭代選擇**：我們遍歷第 `k` 步的所有可能選擇 `c ∈ Cₖ`。
4. **約束檢查 (Pruning)**：對於每一個選擇 `c`，我們檢查新的部分解 `S' = (x₁, ..., xₖ₋₁, c)` 是否滿足問題的約束條件。
   - 如果滿足，我們就得到一個新的、更長的可行部分解 `Sₖ = S'`，並遞迴地去解決 `Sₖ₊₁`。
   - 如果不滿足，我們就**剪枝**，放棄這個選擇 `c`，繼續嘗試 `Cₖ` 中的下一個選擇。
5. **回溯 (Backtrack)**：如果在 `Cₖ` 中嘗試了所有選擇，都無法找到一個可行的 `xₖ` 來延伸 `Sₖ₋₁`，那麼說明 `Sₖ₋₁` 這條路走不通。我們從遞迴中返回，回到 `Sₖ₋₂` 的狀態，去嘗試為 `xₖ₋₁` 選擇一個不同的值。

## 3. 範例：N-皇后問題的數學化

這是一個絕佳的例子，可以清晰地展示上述概念。

- **解的表示 (N-tuple)**：一個解可以表示為 n 元組 `S = (x₁, x₂, ..., xₙ)`，其中 `xᵢ` 代表第 `i` 行的皇后被放置在第 `xᵢ` 列。
- **狀態空間樹**：
  - 根節點是空棋盤。
  - 深度為 `k` 的節點代表一個部分解 `(x₁, ..., xₖ)`，即前 `k` 行的皇后已經被合法地放置。
- **遞迴步驟 (從 `Sₖ₋₁` 到 `Sₖ`)**：
  - **給定狀態**：我們已經合法地放置了前 `k-1` 個皇后，即 `Sₖ₋₁ = (x₁, ..., xₖ₋₁)`。
  - **任務**：為第 `k` 行的皇后找到一個合法的列 `xₖ`。
  - **約束檢查 (Pruning)**：對於每一個候選列 `c ∈ {1, ..., n}`，我們檢查它是否滿足 N 皇后的約束：
    1. **不同列**：`c ≠ xⱼ` for all `j < k`。
    2. **不同對角線**：`|k - j| ≠ |c - xⱼ|` for all `j < k`。
  - **決策**：
    - 如果檢查通過，我們就做出選擇 `xₖ = c`，並帶著新的部分解 `Sₖ` 遞迴下去，解決第 `k+1` 行。
    - 如果檢查不通過，這條路就被**剪枝**了。
  - **回溯**：如果在第 `k` 行嘗試了所有 `n` 個列都無法找到合法位置，則說明 `Sₖ₋₁` 這個部分解無法導向完整解。函式返回，我們回到第 `k-1` 行，去嘗試為 `xₖ₋₁` 找一個新的位置。

## 4. 從數學模型到程式碼的對應

這個看似抽象的模型，其實與我們的程式碼模板一一對應：

| 數學模型概念            | 程式碼實現                                                |
| :---------------------- | :-------------------------------------------------------- |
| **狀態空間樹的節點**    | 遞迴函式 `backtrack()` 的一次呼叫                         |
| **部分解 `Sₖ`**         | 函式參數中的 `path` 或 `currentState`                     |
| **延伸 `Sₖ` 到 `Sₖ₊₁`** | `for` 迴圈遍歷所有 `choices`，並遞迴呼叫                  |
| **約束檢查 `P(S')`**    | `if (is_promising(...)` 或 `if (is_valid(...)` 的剪枝判斷 |
| **回溯**                | 從遞迴呼叫返回，並執行 `unmake_choice()` 來還原狀態       |
