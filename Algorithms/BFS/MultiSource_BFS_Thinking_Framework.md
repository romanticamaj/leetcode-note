# Multi-source BFS 心法與推導框架

## tl;dr

- **核心思想**：將「每個點找最近的來源」反轉為「所有來源點同時擴散」。
- **兩種心法**：
  1. **超級源點 (Super Source)**：想像一個虛擬節點連接所有來源，從它開始做一次 BFS。
  2. **洪水擴散 (Flood Fill)**：把所有來源點當作第一波洪水，同時向外淹沒未訪問的區域。

---

## 🧠 問題背景：什麼時候該用 Multi-source BFS？

你可能會遇到這種情況：

> 「我現在的解法是每個節點自己去找最近的來源，會不會太慢？能不能反過來，讓所有來源同時去『影響』其它節點？」

這時候，**Multi-source BFS** 就是你該切換的思維模式。

---

## 💡 核心原理：為什麼 Multi-source BFS 是正確的？

Multi-source BFS 的本質可以想像成一個「超級源點」(Super Source)。我們可以虛擬一個超級源點，並對所有初始來源點（sources）連一條權重為 0 的邊。從這個超級源點開始做一次單源 BFS，其效果等同於 Multi-source BFS。

**正確性保證**：

1. **初始化**：將所有來源點的距離設為 0，其他點設為無窮大，並將所有來源點放入佇列。
2. **BFS 特性**：BFS 保證了當一個節點第一次被訪問時，一定是通過最短路徑。因為所有來源點同時以「層」為單位向外擴散，所以任何一個目標點被「觸及」時，必然是由離它最近的來源點所觸及。

這解釋了為什麼我們不需要對每個目標點都做一次 BFS，而是可以透過一次從所有來源點同時開始的 BFS，就為所有目標點找到最短距離。

---

## ✅ Step 1: 問題結構是什麼？

- 是不是 **格子型 / 圖型問題？**
- 點與點之間是不是「上下左右」或「有邊相連」？
- 有沒有「**最短距離**」的需求？

✅ 如果以上皆是：**這就是 BFS 類問題！**

---

## ✅ Step 2: 問題有幾個「source」？

- 傳統 BFS 是：**一個起點 → 所有點**
- Multi-source BFS 是：**多個起點 → 擴展出去**

❗ 關鍵判斷：

> 有沒有**一群初始節點已知距離為 0**？

常見例子：

- 542. 01 Matrix（所有 0 是起點）
- 994. Rotten Oranges（所有腐爛橘子是起點）
- 286. Walls and Gates（所有 gate 是起點）

---

## ✅ Step 3: 時間複雜度反推法

| 方法 | 對每個目標點做單源 BFS                   | 從所有來源點做多源 BFS               |
| ---- | ---------------------------------------- | ------------------------------------ |
| 想法 | 每個目標點各自尋找最近的來源             | 所有來源點同時擴散影響力             |
| 時間 | `O(目標點數量 * (V+E))`                  | `O(V+E)`                             |
| 推論 | 複雜度過高，因為大量節點和邊被重複訪問。 | 每個節點和邊只會被訪問一次，足夠快。 |

這種從 `O(N * (V+E))` 到 `O(V+E)` 的量級差異，是推動我們尋找更優解法（如 Multi-source BFS）的核心動力。

## 🛠️ 通用演算法結構

與其記憶特定程式碼，不如掌握其核心結構。Multi-source BFS 的流程可以簡化為以下兩個主要步驟：

### 步驟 1: 初始化 - 建立距離圖並找到所有來源點

- **建立 `dist` 容器**：建立一個與原圖/網格同樣大小的容器（如 `vector<vector<int>>`），用來儲存每個點到最近來源點的距離。通常初始化為一個特殊值（如 -1 或 `INT_MAX`）來表示「尚未訪問」。
- **找出所有來源點 (Sources)**：遍歷一次輸入，找到所有符合「來源」條件的節點。
- **初始化佇列 (Queue)**：
  - 將所有來源點的座標加入佇列。
  - 將這些來源點在 `dist` 容器中的距離設為 0。

```cpp
// 偽代碼
queue<Node> q;
map<Node, int> dist; // 或 vector<vector<int>>

// 遍歷所有節點
for (node : all_nodes) {
    if (is_source(node)) {
        q.push(node);
        dist[node] = 0;
    } else {
        dist[node] = -1; // 未訪問
    }
}
```

### 步驟 2: 標準 BFS - 擴散並更新距離

- **執行標準的 BFS 迴圈**：當佇列不為空時，持續進行。
- **更新鄰居距離**：從佇列中取出一個節點，遍歷其所有鄰居。如果鄰居尚未被訪問（即 `dist` 為 -1），則：
  - 更新鄰居的距離：`dist[neighbor] = dist[current] + 1`。
  - 將鄰居加入佇列，以便後續擴散。

**核心洞察**：這個方法之所以有效，是因為 `dist` 陣列本身就隱含了層級（level）資訊。每當我們從 `dist[current]` 更新 `dist[neighbor]` 時，我們其實就是在處理下一層的節點。因此，不需要額外的 `level` 計數器。

```cpp
// 偽代碼
while (!q.empty()) {
    current = q.front();
    q.pop();

    for (neighbor : current.neighbors) {
        if (dist[neighbor] == -1) { // 如果尚未訪問
            dist[neighbor] = dist[current] + 1;
            q.push(neighbor);
        }
    }
}
```

## 🔄 與單源 BFS 的比較

| 特性           | 單源 BFS (Single-Source)               | 多源 BFS (Multi-Source)          |
| :------------- | :------------------------------------- | :------------------------------- |
| **目標**       | 從一個起點到所有點的最短路             | 從多個起點到所有點的最短路       |
| **佇列初始化** | 只將單一起點放入佇列                   | 將所有來源點一次性放入佇列       |
| **距離初始化** | 起點距離為 0，其餘為無窮大             | 所有來源點距離為 0，其餘為無窮大 |
| **適用場景**   | 迷宮起點到終點、單一好友的社交網路擴散 | 01 矩陣距離、多個火源的蔓延      |

## 🏋️‍♂️ 如何訓練這種「切換思維」？

### 1. 刷圖型 BFS 的經典題目（有多個起點的）

- 542. 01 Matrix
- 994. Rotten Oranges
- 286. Walls and Gates
- 847. Shortest Path Visiting All Nodes

> 特別注意它們**怎麼初始化 queue**，不是只有一個點，而是「全部符合條件的點」一起進 queue。

---

### 2. 練習從暴力到優化的**推導路徑**

- 先寫出暴力解
- 用實例推估時間複雜度
- 再問自己：「我是不是重複走了很多遍一樣的地方？」
- 想辦法「讓來源點變成主動出發」

---

### 3. 把「BFS 是一種洪水」當成心法

> 把 BFS 想成水流，你會自然想從一群水源出發，去灌滿所有節點。  
> 這會比「每個節點去找水源」還直覺。

---

## ✅ 總結

Multi-source BFS 是一種非常實用的優化技巧，當你發現：

- 有多個自然起點
- 每個節點都要找最近的來源
- 暴力法時間太慢

就該啟動這套「反推 + 洪水擴散」的思維模式。
