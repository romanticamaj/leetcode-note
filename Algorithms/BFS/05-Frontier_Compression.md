# Frontier 壓縮：把 queue 換成邊界（Frontier Compression）

> **queue 存的是 frontier。如果 frontier 有更緊緻的表示法，queue 就可以被那個表示法取代。**

BFS 的 `queue` 從來不是目的，它只是「當前這一層有哪些節點」的一種**儲存方式**。當 frontier 的形狀夠規律、可以用常數個數字描述時，整個 queue（連同 `visited`）可以消失，BFS 退化成一次線性掃描——時間從 O(V + E) 降到 O(V)，空間從 O(V) 降到 O(1)。

---

## 🧠 壓縮的四個階梯

| 階梯 | frontier 的表示 | 何時可用 |
| :--- | :--- | :--- |
| 0. 一般 BFS | queue 存整層節點 + `visited` | 永遠可用 |
| 1. 層大小快照 | queue + `int sz = q.size()` | 只要需要「層」的概念 |
| 2. **層邊界** | **兩個整數**（當前層右界、下一層右界） | frontier 是**連續區間** ← 本篇主角 |
| 3. 層計數 | 一個整數 | 只需要「有幾個」，不需要知道是誰 |

階梯 1 見 [01-Level_Ordering_Level_in_Queue.md](01-Level_Ordering_Level_in_Queue.md)。這篇談階梯 2。

---

## 🧩 核心對應關係

當 frontier 是一段連續區間時，queue 的每一個動作都有對應的替代物：

| 一般 BFS | 壓縮後 |
| :--- | :--- |
| `q.push(next)` — 把下一層節點推進去 | `farthest = max(farthest, reach(i))` — **累積下一層的右界** |
| `q.pop()` — 取出當前層節點 | `i++` — **掃描指標前進**，因為當前層就是一段連續索引 |
| 當前層處理完 | `i == levelEnd` — 掃到當前層的右界 |
| `depth++` | `++distance; levelEnd = farthest;` — **封存下一層邊界，同時進層** |
| `visited[]` | **不需要**（見下方） |

一句話記憶：

> **`farthest` 取代 push，`levelEnd` 取代 pop。**

`farthest` 與 `levelEnd` 是**同一個量的兩個時間點**——前者是正在長的下一層邊界，後者是已經封存的當前層邊界。撞到邊界的那一刻，把前者整個接給後者。

### 為什麼 `visited` 也消失了

一般 BFS 需要 `visited` 是為了避免同一個節點被重複入隊。壓縮版不需要，因為**掃描指標只單調前進、每個節點恰好被處理一次**——「不重複」由掃描順序本身保證，而不是靠標記。

這跟雙指針用「單調推進」取代「重複檢查」是同一個手法。

## ✅ 成立的三個條件

要做階梯 2 的壓縮，必須**三個條件同時成立**：

1. **frontier 連續** — 「用 ≤ d 步可達的集合」必須是一段連續區間（通常是從起點開始的**前綴**），沒有洞
2. **邊界可累積推出** — 下一層的邊界 = 當前層所有成員的「可達上界」取 **max**；`max` 可交換、可結合，所以邊掃邊累積就行，不需要保留成員身分
3. **不需要知道身分** — 答案只問「幾步」，不問「走哪條路」

任一條不成立，就退回階梯 0 或 1。

> 條件 1 通常來自「**移動只有單一方向，且可以跳更少**」：能到 `k` 就必然能到 `k-1`、`k-2`…，於是可達集合是前綴。**這個小前提是整個壓縮的地基**，值得單獨驗證。

---

## ⚠️ 什麼時候壓不動

| 情況 | 哪個條件破了 | 結果 |
| :--- | :--- | :--- |
| 可以**往回**移動、或跳躍目標不連續 | 條件 1：frontier 出現洞 | 必須留著 queue |
| 有障礙物 / 某些位置不可進入 | 條件 1：連續性被打斷 | 必須留著 queue |
| 要求**回傳路徑**而不只是距離 | 條件 3：需要身分 | 必須留著 queue（並記 parent） |
| 節點是多維狀態（座標、位元遮罩） | 條件 1：沒有一維的「邊界」可言 | 必須留著 queue |

**「同一個問題，換一條移動規則就換一種資料結構」**——單向可跳到連續區間 ⟹ 兩個整數；可雙向或可跳到離散集合 ⟹ 老實用 queue。看清楚破在哪一條，比記住哪題能壓有用。

---

## 💡 怎麼發現可以壓

1. 先**老實寫出分層 BFS**（`q.size()` 快照那版），確認正確
2. 手算一個小例子，把每一層的成員**列出來**
3. 盯著那幾層問：**它們是什麼形狀？**（連續？前綴？散開？）
4. 若是連續區間 → 問「描述它最少要幾個數字」→ 通常是 1 個（右界）
5. 若只要 1 個數字，queue 裡那一堆 index 就是多餘的 → 替換成上面的對應表

**不要跳過第 1 步。** 先有一個會動的分層 BFS，壓縮才有東西可以對照，也才有辦法驗證壓縮後答案沒變。

---

## ⏱️ 複雜度

| | 一般 BFS | 壓縮後 |
| :--- | :--- | :--- |
| 時間 | O(V + E) — **E 才是瓶頸**，隱式圖裡 E 可能遠大於 V | O(V) — 從不枚舉邊 |
| 空間 | O(V)（queue + visited） | **O(1)** |

隱式圖（每個節點的鄰居由規則生成）特別容易誤判複雜度：節點數看起來是 n，但邊數可能是 n 乘上分支度。壓縮版的價值正在於**完全不碰邊**。

---

## ✅ 檢查清單

- [ ] 先寫出正確的分層 BFS 了嗎？
- [ ] 手算小例子，每層是連續區間嗎？
- [ ] 「能到 k 就能到 k−1」這個前提成立嗎？（連續性的來源）
- [ ] 下一層邊界能只用 `max` 累積出來嗎？
- [ ] 答案只要距離，不要路徑嗎？
- [ ] 壓縮後的邊界條件：終點要不要進迴圈？（通常**不需要從終點起跳**）
