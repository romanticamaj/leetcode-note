# 暴力法的觀察與關鍵設計（Brute Force Design）心法

**先決定「站在哪裡看、固定什麼、把哪些可能性試完」，再考慮如何減少工作。**

暴力法是直接產生候選、依題意檢查或求值，再彙整答案的基準方法。它不必刻意做最多工作，但必須具體、正確，而且能說明為什麼沒有漏掉答案。
難點往往在選擇觀察視角：同一份輸入，可以逐元素看、逐區間看、逐組合看，也可以逐步決策。選對分解方式，才容易寫清楚每一步，並看見後續優化的空間。

## 🧠 先分清楚三件事

- **觀察對象**：這一輪站在誰的角度看？固定的是元素、位置、區間、部分解，還是一個參數？
- **直接工作**：固定它以後，還需要搜尋、枚舉、檢查或模擬什麼？
- **答案彙整**：這次得到的是局部貢獻、一個完整候選，還是可繼續延伸的部分解？最後如何加總、取最值、判定存在或收集結果？

「每個都試」必須說出每個是什麼；「從自己看」則是把觀察對象固定，讓剩餘工作有明確的起點。
以下是可以反覆使用的設計視角，不是互斥分類，也不是必須按順序套用的解題步驟。

**用語範圍**：本篇把直接基準解的設計一起討論。前五種著重候選的枚舉或分解；第六種「直接模擬」不一定有多個候選可窮舉，因此不能把六種都當成嚴格意義下的窮舉演算法分類。

## 🧩 常用的六個關鍵設計

### 1. 從自己看：固定一個對象，查清楚它與周圍的關係

**核心問題：「如果現在只處理自己，需要知道其他地方的哪些資訊？」**

先把觀察中心固定，其他元素暫時視為影響自己的條件。直接掃描相關範圍，找出限制、關係或可用資訊，再算出這個對象對答案的影響。
若答案涉及擴展，就先固定自己的角色或限制，問「往哪些方向還合法、什麼條件會阻擋、停下的位置是否包含在結果內」。能延伸不代表一定要延伸到最遠，還須確認擴展是否使目標值變差。

**適合的觀察**：答案能逐個對象分析，或某個對象可以決定一個候選的限制。
**正確性重點**：若各自產生局部貢獻，須確認彙整時沒有漏算或重算；若各自產生最佳候選，須證明至少有一個能涵蓋全域最優解。

### 2. 固定一部分：把多個自由度拆開枚舉

**核心問題：「答案由哪些部分共同決定？先固定其中一部分後，還剩下什麼要選？」**

先寫出一個完整候選需要哪些選擇，再固定其中一部分，直接枚舉剩餘部分。每固定一部分，剩餘問題就變得更明確；此時不必急著加速內層搜尋。
選擇之間的限制也要一起帶入：哪些位置已經使用、哪些順序被允許，以及不同選擇是否會產生同一個答案。

**適合的觀察**：一個答案由多個元素、位置或角色共同組成。
**正確性重點**：每個完整候選都能由這些選擇生成；若限制枚舉順序，要能說明只是避免重複，沒有刪掉有效答案。

### 3. 從邊界看：先決定範圍，再檢查內容

**核心問題：「只要哪些邊界確定，一個候選的範圍就確定了？」**

把範圍本身當作枚舉單位。先列出所有合法的邊界組合，再直接讀取範圍內的內容，判定是否合法並計算結果。
先固定邊界的語義：包含或不包含端點、是否允許空範圍，以及搜尋不到邊界時如何表示。邊界確定後，求值應遵守同一個範圍定義。

**適合的觀察**：答案由一段連續範圍構成，或候選能由少量邊界完整描述。
**正確性重點**：所有合法範圍都能被枚舉；「候選範圍的邊界」與「範圍外第一個阻擋位置」不可混用。

### 4. 從選擇看：把完整答案拆成一連串決策

**核心問題：「目前已有這個部分解，下一步有哪些合法選擇？」**

先定義已決定與未決定的部分，再列出下一步所有選項。選一個、更新狀態、繼續展開，直到能判定完成或失敗。
下一步的選擇單位應與答案的構成方式一致；每次決策都必須推進，分支結束後也要恢復其他分支仍需要的狀態。

**適合的觀察**：完整答案具有多階段構造，難以一次用固定數量的索引描述。
**正確性重點**：每個合法答案都有對應的決策路徑；計數或列舉時，還須確認不同路徑是否代表不同答案，並說明搜尋為何會終止。

### 5. 從參數看：先假設一個值，再直接驗證

**核心問題：「若先指定一個候選值，能否直接判定它是否成立？」**

先界定候選值的完整範圍，逐一假設並驗證，再依題目要求選取結果。驗證的含義必須固定：是恰好等於、至少達到，還是不超過該值。
若驗證本身還需要搜尋，就把那份工作繼續展開；不能把尚未解決的原問題藏在一句「檢查可不可行」裡。也不必先假設驗證結果具有單調性。

**適合的觀察**：直接構造最佳答案很複雜，但固定某個參數後，合法性較容易檢查。
**正確性重點**：枚舉範圍包含所需答案，且驗證條件與要求一致；若值域不是有限離散集合，須先說明候選如何生成或何時停止。

### 6. 從規則看：一步一步直接模擬

**核心問題：「照題目規則執行一次，狀態會怎麼變？何時算完成？」**

先忠實實現單次操作，再重複到指定次數或終止條件。每一步都區分操作前的資料與操作後的資料，確認更新順序不會破壞尚未讀取的資訊。
先把直接流程說清楚，再觀察是否有重複狀態、週期，或能合併處理的操作；不必一開始就把整段過程化成公式。

**適合的觀察**：題目給出明確操作規則，結果由狀態逐步演化產生。
**正確性重點**：單步轉換符合規則，操作次數或終止條件精確，並有進度或其他理由保證終止。

## 🔍 卡住時，先換觀察單位

若一個視角讓狀態或條件越寫越複雜，先問：**我是否把太多事情綁成同一個單位？**
逐個對象看、固定部分選擇、枚舉範圍、展開決策、指定參數與逐步模擬，可以是同一題的不同入口。切換視角時，重新寫明候選與求值方式，再檢查是否仍涵蓋答案。
「從自己看」尤其有用：它先把問題縮成一個局部提問。但它需要完整性論證，不能只因為局部計算容易，就認為逐個處理必然能得到全域答案。

## ⏱️ 把暴力法的成本算清楚

對枚舉型流程，成本是**生成候選、各候選的檢查／求值，以及必要輸出成本的總和**；各候選成本相近時，才可簡化為「候選數 × 每個候選的處理成本」。
對遞迴流程，要數整棵搜尋樹的工作，不能只看遞迴深度；對模擬流程，則要同時看操作次數與單次成本。複製狀態、保存完整結果與額外空間也要納入。
暴力法沒有固定的複雜度級數；一個方法是否已經共用結果或減少候選，要看實際流程，不能只憑快慢命名。

## 🧭 基準成立後，再用 BUD 檢查工作

BUD 是對既有流程提出三種問題：

- **Bottleneck（瓶頸）**：大部分時間花在哪個步驟？是候選太多，還是單次求值太貴？
- **Unnecessary work（不必要的工作）**：是否算了輸出不需要的資訊，或處理了可證明不可能影響答案的候選？
- **Duplicated work（重複的工作）**：不同觀察對象或不同分支，是否反覆查詢同一批資訊、求解同一個狀態？

先說明想省掉哪份工作，再決定需要記錄什麼、改變什麼順序，或安全地排除哪些候選。**Bookkeeping 的內容，由原本反覆需要的資訊決定。**
記下結果不等於搜尋已變快；改變枚舉或淘汰候選，也必須補上不漏解的理由。每次優化都重新核對答案語義與成本。

## ✅ 一個暴力法說清楚了嗎？

**選視角 → 定候選 → 直接求值 → 證明不漏 → 算成本 → BUD。**

- [ ] 這一輪固定什麼？還有哪些自由度需要處理？
- [ ] 一個候選如何從原始輸入直接判定或求值？
- [ ] 每次結果如何彙整，為何得到題目要求的答案？
- [ ] 是否涵蓋所有必要候選？計數／列舉時是否重複？
- [ ] 邊界、狀態進度、還原與終止條件是否明確？
- [ ] 能否實際走過流程，並計入生成、檢查、複製與輸出的成本？
- [ ] 優化時，能否指出具體省掉的工作及其正確性依據？
