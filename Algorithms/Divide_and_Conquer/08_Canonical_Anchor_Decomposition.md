# 錨點分解（Canonical Anchor Decomposition）

> **找一個由「結構本身」決定、而不是由「我們挑選」的錨點，用它切開。**

遞迴分解一個物件時，真正的難點很少是「怎麼切」——切法通常很多——而是**怎麼切才能保證不重不漏**。這篇講的是那個保證從哪裡來。

---

## 🧠 核心概念

把一個物件分解成子問題時，你會挑一個位置下刀。這個位置有兩種來源：

| | 來源 | 後果 |
| :--- | :--- | :--- |
| ❌ **自由切點** | **我們**從多個合法位置中挑一個 | 同一個物件可能從**多組參數**被產生 → **重複** |
| ✅ **錨點（anchor）** | **物件自己**決定，沒有選擇餘地 | 分解唯一 → 枚舉不重不漏 |

錨點的定義：一個**由物件的結構唯一決定**的位置或元素。給你這個物件，你能指著它說「就是這裡」，而且答案只有一個。

> **分解唯一 ⟺ 枚舉不重複。** 這是同一件事的兩種說法。

---

## 📐 標準流程

分解一個物件時，依序問三個問題：

### 1. 有沒有一個「天然的第一個決定」？

尋找**被結構逼出來、沒得選**的元素。常見的錨點原型：

| 錨點原型 | 為什麼唯一 |
| :--- | :--- |
| **第一個元素**（當合法性把它的取值逼死時） | 位置唯一，取值被約束決定 |
| **與第一個元素配對的那一個** | 配對關係是雙射，配對者唯一 |
| **全域最大 / 最小值** | 極值唯一（有重複時需額外定序，見下方 ⚠️） |
| **樹或層級結構的 root** | 由結構本身給定 |
| **最先結束 / 最晚開始的區間** | 由排序後的極值決定 |
| **最後一個未決策項** | 決策順序固定時，「下一個」唯一 |

### 2. 這個錨點**逼出**了什麼？

錨點的價值不在它本身，而在它**連帶決定的邊界**。

一個元素被釘死之後，通常會強制某個配對者、某條分界線、或某個區間端點也跟著被釘死——那條線才是你真正的切點。

### 3. 切開之後，兩塊是不是**同型的較小問題**？

是 → 遞迴成立，寫出遞迴式。
不是 → 這個錨點選錯了，回到第 1 步換一個。

---

## ✅ 機械測試：會不會重複？

構造時我們**確實會枚舉參數**（例如「左邊那塊的大小」）。那怎麼知道枚舉不會撞車？

> **測試：拿任何一個產生出來的結果，能不能從它反推回唯一的那組枚舉參數？**
>
> - **能** → 映射是**單射**，每個結果只會被產生一次 → 不重複
> - **不能** → 同一個結果有多條產生路徑 → 必定重複

這個測試把「會不會重複」從**直覺**變成**可檢查的動作**：不是去想「應該不會吧」，而是實際做一次反推。

反推的具體做法，就是拿結果去找它的錨點——錨點唯一，參數就唯一。

---

## ⚠️ 反例：自由切點為什麼會爆

把分解定義成「切成兩塊，各自仍然合法」，而切點可以落在**任何合法位置**時：

```
一個由三個相同單元組成的物件：

   X X X  =  X  ·  X X     （參數：左邊 1 塊）
          =  X X  ·  X     （參數：左邊 2 塊）
```

同一個物件從兩組不同參數產生，於是它在結果裡出現兩次。

**病灶不是「切了兩次」，是切點沒有被物件唯一決定。** 只要把分解改成「以某個錨點為界」——例如「第一塊 = 含有第一個元素的那個不可再分的單位」——切點立刻唯一，重複自動消失。

### 三種去重手段的比較

| 手段 | 做法 | 代價 |
| :--- | :--- | :--- |
| **事後去重** | 全部生成後丟進集合 | 記憶體與時間都浪費在「生成再丟掉」 |
| **加 guard 去重** | 枚舉時用條件擋掉非正規的分法（例如強制索引不遞減） | 正確，但條件要自己設計、容易漏 |
| **錨點分解** | 改變分解方式，讓重複**結構上不可能發生** | 最乾淨，不需要任何檢查 |

能做到第三種就不要退而求其次。**「不需要檢查」永遠優於「檢查得很周全」。**

> ⚠️ 當錨點依賴極值、而極值**可能有重複**時，錨點就不再唯一。此時要用額外的定序把它變唯一（例如「最小值中索引最小的那個」），否則會退回自由切點的困境。

## 💡 怎麼真的「發現」錨點

乾想通常想不出來。可操作的做法是**照候選錨點把小 case 分組，看數字對不對得上**：

1. 手動列出規模很小時的**所有**結果（通常 n = 3 就夠）
2. 挑一個候選錨點，照「錨點落在哪裡 / 錨點的配對者在哪裡」把這些結果**分組**
3. 檢查兩件事：
   - **每個結果恰好落在一組裡**（不重不漏）→ 錨點成立
   - **各組的大小，恰好等於子問題規模對應的解數量** → 遞迴式浮現了

第 3 步的第二個檢查是關鍵：如果各組大小正好是「更小規模的答案數」的乘積或和，遞迴式基本上就寫好了。

反過來，如果發現某個結果同時屬於兩組、或某組的大小湊不出來，代表這個候選錨點**不是由結構決定的**，換一個。

> 這是「卡住就找具體例子」的精確版本：**不是隨便舉例，是照候選錨點分組後數數看。**

## 🧩 和其他觀念的關係

- **遞迴式的形狀會自己冒出來**：錨點確定後，子問題規模的組合方式（相加？相乘？笛卡兒積？）就跟著確定，不需要另外猜。
- **與「不變量倒推 guard」互補**：不變量處理的是「這條路還有沒有救」（縱向剪枝）；錨點處理的是「同一個解會不會被走到兩次」（橫向去重）。兩者一起用，枚舉型問題就不會出錯。
- **與 DP 的關係**：錨點分解得到的遞迴式，若子問題重疊，直接加 memo 就是 DP；依賴的形狀（只依賴前幾項 / 依賴所有成對切分 / 依賴所有區間切點）也順帶決定了它屬於哪一類 DP。

### 更上層：這是「正規化」的一種用法

錨點分解屬於一個更大的家族——**正規化（canonicalization）**：在一堆等價的表示法中，指定**唯一一個**當代表。

同一個手法有兩種用途，看你把代表拿來做什麼：

| 用途 | 做法 | 目的 |
| :--- | :--- | :--- |
| **去重** | 讓每個物件只有一種**分解方式** | 枚舉時不重複產生 |
| **分組** | 讓每個物件算出一個**正規形式**當 key | 等價的東西落進同一桶 |

分組的典型長相：一組物件在某種變換下彼此等價（重排、旋轉、平移、縮放），你需要把等價的歸在一起。做法是替每個物件算出**唯一的正規形式**當 hash key。

> ⚠️ 取得正規形式的手段常常不只一種，而**最直覺的手段未必最好**。例如「把元素排序」是常見做法，但如果等價關係只取決於**各元素出現幾次**，那麼直接算計數本身就是正規形式——跳過排序這個中間步驟，同時也換掉了複雜度（`k log k` → `k + Σ`）。
>
> 先問「**什麼資訊決定了等價？**」再決定正規形式怎麼算，不要反射性地排序。

兩種用途共用同一條判準：**正規形式必須唯一**。去重時唯一性保證不重複產生；分組時唯一性保證等價的東西一定撞在一起、不等價的一定不撞。

⚠️ 分組時還多一個**編碼**的陷阱：把多個數字串接成 key 時，若沒有分隔符，`[1, 11]` 和 `[11, 1]` 會編出同一個字串。**唯一的正規形式被編碼毀掉，等於沒有正規形式。**

## ✅ 檢查清單

分解任何物件之前：

- [ ] 我的切點是**物件決定的**，還是**我挑的**？
- [ ] 說得出「給我任何一個結果，我能指出它的錨點在哪」嗎？
- [ ] 做過單射測試了嗎——從結果能反推回唯一的枚舉參數？
- [ ] 錨點依賴極值時，極值可能重複嗎？需不需要額外定序？
- [ ] 切完的兩塊，真的是同型的較小問題嗎？
- [ ] 小規模手動分組驗證過：不重、不漏、各組大小對得上？
- [ ] （分組用途）什麼資訊決定等價？正規形式的**編碼**有沒有歧義（分隔符）？
