# 進階技巧：使用位元遮罩進行狀態壓縮

在演算法問題中，特別是回溯法 (Backtracking) 和動態規劃 (Dynamic Programming)，我們經常需要追蹤一個集合中的元素是否已被使用，以確保每個元素最多只使用一次。

## 問題情境：追蹤「已訪問」狀態

傳統上，我們可能會想到幾種方法來記錄狀態：

1. **布林陣列**：使用一個布林陣列 `visited[i]` 來表示第 `i` 個元素是否被訪問。

   - **缺點**：陣列本身在 C++ 中是不可雜湊的。這意味著當我們需要將「狀態」作為鍵存入 `unordered_map` 進行記憶化搜尋 (Memoization) 時，陣列無法直接使用。

2. **元組 (Tuple) 或向量 (Vector)**：將狀態轉換為 `std::vector` 或 `std::tuple`。
   - **缺點**：雖然 `std::tuple` 在某些情況下是可雜湊的，但在狀態轉換的每一步中複製和修改元組或向量的成本很高，且程式碼不夠簡潔。

## 解決方案：位元遮罩 (Bitmask)

位元遮罩是解決這個問題的最佳選擇。它將一個整數的位元對應到集合中的元素。

- **核心思想**：用一個整數 `mask` 來代表訪問狀態。如果 `mask` 的第 `i` 個位元為 1，代表第 `i` 個元素已被使用；如果為 0，則代表尚未使用。

這種方法的優勢非常明顯：

- **可雜湊**：整數本身就是可雜湊的，可以直接作為 `map` 或 `unordered_map` 的鍵。
- **高效率**：使用位元運算 (`&`, `|`, `^`) 來檢查和更新狀態，速度極快。
- **空間優化**：一個 `int` (通常 32 位元) 或 `long long` (64 位元) 就可以表示多達 32 或 64 個元素的訪問狀態，極大地節省了空間。

### 操作範例

假設我們有一個最多包含 `N` 個元素的集合，`N <= 32`。

- **狀態表示**：`int mask`，初始為 `0` (所有元素都未使用)。

- **檢查第 `i` 個元素是否已使用**：

  ```cpp
  bool is_used = (mask & (1 << i)) != 0;
  ```

- **將第 `i` 個元素標記為已使用**：

  ```cpp
  mask = mask | (1 << i);
  ```

  或者，如果確定要從未使用變為使用：

  ```cpp
  mask = mask ^ (1 << i);
  ```

- **取消對第 `i` 個元素的標記** (回溯時常用)：

  ```cpp
  mask = mask ^ (1 << i);
  ```

這種技巧在解決旅行商問題 (TSP)、排列組合相關的 DP 問題以及需要狀態壓縮的圖論問題中非常常見且強大。

## 二元模擬狀態的表示

Bitmask 不只表示 visited 集合，也能表示每格為 0／1 的完整系統狀態。LC 957 可用 8-bit 整數表示八格，作為 cycle detection 的 key；循環加速與狀態壓縮是兩個可分開使用的設計。見 [狀態循環與 Fast Forwarding](../Simulation/02-Cycle_Detection_and_Fast_Forward.md)。
