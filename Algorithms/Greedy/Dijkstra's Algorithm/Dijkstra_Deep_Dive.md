# Dijkstra 演算法深度剖析

Dijkstra 演算法是圖論中最著名且應用最廣的演算法之一，常用於解決帶有非負權重的單源最短路徑問題。本篇旨在深入探討其核心思想、與 BFS 的關係、關鍵資料結構以及實作中的權衡。

## 1. 核心概念：作為 BFS 的貪婪優化

Dijkstra 的核心思想可以理解為**對加權圖的廣度優先搜尋 (BFS) 的一種貪婪優化**。

- **標準 BFS 的局限**：在**無權重圖**中，BFS 能保證找到最短路徑，因為它逐層擴展，第一次到達某節點的路徑必然是邊數最少的路徑。然而，在**加權圖**中，邊數最少的路徑不等於權重總和最小的路徑。若直接使用普通佇列 (Queue) 進行 BFS，無法保證先從佇列中取出的節點就是距離源點最近的節點。

- **Dijkstra 的貪婪策略**：Dijkstra 演算法引入了貪婪策略來解決這個問題。其策略是：**在所有已被發現但尚未完全探索的節點中，永遠優先選擇距離源點最近的那個節點進行擴展**。

- **Priority Queue 的作用**：為了高效地實踐這個貪婪策略，「尋找距離最近的節點」這個操作是關鍵。
  - **若用普通陣列或佇列**：每次尋找最小值都需要 `O(V)` 的時間，效率低下。
  - **若用最小優先佇列 (Min-Priority Queue)**：可以將尋找最小值的時間複雜度降低到 `O(log V)`。這正是 Dijkstra 演算法效率的來源。

因此，Dijkstra 可以視為：**使用優先佇列來優化節點選擇策略的 BFS**。

## 2. `distance` 表的重要性：從策略到演算法

您提到 Dijkstra 不僅是解最短路徑，更是一種「選擇策略」，這個觀點非常精闢。我們可以將其拆解來看：

1. **貪婪選擇策略**：不斷從優先佇列中取出 `<distance, node>`，這個 `distance` 代表的是**某條**從源點到 `node` 的路徑權重和。
2. **最短路徑演算法**：為了確保我們最終得到的是**最短路徑**，必須引入一個外部的 `distance` 表（或稱 `dist` 陣列）。

**`distance` 表的核心作用**：
它儲存了**從源點到每個節點當前已知的最短距離**。當我們從優先佇列中取出一個節點 `{d, u}` 時，必須與 `distance[u]` 進行比較：

- **若 `d > distance[u]`**：這意味著我們之前已經找到了一條更短的路徑到達節點 `u`。因此，當前這條更長的路徑是無效的，應直接忽略，避免不必要的擴展。
- **若 `d <= distance[u]`**：這才是當前找到的最短路徑，我們繼續用它來更新其鄰居節點。

**如果沒有 `distance` 表會如何？**
演算法仍然可以運行，但它會退化成一個單純的圖遍歷策略。它會處理所有可能的路徑，包括那些明顯更長的路徑，導致同一個節點被多次以不同的距離訪問和擴展，不僅效率極低，也無法保證最終結果的正確性。

**與 BFS 的關係**：
標準 BFS 的 `visited` 集合其實扮演了類似 `distance` 表的「簡化版」角色。在無權重圖中，一旦一個節點被訪問 (`visited[u] = true`)，就意味著已經找到了到 `u` 的最短路徑，後續任何再次到達 `u` 的路徑都必然更長，可以直接忽略。

## 3. C++ 核心資料結構

在 C++ 中實現 Dijkstra 時，通常會用到以下兩種核心結構：

1. **加權鄰接表 (Weighted Adjacency List)**：
   這是儲存圖最常用的方式。`pair` 的第一個元素是鄰居節點，第二個是邊的權重。

   ```cpp
   // adj[u] = { {v1, w1}, {v2, w2}, ... }
   vector<vector<pair<int, int>>> adj;
   ```

2. **最小優先佇列 (Min-Priority Queue)**：
   用於高效實現貪婪選擇。`pair` 的第一個元素是距離，第二個是節點。使用 `std::greater` 將其變為最小堆。

   ```cpp
   // {distance, node}
   priority_queue<pair<int, int>, vector<pair<int, int>>, greater<pair<int, int>>> pq;
   ```

## 4. 時間複雜度分析

- **標準 BFS (無權重圖)**：

  - 每個頂點和每條邊都只會被訪問一次。
  - **時間複雜度: O(V + E)**

- **Dijkstra (使用二元堆實現的優先佇列)**：

  - 每個頂點最多入隊一次，出隊一次：`V * O(log V)`。
  - 每條邊最多被放鬆 (relax) 一次，可能觸發一次入隊操作：`E * O(log V)`。
  - **總時間複雜度: O((V + E) log V)**。在連通圖中，`E` 通常大於等於 `V`，因此可簡化為 **O(E log V)**。

## 5. 總結：Dijkstra 作為一種策略

Dijkstra 演算法的本質，是 **「貪婪選擇」與「狀態記錄」的結合**。

- **優先佇列**提供了高效的「貪婪選擇」工具。
- **`distance` 表**提供了「狀態記錄」機制，確保貪婪選擇的每一步都是基於當前最優解，從而保證了全域最優解。

若只取其一，演算法便不再完整。理解這一點，有助於我們在面對更複雜的圖論問題時，靈活地借用 Dijkstra 的部分思想來設計新的解決方案。

Dijkstra 的核心策略不僅能解決標準的最短路徑問題，更能透過「重新定義狀態」來解決帶有額外約束的變形問題，例如 LeetCode 787 (Cheapest Flights Within K Stops)。
