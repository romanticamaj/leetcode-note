# 模組化算術在程式設計中的實用指南

模組化算術（Modular Arithmetic）是程式設計中一個看似簡單卻影響深遠的概念。雖然在一般面試中不常出現，但在特定領域至關重要。尤其在**競技程式設計**和處理大數運算、要求結果對特定數值（如 `1,000,000,007`）取模的 LeetCode 問題中，模組化算術是不可或缺的工具。

---

## tl;dr

- **避免溢位**：在處理可能超出整數範圍的大數運算時，使用模數（`%`）運算來將結果保持在一個可管理的範圍內。
- **安全乘法**：在 C++ 中，兩個 `int` 相乘可能導致溢位。為避免這種情況，應先將其中一個運算元轉換為 `long long`，例如 `(1LL * a * b) % MOD`。
- **`1e9` 是 `double`**：在 C++ 中，`1e9 + 7` 這樣的科學記號表示法會被視為 `double` 型別，可能導致精度問題或非預期行為。應使用 `1000000007` 或 `1'000'000'007`。
- **混合型別運算**：`long long` 型別的數值可以和 `int` 型別的 `MOD` 一起進行模數運算，C++ 會自動處理型別提升，確保運算安全。
- **負數餘數與索引**：C++ 的 `%` 可能得到負數；若結果要當環狀 array index，先取餘數，再把負值加上正的模數。

---

## 負數取餘：何時要正規化？

C++ 的整數除法向零截斷，餘數與被除數同號或為零。例如 `-3 % 10 == -3`。反轉負整數、逐位取 digit 時，這個帶負號的餘數正是需要的值；但當結果要當 array index 或環狀位置時，索引必須落在 `[0, n - 1]`。

```cpp
// n > 0；將 x 對 n 的餘數正規化為 [0, n - 1]
int r = x % n;
if (r < 0) r += n;
```

例如 `x = -3, n = 10`，`x % n` 是 `-3`，正規化後是索引 `7`。不要把 `(x + n) % n` 當成任意負數的通用寫法：只有 `x >= -n` 時，加一次 `n` 才足以讓被除數非負（且加法本身仍須避免溢位）。例如 `(-13 + 10) % 10 == -3`，仍不是合法索引。先 `% n` 再視需要加 `n`，因為餘數已落在 `-(n - 1)` 到 `n - 1` 之間，加一次即可。

## 為什麼需要 MOD？

在許多演算法問題中，特別是組合數學或動態規劃領域，中間或最終結果可能輕易超出標準整數型別的表示範圍（例如，計算階乘、連乘積或大規模數組的總和）。對於像 C++ 這樣有整數溢位風險的語言，必須謹慎處理以避免未定義行為。即使在 Python 這類支援大整數運算的語言中，處理極大數值也會顯著降低執行效率。

為了解決這個挑戰，程式設計競賽和演算法題目通常會要求將最終結果對一個大質數取模：

```cpp
const int MOD = 1000000007;         // classic form
const int MOD = 1'000'000'007;      // readable, C++14+
constexpr int MOD = 1'000'000'007;  // compile-time constant
constexpr int MOD = 1_000_000_007;  // C++23 digit separator syntax
const int MOD = 1e9 + 7;            // beware: 1e9 + 7 is double, not int!
```

### ⚠️ 注意 `1e9 + 7`

- 在 C++ 中，`1e9` 是一個 `double` 型別的字面值。
- 寫成 `1e9 + 7` 會得到一個 `double`，這在模運算或整數溢位時可能導致**非預期行為**。
- 為了安全和清晰，請務必將其轉換為 `int`，或直接寫成 `1000000007`、`1'000'000'007`，或使用 `constexpr`。

## 模組化算術的關鍵性質

模組化算術讓我們能夠在保持數值較小的同時，計算出正確的答案。這要歸功於以下性質：

### 加法

```
(a + b) % MOD == ((a % MOD) + (b % MOD)) % MOD
```

### 減法

```
(a - b + MOD) % MOD == ((a % MOD) - (b % MOD) + MOD) % MOD
```

### 乘法

```
(a * b) % MOD == ((a % MOD) * (b % MOD)) % MOD
```

這些性質意味著你可以在運算過程的**每一步都進行取模**，而無需等到最後才處理，從而有效防止中間結果溢位。

---

## 實際範例

假設我們有：

```cpp
MOD = 7;
nums = [11, 15, 26, 43, 62];
```

### 完整乘積

```
11 * 15 * 26 * 43 * 62 = 11437140
11437140 % 7 = 1
```

### 每一步都取模

```
11 * 15 = 165 % 7 = 4
4 * 26 = 104 % 7 = 6
6 * 43 = 258 % 7 = 6
6 * 62 = 372 % 7 = 1
```

✅ 結果相同。

---

## C++ 實作技巧

### ❌ 不要這樣做

```cpp
int ans = (a * b) % MOD; // 不安全：可能發生整數溢位
```

### ✅ 應該這樣做

```cpp
int ans = (1LL * a * b) % MOD; // 安全：在相乘前提升為 long long
```

### ⚠️ 為什麼？

- 在 C++ 中，`int` 型別的溢位會導致**未定義行為 (Undefined Behavior)**，這是程式中應極力避免的嚴重錯誤。
- 透過 `1LL`，我們將運算元 `a` 提升為 `long long` 型別，使得整個乘法運算在 64 位元整數範圍內進行，從而避免溢位。
- 即使 `MOD` 本身是 `int`，C++ 的型別規則會確保取模運算 `%` 的正確性。

## 進階應用：混合運算

模組化算術的性質可以完美地結合。加法和乘法的分配律在模組化算術中依然成立。這意味著你可以將複雜的表達式拆解，在每一步都進行取模。

例如，對於 `(a * b + c) % MOD`，我們可以這樣分解：

```
(a * b + c) % MOD == ( (a * b) % MOD + c % MOD ) % MOD
```

這在許多演算法中非常有用，例如在計算多項式雜湊（Polynomial Hashing）或處理遞迴關係式時。

### 範例：計算 `(A * x + B) % MOD`

```cpp
long long A = 12345678;
long long B = 98765432;
long long x = 100;
const int MOD = 1'000'000'007;

// 先計算乘法部分並取模
long long term1 = (A * x) % MOD;

// 再與 B 相加後取模
long long result = (term1 + B) % MOD;

// 確保結果為正
result = (result + MOD) % MOD;
```

這種在每一步都取模的策略，是確保計算過程不會溢位且結果正確的關鍵。

## 總結

### 🔄 模組化算術思維

- ✅ 使用 `MOD` 來防止溢位。
- ✅ 在**每一步**都取模，而不僅僅是在最後。
- ✅ 進行乘法時，務必轉換為 `long long`。

### 🔢 安全的 C++ 模式

```cpp
const int MOD = 1'000'000'007;
int ans = 1;
for (int x : nums) {
    ans = (1LL * ans * x) % MOD;
}
```

這種模式能同時確保大數運算下的**正確性**與**執行效率**。

---

> ⚡ **專業提示**：當處理大量數字的連乘或累加時，將每一步的中間結果都保持在 `[0, MOD)` 範圍內，不僅是重要的效能優化，在 C++ 中更是避免未定義行為的關鍵手段。
