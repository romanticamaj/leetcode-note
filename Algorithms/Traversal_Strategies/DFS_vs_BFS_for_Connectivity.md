# 連通性問題：DFS vs. BFS 策略比較

在圖論中，**連通性 (Connectivity)** 問題是最基本也最常見的類型之一。這類問題的核心是判斷節點之間是否存在路徑，或者找出所有相互連接的節點群。一個常見的誤解是，BFS 因為能找到最短路徑，所以總是更優越。然而，當問題只關心“能否到達”時，DFS 和 BFS 都是完全可行的工具，選擇哪一個取決於對其特性的理解。

---

## 核心概念：只問「可達性」，不問「路徑」

> **連通性的核心是：走得到就好。**

我們不關心路徑的長度（最短、最長），也不關心具體路徑是什麼。我們只需要一個 `bool` 答案：`true`（可到達）或 `false`（不可到達）。

這意味著，像 BFS 保證找到最短路徑的特性，在這裡並不是必要的優勢。

---

## DFS (深度優先搜尋) 策略

DFS 在解決連通性問題時，就像一個堅持不懈的探險家，會沿著一條路走到黑，直到無路可走才返回上一個路口，嘗試另一條路。

- **資料結構：** 堆疊 (Stack)，通常透過遞迴函式的呼叫堆疊隱性實現。
- **訪問機制：**
  1. 從起始點開始。
  2. 將其標記為「已訪問」。
  3. 選擇一個**尚未訪問**的鄰居，並對其進行遞迴呼叫。
  4. 重複此過程，直到一個節點的所有鄰居都已被訪問，然後返回。
- **優點：**
  - **程式碼簡潔：** 使用遞迴實現的 DFS 通常非常優雅、簡潔。
  - **空間效率 (對特定圖)：** 如果圖很深但分支不多，DFS 使用的記憶體（遞迴深度）可能比 BFS（需要儲存整層節點）要少。
- **缺點：**
  - **可能“繞遠路”：** 如果目標節點就在起點旁邊，但 DFS 的第一選擇是一條通往圖另一端的深邃路徑，那麼 DFS 可能會遍歷大部分圖才找到目標。
  - **堆疊溢位風險：** 在極深的圖中，遞迴實現可能導致堆疊溢位 (Stack Overflow)。

---

## BFS (廣度優先搜尋) 策略

BFS 則像水波紋一樣，從中心點開始，一層一層地向外擴散探索。

- **資料結構：** 佇列 (Queue)。
- **訪問機制：**
  1. 將起始點放入佇列，並標記為「已訪問」。
  2. 當佇列不為空時，取出一個節點。
  3. 將其所有**尚未訪問**的鄰居加入佇列，並標記為「已訪問」。
  4. 重複此過程。
- **優點：**
  - **無堆疊溢位風險：** 迭代實現使其非常穩健。
  - **實務上的效能：** 「BFS 通常會快一點」是有道理的。因為 BFS 按層次遍歷，其記憶體存取模式通常更具**局部性 (Locality of Reference)**，這對 CPU 快取更友好。此外，它沒有遞迴呼叫的額外開銷。
- **缺點：**
  - **空間效率 (對特定圖)：** 如果圖很寬（一個節點有大量鄰居），佇列中可能需要儲存大量節點，導致記憶體使用較高。

---

## 為何不需要「回溯 (Backtracking)」？

對於單純的連通性問題，我們只需要一個 `visited` 集合（陣列或雜湊表）來記錄走過的路徑，**而不需要回溯**。

- **`visited` 的作用：** 確保我們不會重複訪問同一個節點，避免在有環的圖中陷入無限循環。一旦一個節點被標記為 `visited`，就意味著我們已經確認了從起點到它的連通性，無需再次考慮。
- **回溯的用途：** 回溯通常用於需要**枚舉所有可能路徑**或**尋找滿足特定條件的唯一路徑**的問題。在這些問題中，你需要“撤銷”你的選擇（例如，將節點從 `current_path` 中移除，並可能將其 `visited` 狀態重置），以便探索其他分支。
- **連通性問題的簡化：** 因為我們不在乎路徑本身，所以一旦走過，就無需“忘記”它。

---

## 總結比較

| 特性           | DFS (深度優先)                                              | BFS (廣度優先)              |
| :------------- | :---------------------------------------------------------- | :-------------------------- |
| **核心思想**   | 走到黑，再回頭                                              | 一層一層，向外擴散          |
| **資料結構**   | 堆疊 (Stack) / 遞迴                                         | 佇列 (Queue)                |
| **程式碼實現** | 遞迴寫法通常更簡潔                                          | 迭代寫法，通常更穩健        |
| **適用場景**   | 尋找是否存在路徑、拓撲排序                                  | 尋找最短路徑（邊權重為 1）  |
| **記憶體消耗** | 與最長路徑深度成正比 `O(D)`                                 | 與圖的最大寬度成正比 `O(W)` |
| **結論**       | **對於純連通性問題，兩者皆可，且時間複雜度同為 `O(V+E)`。** |

**最終選擇：** 在只關心連通性的情況下，選擇 DFS 還是 BFS 往往取決於個人偏好和具體圖的特性。遞迴 DFS 因其簡潔而受歡迎，而迭代 BFS 因其穩健和潛在的快取優勢也同樣常用。
