# 雙指針子模式：相鄰指針 (Adjacent Pointers)

**相鄰指針** (Adjacent Pointers) 是「同向雙指針」模式的一個核心變體，其設計精髓在於維持兩個指針的**固定相對位置**（通常相差 1），並讓它們同步向前移動。

這種模式如同一個大小為 2 的滑動窗口，專注於處理序列中**連續兩個元素**的關係。它在需要原地修改資料結構，特別是鏈表操作（如反轉或交換節點）時，展現出卓越的效率和簡潔性。

> **關聯:** 本文是 **[雙指針核心模式與模板](./01-Two_Pointers_Core_Patterns_and_Templates.md)** 的補充，建議先閱讀核心模式以建立完整概念。

---

## 核心思想

- **固定間距 (Fixed Gap):** 兩個指針（`prev` 和 `curr`）在邏輯上始終相鄰，保持 1 個元素的間距。
- **同步移動 (Synchronized Movement):** 兩個指針以相同的步調向前推進，共同遍歷資料結構。
- **原地操作 (In-place Operation):** 核心優勢在於能夠直接在原始資料結構上進行修改，僅需 O(1) 的額外空間。
- **職責劃分:** 通常，`curr` 指針負責探索當前節點，而 `prev` 指針則記錄其前驅節點，為反轉或交換等操作提供必要的歷史參照。

---

## 鏈表操作泛化模板

以下模板展示了相鄰指針在鏈表操作中的典型結構。

```cpp
ListNode* adjacent_pointers_template(ListNode* head) {
    // 1. 指針初始化
    ListNode* prev = nullptr;  // 前驅指針，初始為空
    ListNode* curr = head;     // 當前指針，從頭節點開始

    // 2. 循環遍歷
    while (curr != nullptr) {
        // a. 保存後繼狀態 (防止斷鏈)
        ListNode* next_temp = curr->next;

        // b. 核心操作 (Processing)
        //    在此處根據具體問題，對 curr 和 prev 進行操作。
        //    例如：反轉 curr 的指向 -> curr->next = prev;
        
        // c. 同步前進 (Movement)
        prev = curr;
        curr = next_temp; // 使用暫存的 next_temp 來安全前進
    }

    // 3. 返回結果
    //    循環結束後，prev 通常指向新的頭節點或操作完成後的參照點。
    return prev; 
}
```

## 關鍵設計要素分析

### 1. 循環終止條件 (Termination Condition)

終止條件 `while (curr)` 是模式的標準實踐，它確保了操作的安全性與完整性。

- **安全性:** 保證 `curr` 指針在被訪問前非空，避免了對 `nullptr` 的非法操作。
- **完整性:** 確保鏈表的每個節點都被訪問一次，直到 `curr` 超出鏈表末尾。
- **邊界處理:** 能自然地處理空鏈表 (`head` 為 `nullptr`) 或單節點鏈表等邊界情況。

**設計原則:** 終止條件必須與循環體內的操作相匹配，確保在循環的任何階段都不會出現無效的指針訪問，並在循環結束時達成問題的預期目標。

### 2. 指針前進邏輯 (Movement Logic)

指針的移動是模式的核心，分為兩個關鍵步驟：

```cpp
// 步驟 1: 在操作前，暫存 next 指針
ListNode* next_temp = curr->next;

// ... 執行核心操作 ...

// 步驟 2: 同步向前移動
prev = curr;
curr = next_temp;
```

- **防止斷鏈:** 提前保存 `curr->next` 至關重要。如果先修改了 `curr->next`（例如在反轉操作中），那麼原始的鏈路就會丟失，導致無法繼續遍歷。
- **維持關係:** `prev = curr;` 和 `curr = next_temp;` 這兩行代碼確保了 `prev` 和 `curr` 在每次迭代後，依然維持著「前驅」和「當前」的相鄰關係，為下一次循環準備好正確的上下文。

**設計原則:** 指針的移動策略必須服務於**核心操作**。在鏈表問題中，首要原則是**防止斷鏈**。移動前必須完成對當前節點的所有處理，並確保移動後指針的相對關係符合模式定義。

---

## 常見應用場景

- **反轉整個鏈表:** 經典應用，通過逐個反轉節點的 `next` 指針來實現。
- **反轉鏈表的一部分:** 在指定範圍內應用此模式。
- **兩兩交換鏈表中的節點:** 稍微調整操作邏輯，交換 `prev` 和 `curr` 的位置。

> **註:** 在鏈表語境中，「反轉 (Reverse)」和「交換 (Swap)」操作緊密相關。許多反轉效果是通過一系列節點指針的交換來實現的。

---

## 模式優勢

- **空間效率:** 僅需 O(1) 的額外空間，實現真正的原地修改。
- **邏輯簡潔:** 代碼結構清晰，易於理解和實現。
- **應用廣泛:** 是解決多種鏈表原地修改問題的通用範式。
