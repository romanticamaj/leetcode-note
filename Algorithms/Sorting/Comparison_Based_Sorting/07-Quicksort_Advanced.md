# 快速排序進階與優化 (Quicksort Advanced & Optimizations)

標準的快速排序在平均情況下表現出色，但在特定情況下（如處理已排序或包含大量重複元素的陣列）效能會急劇下降。為了解決這些問題，社群發展出了多種優化策略。

## 1. 隨機化分割 (Randomized Partition)

### 核心概念

這是最常用也最簡單的優化，旨在**避免最差情況的發生**。標準快速排序如果每次都選到最大或最小的元素作為基準 (Pivot)，時間複雜度會退化到 O(n²)。這種情況在處理已排序或反向排序的陣列時尤其常見。

隨機化分割的核心思想非常簡單：在進行分割前，**隨機**地從當前子陣列中選取一個元素，並將它與最後一個元素交換。然後，再執行原本的 Lomuto 或 Hoare 分割程序。

```cpp
int randomizedPartition(vector<int>& nums, int start, int end) {
    // 1. 在 [start, end-1] 範圍內隨機選擇一個索引
    int randomIndex = start + rand() % (end - start);

    // 2. 將隨機選擇的元素與最後一個元素交換
    swap(nums[randomIndex], nums[end - 1]);

    // 3. 執行標準的分割程序
    return partition(nums, start, end);
}
```

### 複雜度影響

- **時間複雜度**: 隨機化使得任何一種輸入（包括已排序的陣列）出現最差情況的機率都變得極小。它無法完全消除最差情況，但能確保對於任何輸入，演算法的**期望執行時間**都是 **O(n log n)**。

## 2. 三向切分快速排序 (3-Way Quicksort)

### 核心概念

此優化主要用於解決**存在大量重複元素的陣列**。標準的 Lomuto 分割會將所有等於基準的元素都放在分割點的一側，這會導致遞迴樹變得非常不平衡。

三向切分（也稱為**荷蘭國旗問題 (Dutch National Flag Problem)**）將陣列劃分為**三個**部分，而不是兩個：

> 四段 invariant、`i` 為什麼換 0 前進、換 2 不動的正確性論證，見 [02-Dutch_National_Flag.md](../../Partition/02-Dutch_National_Flag.md)。

- `[start...lt-1]`：所有元素都 **<** 基準值。
- `[lt...gt]`：所有元素都 **==** 基準值。
- `[gt+1...end-1]`：所有元素都 **>** 基準值。

分割完成後，中間等於基準的部分就無需再進行排序，我們只需要遞迴地對小於和大於基準的兩個部分進行排序。

```cpp
void quicksort3Way(vector<int>& nums, int start, int end) {
    if (end - start <= 1) return;

    int pivot = nums[start]; // 以第一個元素為基準
    int lt = start;    // 小於基準區間的右邊界
    int gt = end - 1;  // 大於基準區間的左邊界
    int i = start + 1; // 當前掃描的指標

    while (i <= gt) {
        if (nums[i] < pivot) {
            swap(nums[lt++], nums[i++]);
        } else if (nums[i] > pivot) {
            swap(nums[i], nums[gt--]);
        } else { // nums[i] == pivot
            i++;
        }
    }

    // 現在 [lt...gt] 都是等於基準的元素
    quicksort3Way(nums, start, lt);
    quicksort3Way(nums, gt + 1, end);
}
```

### 複雜度影響

- **時間複雜度**:
  - 在有大量重複鍵的情況下，三向切分能顯著提高效能，因為它一次性將所有與基準相等的元素都排到了正確的最終位置，大大減少了遞迴的規模。
  - 在最差情況下（所有元素都相等），時間複雜度為 **O(n)**。
  - 平均時間複雜度仍然是 **O(n log n)**。

## 3. 三數取中分割 (Median-of-Three Partition)

### 核心概念

這是另一種降低選到極端值作為基準機率的策略。它的作法是：

1. 從陣列的**頭、中、尾**三個位置選取元素。
2. 找出這三個元素的中位數。
3. 將這個中位數與子陣列的最後一個元素交換，然後用它作為基準進行標準的分割。

這個方法比完全隨機化稍微多了一些開銷，但它能更好地避免在一些「看起來有規律」的輸入（如部分排序的資料）上出現最差情況。

### 複雜度影響

- **時間複雜度**: 與隨機化分割類似，它主要目的是讓分割更均衡，從而確保演算法的平均效能維持在 **O(n log n)**，並降低最差情況發生的機率。

## 總結

| 優化策略       | 主要解決的問題         | 核心思想                                         |
| :------------- | :--------------------- | :----------------------------------------------- |
| **隨機化分割** | 已排序或反向排序的輸入 | 隨機選取基準，避免可預測的最差情況。             |
| **三向切分**   | 大量重複元素的輸入     | 將陣列分為 `<`、`==`、`>` 三部分，減少遞迴規模。 |
| **三數取中**   | 「部分有序」等特殊輸入 | 從頭、中、尾選取中位數作為基準，使分割更均衡。   |

在現代的函式庫實作中，通常會結合多種策略，例如 `std::sort` 在底層使用的 **Introsort** 就是一種混合式排序，它以快速排序為主，但會偵測遞迴深度，當深度過深時切換到堆積排序以保證 O(n log n) 的最差情況效能，並在處理小陣列時切換到插入排序。
