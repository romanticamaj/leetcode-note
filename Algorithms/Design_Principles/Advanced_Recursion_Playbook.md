# 進階遞迴設計心法 (Advanced Recursion Playbook)

遞迴是將複雜問題分解為更小、可管理子問題的強大工具。本手冊旨在整理能顯著提升遞迴程式碼品質的設計模式與優化策略。

---

## 階段一：問題建模 (Problem Modeling)

在寫下任何程式碼之前，首要步驟是建立清晰的遞迴模型。

### 1. 尋找遞迴關係式

> **心法：當思路卡關時，回歸數學，寫下遞迴關係式。**

遞迴的本質與數學歸納法緊密相連。透過定義 `F(n)` 為問題在規模 `n` 下的解，並嘗試將其用子問題的解（如 `F(n-1)`, `F(n/2)`）來表示，往往能揭示問題內在的遞迴結構。

- **案例**: LeetCode 95. Unique Binary Search Trees II，其解法正是基於將 `[1...n]` 的問題，分解為以 `i` 為根、`[1...i-1]` 為左子樹、`[i+1...n]` 為右子樹的子問題。

### 2. 遞迴關係式的不同視角

> **心法：同一個問題可以有多種等價的遞迴關係，選擇最直觀或最易實現的一種。**

以 `Pow(x, n)` 為例，存在兩種常見的分治解法：

- **視角一 (後組合)**: 先遞迴計算 `half = myPow(x, n / 2)`，然後再組合結果 `half * half`。這是將工作留給了遞迴的「返回」階段。
- **視角二 (預轉換)**: 先將問題轉換為 `myPow(x * x, n / 2)`，再進行遞迴。這是將工作放在了遞迴的「深入」階段。

理解這兩種視角的差異，有助於更靈活地設計遞迴演算法。

## 階段二：邏輯簡化 (Logic Simplification)

模型建立後，應思考如何讓核心邏輯盡可能純粹。

### 3. 輸入預處理 vs. 輸出後處理

> **心法：優先在入口處轉換輸入來簡化問題，而不是在得到結果後再修飾輸出。**

與其讓遞迴函式內部充滿 `if-else` 來處理多種情況（如正負數），不如設計一個「前處理」入口，將所有情況都轉換為一個標準化的核心問題。

- **案例 (`Pow(x, n)`)**: 在入口處檢查 `n`。若 `n` 為負，立即將問題轉換為求解 `myPow(1/x, -n)`。這樣，核心的 `myPow` 函式就永遠不需要處理負指數，其職責非常單一。

## 階段三：效能優化 (Performance Optimization)

簡潔的邏輯之上，我們可以進一步考慮效能。

### 4. 記憶化 (Memoization)

> **心法：當遞迴中存在大量重疊子問題時，應用記憶化。**

記憶化是一種用空間換取時間的經典技巧，它透過快取子問題的解，來避免重複計算，能將許多指數時間複雜度的演算法優化到多項式時間。

- **策略**:
  1. 建立快取容器（`map` 或 `vector`）。
  2. 遞迴入口處，檢查快取。若命中，直接返回。
  3. 遞迴返回前，將結果存入快取。

### 5. 尾遞迴 (Tail Recursion)

> **心法：當遞迴呼叫是函式最後一個動作時，考慮改寫為尾遞迴以優化空間。**

尾遞迴是一種特殊的遞迴形式，它允許編譯器進行優化，將遞迴轉換為迭代，從而避免了堆疊幀的無限累積。

- **優勢**:
  - **空間優化**: 空間複雜度從 O(n) 降至 O(1)。
  - **防止堆疊溢位**: 即使遞迴深度極大，也不會導致 Stack Overflow。
- **策略**: 將狀態透過函式參數向下傳遞，而不是在遞迴返回後再進行計算。
