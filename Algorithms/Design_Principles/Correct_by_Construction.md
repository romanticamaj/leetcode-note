# 由構造保證正確（Correct by Construction）

> **正確性不要掛在「我會記得」上面，要掛在「結構讓它不可能錯」上面。**

這一篇處理的不是演算法，是**一類 bug 的共同成因**：程式碼是對的，理由也知道，但那個理由**只存在腦子裡**——沒有任何一行程式碼在維持它。於是它每隔一段時間就掉一次，而每次掉都會被自己歸類成「粗心」。

粗心是錯誤的診斷。**同一個地方錯第二次，就不是注意力問題，是結構沒有把理由編進去。**

---

## 🧠 核心判準

寫完一行帶「理由」的程式碼時問自己：

> **如果我三個月後重讀這行、當下沒想到那個理由，我會不會寫錯？**

- **不會** → 理由已經在結構裡了（型別、命名、不變量、預設值幫你扛著）。
- **會** → 這行的正確性掛在記憶上。**去改結構，不要改注意力。**

推論：**「下次小心一點」不是修法。** 它把成本攤到未來每一次重寫，而且利率是複利。

---

## 🧩 三種失效形態與對應的結構手段

| 題 | 掛在記憶上的版本 | 掛在結構上的版本 | 手段 |
| :--- | :--- | :--- | :--- |
| **150** Evaluate RPN | 記得「pop 出來的順序是反的」 | `int rhs = pop(); int lhs = pop();` 之後寫 `lhs - rhs` | **命名**：名字本身就是算式結構，pop 的先後降級成實作細節 |
| **138** Copy List w/ Random Ptr | 記得「`hashmap[nullptr]` 要特判」 | `unordered_map<Node*, Node*>`，`map[nullptr]` 的預設值**剛好**是 `nullptr` | **型別**：讓零值只有一種解釋 |
| **78 / 39** Subsets / Combination Sum | 記得「這裡要傳 `i` 不是 `i + 1`」 | 先寫出不變量（嚴格遞增 / 非遞減），傳什麼由它推出來 | **不變量**：見 [`07-Guards_from_Invariants.md`](../Backtracking/07-Guards_from_Invariants.md) |

三格是同一件事的三種做法。**不變量只是其中一種手段，不是唯一的**——它要求有跨狀態的性質可講；150 沒有狀態，所以「先寫出公式」救不了它，得靠命名。

## 📐 手段目錄

挑手段的順序，大致是從「改動最小」到「改動最大」：

| 手段 | 什麼時候用 | 例子 |
| :--- | :--- | :--- |
| **命名** | 事實是一個**固定映射**，只是容易記反 | `a` / `b` 而非 `x` / `y`、`lo` / `hi` 而非 `i` / `j` |
| **型別 / 預設值** | 特判的存在理由是「零值有歧義」 | `int` 索引 → 指標；`map` 的 value-initialization 剛好是想要的答案 |
| **回傳型別** | 遞迴要靠全域 + guard 才能防止答案被覆蓋 | 236 LCA：`pair<bool,bool>` → `TreeNode*`，全域與 reset 同時消失；見 [`Recursion/05-Recursion_Signature_Contract.md`](Recursion/05-Recursion_Signature_Contract.md) |
| **不變量 + guard** | 有跨迴圈 / 跨遞迴的性質要維持 | `first` 守的是「不重複」，不是「切子問題」 |
| **把中繼資料寫進資料本身** | 兩份資訊必須同步，分開存就會不同步 | [`In_Place_Marking.md`](In_Place_Marking.md)、138 的交錯法 |
| **刪掉那一層** | 兩個結構複合起來等於恆等函數 | 138 的 `cache[hashmap[x]] == map[x]`，中間那個 `int` 純粹是 bug 溫床 |

最後一列值得單獨記：**多一層編碼，就多一個「零值有歧義」的破口**（見 [`CPP_Reference/Container/Operator_Bracket_Behavior_Vector_vs_Map.md`](../../CPP_Reference/Container/Operator_Bracket_Behavior_Vector_vs_Map.md)）。能刪掉的間接層，一定比「小心地維護它」便宜。

## ⚠️ 常見陷阱

- **把重複犯的錯歸類成粗心。** 錯兩次 = 結構問題，去看上面那張表，不要罰自己。
- **寫在紙上但沒進到程式碼的公式。** 白板上推出「top 是右運算元」不等於修好了——**沒有被程式碼結構承載的結論，等於沒有結論。**
- **靠註解維持。** `// 注意順序` 是承認結構沒扛住，而且註解不會在寫錯時報錯。能改命名就別寫註解。
- **只在可交換運算上測試。** `+`、`*` 怎麼放都對，**錯只在 `-`、`/` 上現形**——這是下一節的由來。
