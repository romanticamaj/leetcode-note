# 原地標記：把輸入當作輔助空間（In-Place Marking）

> **原地標記的本質是：每一格要同時存「原值」和「標記」。所以第一個問題永遠是——這一格的表示能力，有沒有多餘的部分可以挖？**

當題目要求 **O(1) 額外空間**，而你的解法又需要一個 `set` / `bool[]` / `hash map` 來記錄「哪些東西被標記過」時，唯一的出路是把那份中繼資料**寫回輸入本身**。

這個手法威力很大，但它引入了一個新問題：同一塊記憶體現在有兩種意義。

> ### ⚠️ **in-place 標記的頭號陷阱：資料區和中繼資料區重疊了。**

所有的 bug 都是這句話的推論——**分不出現在讀到的是原始資料，還是自己剛蓋上去的標記。** 下面兩步（挑載體、三項檢查）做的都是同一件事：把這個重疊處理掉。

---

## 🧠 第一步：挑選標記的載體

不要急著想演算法。先問這一格有沒有**沒被用到的表示能力**：

| 問題 | 若答案為是 → 載體 | 讀回原值的方式 |
| :--- | :--- | :--- |
| 值域**非負**，符號位沒用到？ | **正負號**：`nums[k] = -nums[k]` 表示「k 被標記」 | `abs(nums[k])` |
| 值域**有上界 M**，且加法不溢位？ | **取模編碼**：`nums[k] += M * flag` | 原值 `nums[k] % M`、標記 `nums[k] / M` |
| 值域**恰好等於索引域**？ | **搬到正確位置**：把值 `v` 換到 `nums[v-1]` | 位置本身就是資訊，不需要額外標記 |
| 以上皆否（原值與標記**無法區分**）？ | **犧牲一整條線**（某一列 / 某一行 / 開頭幾格） | 那條線的原始資料必須另外用 flag 保存 |

> **關鍵判準：標記與原值**能不能靠編碼分辨**。**
> - **能**（負數一定是標記、`≥ M` 一定是標記）→ 標記區與資料區**可以重疊**，隨便掃。
> - **不能**（例如用 `0` 當標記，但 `0` 本身也是合法資料）→ **只能靠區域分離**來分辨，於是有了下面的三項檢查。

最後一列的情況最危險，因為它看起來最單純，卻把「分辨」的責任從編碼轉嫁到了**掃描順序**上。

---

## 🧩 第二步：三項安全檢查

只要用了「無法靠編碼分辨」的載體，這三項就必須逐條過：

| # | 檢查 | 沒過會怎樣 | 修法 |
| :--- | :--- | :--- | :--- |
| 1 | **標記區 ∩ 掃描區 = ∅ ？** | 掃描時讀到自己剛寫的標記，誤判成原始資料 | 把掃描範圍縮到標記線之外 |
| 2 | **有沒有哪一格身兼兩職？** | 一次標記動作同時宣告了兩件事 | 把其中一職拉出來用一個 flag 承接 |
| 3 | **消費標記的順序，會不會先毀掉還沒讀的標記？** | 前面的寫入把後面要讀的標記抹掉 | 用遍歷方向化解（通常是倒著走），或把標記線留到最後處理 |

第 3 項可以獨立記成一句話：**寫出去之前，先確認沒有人還要讀它。**

---

## 📐 標準流程

```cpp
// 寫 code 之前先寫這三行
// CARRIER  : 標記存在哪裡（符號 / 取模 / 位置 / 犧牲的那條線）
// DISTINCT : 怎麼分辨「這是原值」還是「這是標記」
// ORDER    : 兩趟的掃描範圍與方向，為什麼不會互相破壞

// Pass 1：只寫標記，絕不把自己寫的標記當成資料讀
// Pass 2：只讀標記並套用，順序保證標記在被用完之前不被覆蓋
// Pass 3（僅「犧牲一條線」需要）：用 flag 還原 / 處理那條線本身
```

「犧牲一條線」的做法**一定是三趟**（或兩趟加尾巴），因為那條線既是標記又是答案的一部分，必須最後才輪到它。少了第三趟就是漏處理。

## 🧩 範例：LC 73. Set Matrix Zeroes

**題目：** 矩陣中若 `matrix[i][j] == 0`，把第 `i` 列與第 `j` 行全部設為 0。要求 O(1) 額外空間。

需要記錄的中繼資料是「哪些列要清零」「哪些行要清零」，自然想到拿**一列**和**一行**來存。但 `0` 既是標記、也是合法的原始資料 → **編碼不可分辨** → 三項檢查全部都要做。

### ❌ 錯誤版本：用最後一列 / 最後一行，且掃描整個矩陣

```cpp
for (int i = 0; i < m; i++)
    for (int j = 0; j < n; j++)
        if (matrix[i][j] == 0) {
            matrix[i][n - 1] = 0;   // row i 的標記
            matrix[m - 1][j] = 0;   // col j 的標記
        }
// 第二趟：if (matrix[i][n-1] == 0 || matrix[m-1][j] == 0) matrix[i][j] = 0;
```

反例 `[[1,1,1],[1,0,1],[1,1,1]]` 會得到全 0 的下半部，正確答案是 `[[1,0,1],[0,0,0],[1,0,1]]`。**原始的 0 在正中央，完全沒碰到最後一列 / 行，照樣錯**——兩項檢查同時沒過：

- **檢查 1 沒過**：迴圈掃到 `(1, n-1)` 時看到的 0 是自己剛寫的標記，卻被當成原始資料，於是又去標記別的東西，**標記像傳染病一樣擴散**。
- **檢查 2 沒過**：角落 `matrix[m-1][n-1]` 同時是「row `m-1` 的標記」和「col `n-1` 的標記」。標記其中一個，另一個被連帶宣告。

### ✅ 正確版本

```cpp
void setZeroes(vector<vector<int>>& matrix) {
    const int m = matrix.size(), n = matrix[0].size();
    // CARRIER  : 第 0 列存「哪些行要清零」、第 0 行存「哪些列要清零」
    // DISTINCT : 0 不可分辨 → 靠區域分離：掃描只走 (1..m-1, 1..n-1)
    // ORDER    : 第二趟由下而上，標記線最後才被覆蓋
    bool firstColZero = false;                        // 檢查 2：角落的第二職拉出來

    for (int i = 0; i < m; i++) {
        if (matrix[i][0] == 0) firstColZero = true;
        for (int j = 1; j < n; j++)                   // 檢查 1：不掃標記行
            if (matrix[i][j] == 0) {
                matrix[i][0] = 0;
                matrix[0][j] = 0;
            }
    }

    for (int i = m - 1; i >= 0; i--) {                // 檢查 3：倒著走
        for (int j = n - 1; j >= 1; j--)
            if (matrix[i][0] == 0 || matrix[0][j] == 0) matrix[i][j] = 0;
        if (firstColZero) matrix[i][0] = 0;           // 標記行最後才覆蓋
    }
}
```

三處修改一一對應三項檢查，沒有一處是試出來的。

> 標記線放在**開頭**或**結尾**都可以（放結尾就改成掃 `(0..m-2, 0..n-2)`、第二趟正著走）。**方向不是重點，「掃描區與標記區不重疊」才是。**

## ⚠️ 常見陷阱

| 陷阱 | 說明 |
| :--- | :--- |
| **重複標記** | 用正負號時，同一格被標記兩次會翻回正數。標記前要先判斷 `if (nums[k] > 0)` |
| **用標記過的值當索引** | `nums[k]` 可能已是負數或已被加上 `M`，拿它當索引前必須先 `abs()` / `% M` 還原 |
| **溢位** | 取模編碼的 `M` 要大於值域上界，且 `原值 + M` 不能超過型別上限 |
| **題目不允許破壞輸入** | 原地標記會改寫輸入。若後續還要用原始資料，必須能完整還原（正負號、取模可以；犧牲一條線不行） |
| **少寫最後一趟** | 「犧牲一條線」時，那條線本身的答案要用 flag 另外處理，漏掉就只錯那一條線，很難從大測資看出來 |

## ⏱️ 複雜度與代價

| | 用額外空間 | 原地標記 |
| :--- | :--- | :--- |
| 時間 | O(mn) | O(mn)（趟數變多，常數略高） |
| 空間 | O(m + n) | **O(1)** |
| 代價 | — | 破壞輸入、可讀性下降、正確性論證變長 |

面試話術：**先寫 O(m+n) 的版本並講清楚**，再說「如果要求 O(1) 額外空間，可以把這兩個陣列吸收進矩陣的第一列和第一行，代價是要處理標記與資料的混疊」。**先講代價再寫**，比直接端出原地版本更能展示判斷力。

## ✅ 檢查清單

> 全部只為了回答一句話：**資料區和中繼資料區有沒有重疊？重疊了要怎麼分辨？**


- [ ] 我要記錄的中繼資料是什麼？原本會用什麼容器裝？
- [ ] 這一格有沒有沒用到的表示能力？（符號 / 值域 / 位置）
- [ ] 標記與原值**能不能靠編碼分辨**？不能的話才需要區域分離
- [ ] 掃描區有沒有蓋到標記區？
- [ ] 有沒有哪一格身兼兩職？（通常是兩條標記線的交點）
- [ ] 第二趟的方向，會不會在標記被讀完之前就覆蓋掉它？
- [ ] 犧牲的那條線本身，有沒有用 flag 補一趟？
