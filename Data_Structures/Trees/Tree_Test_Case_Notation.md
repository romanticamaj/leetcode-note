# 樹結構 Test Case 的高效標記法

在 LeetCode 練習中，為樹結構題目記錄 test case 時，冗長的陣列表示法（如 `[1, 2, 3, null, 4]`）雖然完整，但可讀性差。以下提供幾種更高效、更直觀的標記方式。

---

## 1. 視覺化結構標記法 (Visual Structure Notation)

這種方法最直觀，特別適合在註解中快速理解樹的結構。

**範例**：

```cpp
// Test Case:
//     10
//    /  \
//   5    15
//  / \   / \
// 3   7 13  18
// /   /
// 1   6
```

**優點**：
- 極度直觀，一眼就能看出樹的形狀和父子關係。
- 適合標記不平衡或結構特殊的樹。

**缺點**：
- 書寫稍嫌麻煩，需要對齊。
- 不適合非常大的樹。

---

## 2. 簡化層序遍歷法 (Simplified Level-Order)

這是對 LeetCode 陣列表示法的改良，省略 `null`，並用特殊符號表示空節點。

**範例**：

```cpp
// Test Case: [10, 5, 15, 3, 7, 13, 18, 1, #, 6]
// (# 代表 null)
```

**優點**：
- 比 LeetCode 原生格式更簡潔。
- 仍然保留了層序遍歷的完整資訊。

**缺點**：
- 對於深度的不平衡樹，仍然會有很多 `#`。

---

## 3. 前序/中序遍歷標記法 (Pre-order/In-order Notation)

對於二元搜尋樹 (BST)，使用前序或中序遍歷來記錄更為高效，因為可以唯一確定一棵 BST。

**範例 (BST)**：

```cpp
// Test Case (Pre-order): [10, 5, 3, 1, 7, 6, 15, 13, 18]
// (假設為 BST，此序列可唯一重建樹)
```

**優點**：
- 非常緊湊，特別適合 BST。
- 直接對應到遞迴建構的順序。

**缺點**：
- 對於非 BST，需要同時提供中序遍歷才能唯一確定樹。
- 不如視覺化方法直觀。

---

## 4. 描述性標記法 (Descriptive Notation)

專注於描述 test case 的「類型」而非完整結構，適合用來提醒自己要測試的邊界情況。

**範例**：

```cpp
// Test Case 1: Empty Tree
// Test Case 2: Single Node Tree
// Test Case 3: Perfect Binary Tree (height=3)
// Test Case 4: Right-skewed Tree (5 nodes)
// Test Case 5: Tree with duplicate values (e.g., two nodes with value 5)
```

**優點**：
- 極度簡潔，專注於測試目的。
- 強迫自己思考要測試的邊界條件。

**缺點**：
- 無法還原具體樹結構，需要時仍得手動建構。

---

## ✅ 結論與建議

**這不是必要的**，但強烈建議使用一種高效的方式來記錄。冗長的陣列寫法在 review code 或回顧解法時效率很低。
---

## 5. 面試專用標記法 (Interview-Friendly Notation)

在面試中，時間寶貴，手繪或打字對齊都很耗時。此時，應採用一種能快速溝通、又能精確表達結構的方法。

**核心思想**：使用 **括號表示法 (Parenthetical Notation)** 或 **縮排表示法 (Indented Notation)**。

### 括號表示法

**範例**：

```
// Test Case: 10(5(3(1), 7(6)), 15(13, 18))
```

**解讀**：
- `10` 是根節點。
- `10(...)` 括號內是 `10` 的子節點。
- `5(...)` 和 `15(...)` 是 `10` 的左右子節點。
- `3(1)` 表示 `3` 的左子節點是 `1`。
- `7(6)` 表示 `7` 的左子節點是 `6`。
- `15(13, 18)` 表示 `15` 的左右子節點是 `13` 和 `18`。

**優點**：
- **書寫快速**：單行即可表示，無需對齊。
- **結構清晰**：括號清晰地表達了父子關係和層次。
- **無歧義**：可以精確表示任何二元樹。

### 縮排表示法

**範例**：

```
// Test Case:
// 10
//   5
//     3
//       1
//     7
//       6
//   15
//     13
//     18
```

**優點**：
- **可讀性高**：比括號表示法更接近視覺結構。
- **書寫較快**：只需換行和縮排，比手繪對齊快。

**缺點**：
- 佔用較多行數。

---

## ✅ 面試場景結論與建議

在面試中，**括號表示法** 是最高效且最推薦的方式。它能在最短時間內，無歧義地與面試官溝通你正在思考的樹結構。

**建議流程**：
1.  **口頭描述**：先用「一個根節點是 10，左子樹是...」來溝通。
2.  **快速書寫**：在白板或線上編輯器上，用括號表示法寫下 test case。
3.  **確認**：與面試官確認這個結構是否符合你們的討論。

這樣既節省了時間，又展現了你清晰的邏輯和溝通能力。

**最佳實踐**：

- **在註解中**：使用 **視覺化結構標記法** 或 **描述性標記法**。
- **若需複製貼上**：使用 **簡化層序遍歷法**。
- **對於 BST**：優先考慮 **前序/中序遍歷標記法**。

選擇一種你覺得最舒服、最能幫助你快速回憶起問題情境的標記方式，並保持一致性。
