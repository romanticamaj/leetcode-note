# 遞迴設計心法：萬用邏輯架構與實戰準則

---

## 🧠 遞迴的三大核心心法

### 1. Base Case ≠ 單純停止，而是**含有意義的最小單位**

- Base case 是你要處理的「最小問題」或「終止條件」。
- 它應該具備**明確的結構意義或答案特性**，不是單純為了停止遞迴。
- 在遇到 base case 時，往往已經足以：
  - 給出最終解答的一部分
  - 完成局部操作（例如建立節點、回傳總和、或傳回空容器）

---

### 2. 遞迴的呼叫位置 = **主動操作點**

- 呼叫遞迴不只是丟出去算，而是：
  - **接收回傳值（有意義）**
  - **基於回傳值進行操作**
- 所以在呼叫遞迴那一行，你可以而且應該做：
  - 資料結構的連接或修改
  - 加總、累積、計算邏輯
  - 決策性更新（如記錄最大值、長度、合併）

---

### 3. 回傳值需設計成可串接、可堆疊、可理解

- 所有遞迴層級應保持一致回傳意義與型態。
  - 「可串接」：每一層回傳的值能被上層接住並進一步處理（如合併、加總、建構）。
  - 「可堆疊」：多層遞迴的回傳值能自然堆疊成一個整體（如陣列、樹、字串）。
  - 「可理解」：回傳值的語意清楚，能代表該層遞迴的處理結果。
- 若不回傳任何東西，就應明確設計為 in-place mutation 或副作用模式。
- 為了維持邏輯完整性，非 base case 通常也需：
  - 回傳處理後的狀態（如部分解、結構、節點）
  - 將遞迴的意圖往上傳遞

---

## 🧩 心法速查表

| 編號 | 心法內容                     | 關鍵行為                         |
| ---- | ---------------------------- | -------------------------------- |
| 1    | Base case 有其邊界意義       | 是答案的一部分，而非僅為終止條件 |
| 2    | 呼叫遞迴的位置應做實際操作   | 接回傳值、合併、建構、改寫等     |
| 3    | 回傳值需語意統一、邏輯可串接 | 維持 call stack 邏輯與意圖一致   |

## 🔧 遞迴設計模板

你可以這樣設計一個遞迴函式：

```cpp
ReturnType function(Args...) {
    // 1. Base Case
    if (終止條件)
        return 明確答案或基本結構;

    // 2. Recursive Call + 操作
    auto result1 = function(子問題1);
    // 分開處理: process result1 with current structure;

    auto result2 = function(子問題2);
    // 分開處理: process result2 with current structure;

    auto combined = merge(result1, result2);
    // 合併處理: process combined with current strucuture;

    // 3. 回傳結構
    return 最終結果;
}
```

## 🌳 範例：BST 插入節點（insertIntoBST）

### 問題定義：

給一個 BST 根節點與一個數值 val，插入 val 並回傳插入後的根。

### 應用遞迴心法：

| 步驟 | 實作                                | 原則對應                           |
| ---- | ----------------------------------- | ---------------------------------- |
| 1    | 若 root 為 null，表示已到插入位置   | base case 有意義：要插入節點的位置 |
| 2    | 比較 val 與 root->val，決定往左還右 | 呼叫處即接住、賦值                 |
| 3    | 回傳 root，讓上層維持整體結構不變   | 回傳值統一與串接                   |


## 📘 結語

不論是樹、陣列、字串或動態規劃，遞迴設計的精髓不在「反覆呼叫自己」，而在於：

> **每一層呼叫都要有其意義，每一次回傳都要能被接住並傳遞整體邏輯。**

這三個心法將幫助你建立出可維護、可擴展、可 debug 的遞迴程式架構。
