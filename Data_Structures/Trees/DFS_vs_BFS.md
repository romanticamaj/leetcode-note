# DFS vs BFS 比較

本文件主要比較深度優先搜索（DFS）和廣度優先搜索（BFS）的差異、應用場景和選擇標準。

> 注意：有關 DFS 和 BFS 的詳細介紹，請分別參考 [DFS.md](./DFS.md) 和 [BFS.md](./BFS.md)。

## 何時使用 DFS vs BFS?

何時使用 BFS 與 DFS？

無論你選擇前序、中序還是後序 DFS，重要的是你只需要訪問所有節點。如果你面對的是這類問題，那麼使用 BFS 還是 DFS 都無所謂，因為對每個節點的「訪問」都會存儲足夠的信息，而不受訪問順序的影響。

### 兩者都適用的情況

如果問題只需要遍歷 (visit) 所有節點，而不關心遍歷順序 (e.g., level order)，那麼使用 DFS 或 BFS 都可以。在這種情況下，大多數人會選擇 DFS，因為：

1. DFS 實現起來通常更簡潔（特別是使用遞歸時）
2. DFS 所需的代碼量更少
3. 遞歸 DFS 更容易實現

因此，在二叉樹算法問題中，很少有使用 DFS 比使用 BFS「更好」的問題。然而，實現 DFS 通常更快，因為它需要的代碼更少，如果使用遞歸，實現起來更容易，所以對於 BFS/DFS 無關緊要的問題，大多數人最終會使用 DFS。

### BFS 更適合的情況

另一方面，有相當多的問題使用 BFS 在算法上比使用 DFS 更有意義。通常，這適用於任何我們想要按照節點的層級 (level ordering) 來處理它們的問題。

在以下情況中，BFS 通常是更好的選擇：

1. **按層處理節點**：當問題需要按層級處理節點時，例如層序遍歷
2. **尋找最短路徑**：BFS 總是先訪問距離根節點較近的節點，因此可以找到最短路徑
3. **尋找最接近根節點的特定值**：當目標節點可能在樹的上層時，BFS 可以更快地找到它
4. **樹的寬度很大但深度較小**：BFS 的空間複雜度與樹的最寬層級成正比

### DFS 更適合的情況

在以下情況中，DFS 通常是更好的選擇：

1. **檢查路徑存在性**：DFS 通常更快地找到一條路徑
2. **樹的深度很大但寬度較小**：DFS 的空間複雜度與樹的高度成正比
3. **涉及樹的後序處理**：如計算子樹的某些屬性
4. **實現簡單性優先**：當需要快速解決問題時

## 面試中的常見問題

### DFS 的主要缺點

- 如果目標節點在樹的上層，但 DFS 先遍歷了其他分支，可能會浪費大量時間
- 例如：如果目標節點是根節點的右子節點，但 DFS 先遍歷左子樹，那麼它將遍歷整個左子樹（可能是數十萬甚至數百萬操作）才能找到實際上距離根節點只有一步之遙的目標節點

### BFS 的主要缺點

- 如果目標節點在樹的底層，BFS 需要遍歷所有上層節點才能到達底層
- 對於深度很大的樹，這可能會非常耗時
- BFS 可能需要存儲大量節點（特別是對於寬而淺的樹），導致空間複雜度較高

## 空間複雜度分析

- **DFS 空間複雜度**：O(h)，其中 h 是樹的高度（最大深度）
  - 由於遞歸或棧存儲的是從根到當前節點的路徑
- **BFS 空間複雜度**：O(w)，其中 w 是樹中最寬的層級的節點數
  - 由於隊列存儲的是當前層和下一層的節點

### 不同樹結構下的空間複雜度比較

1. **完美二叉樹 (Perfect Binary Tree)**

   - DFS 空間複雜度：O(log n)，其中 n 是節點總數
   - BFS 空間複雜度：O(n)，因為最底層包含約 n/2 個節點

2. **極度不平衡的樹 (如鏈狀樹)**

   - DFS 空間複雜度：O(n)，因為需要存儲從根到葉的整個路徑
   - BFS 空間複雜度：O(1)，因為每層只有一個節點

## 總結與選擇指南

| 特性           | DFS                             | BFS                         |
| -------------- | ------------------------------- | --------------------------- |
| 適用場景       | 深度很大但寬度較小的樹          | 寬度很大但深度較小的樹      |
| 查找目標值     | 當目標值可能在樹的深處          | 當目標值可能在樹的上層      |
| 路徑查找       | 確定路徑是否存在                | 尋找最短路徑                |
| 實現難度       | 較簡單（特別是 recursive 實現） | 稍複雜（需要使用 queue）    |
| 空間複雜度     | 與樹高度成正比 O(h)             | 與最寬層級節點數成正比 O(w) |
| 代碼量         | 通常較少                        | 通常較多                    |
| 數據結構       | statck（隱式或顯式）            | queue                       |
| 適合的遍歷需求 | 深度優先                        | 層序遍歷                    |

### 最佳實踐建議

1. 如果問題不強調遍歷順序，通常選擇 DFS，特別是用 Recursive
2. 如果問題涉及最短路徑或按層處理，選擇 BFS
3. 根據樹的結構特點選擇：
   - 對於寬而淺的樹，優先考慮 DFS
   - 對於窄而深的樹，優先考慮 BFS
4. 在面試中，如果時間有限，DFS 通常是更快實現的選擇
5. 如果問題需要後序處理（Postorder Traversal，如計算子樹的屬性），選擇 DFS
6. 如果問題需要層級信息 (Level Order)，選擇 BFS
