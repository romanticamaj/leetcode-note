# 心法：將遞迴轉換為迭代

將遞迴演算法轉換為迭代形式是一項基本技能，它不僅能加深對遞迴運作方式的理解，還可以透過避免函式調用堆疊的開銷來提升效能。關鍵在於，我們需要明確地管理那些在遞迴中由調用堆疊隱式處理的狀態。

## 核心原則：模擬調用堆疊 (Call Stack)

一個遞迴函式調用主要做兩件事：

1. **保存狀態**：它將其局部變數和「返回地址」（即調用結束後要從哪裡繼續執行）儲存在調用堆疊上。
2. **轉移控制**：它帶著新的參數跳轉到函式的開頭。

要建立一個迭代版本，我們必須使用一個迴圈和一個顯式的資料結構（通常是 `stack`）來複製這個過程。

### 迴圈不變量 (Loop Invariant) 框架

思考轉換最穩健的方式是透過**迴圈不變量**。這是一個在你的主迴圈每次迭代開始時都必須為真的條件。設計過程如下：

1. **識別狀態**：單次遞迴調用需要哪些關鍵資訊才能完成其工作？這通常包括：

   - 當前的「工作項目」（例如，樹遍歷中的 `TreeNode*`，或陣列中的索引）。
   - 任何其他隨每次遞迴調用而改變的局部變數。

2. **定義狀態表示**：你將如何在迭代版本中儲存這些狀態？

   - 「當前工作項目」通常是一個簡單的變數（如 `TreeNode* current`）。
   - 「父」調用的已保存狀態則儲存在一個顯式的 `stack` 中。堆疊上的每個元素代表一個被暫停的父任務，它正在等待一個子任務完成。

3. **建立迴圈不變量**：定義你的狀態變數在迴圈開始時的意義。例如：

   > 「在每個 `while` 迴圈開始時，`current` 指標代表我們即將要解決的子問題，而 `stack` 則持有我們需要返回的父問題序列。」

4. **設計迴圈主體**：迴圈主體的任務是在維持不變量的前提下取得進展。它模仿遞迴函式的邏輯：
   - **基本案例檢查 (Base Case Check)**：在遞迴中，這通常是 `if (node == nullptr) return;`。在迭代中，這對應於你停止向下走訪並開始從堆疊處理的條件（例如 `if (current == nullptr)`）。
   - **遞迴步驟 (狀態轉換)**：
     - 一個像 `traverse(node->left)` 的遞迴調用，變成了一個像 `current = current->left` 的迭代狀態改變。
     - 在進行這種「向下走訪」之前，如果你需要稍後返回當前狀態（例如，為了處理節點本身或其右子節點），你必須將當前狀態保存在堆疊上。(關鍵步驟！！！)

## 將此框架應用於樹的遍歷

讓我們從這個角度來分析迭代式遍歷。

### 狀態表示

- `TreeNode* current`：當前的子問題（以 `current` 為根的子樹）。
- `stack<TreeNode*> s`：調用堆疊，儲存被暫停的父節點。

### 迴圈不變量

> 在迴圈開始時，我們的目標是遍歷 `current` 所在的子樹。`stack` 中持有我們必須返回的 `current` 的祖先節點。

### 特定遍歷的邏輯 (「處理」步驟的時機)

三種遍歷之間唯一的區別在於**何時「處理」一個節點**（例如，將其值加入結果向量中）。

1. **Preorder (根 -> 左 -> 右)**

   - **邏輯**：在**向下走訪之前**處理。
   - **實作**：
     1. 看到一個節點 (`current != nullptr`)。
     2. **立即處理 `current`**。
     3. 將其存入堆疊（以記住右邊的路徑）。
     4. 向左走訪 (`current = current->left`)。

2. **Inorder (左 -> 根 -> 右)**

   - **邏輯**：在**左邊走訪完成後**，但在**右邊走訪開始前**處理。
   - **實作**：
     1. 看到一個節點 (`current != nullptr`)。
     2. 將其存入堆疊（延遲處理）。
     3. 向左走訪 (`current = current->left`)。
     4. 當走訪到底 (`current == nullptr`)，從堆疊中彈出。
     5. **處理彈出的節點**。
     6. 向右走訪 (`current = popped_node->right`)。

3. **Postorder (左 -> 右 -> 根)**
   - **邏輯**：在**左邊和右邊的走訪都完成後**處理。這需要額外的狀態來區分是從左子節點返回還是右子節點返回。
   - **實作**：
     1. 盡可能向左走訪，將父節點推入堆疊。
     2. 當 current 指標為 nullptr 時，窺視堆疊頂部 (`peek_node`)。
     3. **條件**：我們能處理 `peek_node` 嗎？只有當它的右子節點為 null 或其右子節點已被訪問過時才可以。
     4. 如果我們**不能**處理它，我們必須先處理右子樹。`current = peek_node->right`。
     5. 如果我們**可以**處理它，**處理 `peek_node`**，將其彈出，並將其記錄為 `lastVisited`。將 `current` 設為 `nullptr` 以強制迴圈透過窺視新的堆疊頂部來繼續，有效地「向上返回」。

## 通用轉換步驟

1. **函式簽名**：函式簽名保持不變。
2. **狀態**：識別遞迴調用的參數（例如 `TreeNode* node`）。這成為你的主要迭代變數 (`current`)。建立一個顯式的 `stack` 來持有這些狀態的實例。
3. **迴圈**：建立一個 `while` 迴圈，只要還有工作要做就繼續（例如 `while (current || !stack.empty())`）。
4. **「向下走訪」邏輯**：迴圈的第一部分應處理「向下走訪」或移動到下一個子問題，模仿主要的遞迴調用（例如 `向左走`）。在你向下走訪之前，如果需要返回，就將狀態推入堆疊。
5. **「向上返回」邏輯**：`else` 區塊（或等效邏輯）處理從遞迴調用「返回」的情況。這涉及從堆疊中彈出以恢復父節點的狀態。
6. **處理時機**：將你的核心「處理」邏輯放在迴圈內的正確位置，以匹配遞迴的順序（走訪前、走訪之間或兩者之後）。
7. **額外狀態**：對於像 postorder 這樣的複雜模式，你可能需要一個額外的變數（`lastVisited`）來追蹤更詳細的狀態，這些狀態在遞迴中由調用堆疊的結構隱式處理。
