# 心法：原地陣列操作的「向後填充」模式 (In-Place Array Manipulation with Backward Fill)

在處理需要「原地 (in-place)」修改陣列，特別是涉及元素**擴展**（如複製）或**收縮**（如刪除）的問題時，一個非常強大且優雅的模式是「向後填充」。這種方法的核心在於避免在遍歷過程中覆蓋尚未處理的數據。

這個模式可以被拆解為一個清晰的三部曲。

---

## 1. 第一步：預計算，確定「最終邊界」

在接觸陣列並進行任何修改之前，首先要通過一次遍歷來**預測操作完成後的最終狀態**。

- **目標**: 確定修改後，原數組的哪些元素會被保留，以及最終的有效長度是多少。
- **方法**: 通常使用雙指針或計數器來模擬擴展或收縮過程。
  - 對於擴展問題（如 LeetCode 1089. Duplicate Zeros），一個指針遍歷原數組，另一個計數器或指針計算擴展後所需的總長度。
  - 對於收縮問題（如 LeetCode 27. Remove Element），一個快指針尋找有效元素，一個慢指針記錄有效元素的最終位置。
- **產出**: 得到最終有效部分的結尾索引 `last` 或 `end`。

> **心法口條**: 「先算新長度，再決定能走到哪裡。」

---

## 2. 第二步：處理邊界，隔離「特殊情況」

在第一步的預計算過程中，我們經常會遇到邊界上的特殊情況。最明智的做法是在這一階段就將其處理掉，以確保後續的回填邏輯是乾淨、統一的。

- **常見情境**:
  - 在擴展問題中，最後一個被保留的元素可能無法「完全擴展」（例如，`Duplicate Zeros` 中，如果最後一個有效元素是 `0`，但其後沒有空間再複製一個 `0`）。
  - 在收縮問題中，可能需要處理邊界條件或空數組。
- **策略**: 在計算最終邊界的遍歷過程中，一旦識別出這種邊界情況，就立即對其進行預處理或標記。

> **心法口條**: 「把麻煩的 edge case 在前向遍歷 (forward pass) 時解決掉，確保後向遍歷 (backward pass) 變成純粹的數據搬運。」

---

## 3. 第三步：向後填充 (Backward Fill)

這是該模式的核心。我們從計算出的「最終邊界」和原始數據的有效邊界開始，**同時從右向左**遍歷，將元素放置到它們在修改後陣列中的最終位置。

- **為什麼要從後往前？**
  - 因為這樣可以保證我們寫入的位置 `arr[k]` 總是在我們正在讀取的位置 `arr[i]` 的**右邊或同一位置** (`k >= i`)。這就完美地避免了覆蓋尚未被處理的原始數據。
- **指針設置**:
  - 一個寫指針 `k`，從陣列的物理末端或計算出的新末端開始，向左移動。
  - 一個讀指針 `i`，從原始數據的有效末端開始，向左移動。
- **常見應用**:
  - **LeetCode 1089. Duplicate Zeros**: 遇到 `0`，在 `k` 和 `k-1` 的位置都寫入 `0`。
  - **LeetCode 88. Merge Sorted Array**: 從兩個數組的末尾比較元素，將較大者放入目標數組的末尾。
  - **Cracking the Coding Interview "URLify"**: 將空格替換為 `%20`。由於是擴展操作，從後往前填可以避免覆蓋。

> **心法口條**: 「倒著填，才能避免踩到自己。」

---

## 模式總結：三部曲口訣

1. **算長度 → 找新邊界**
2. **清邊界 → 處理 edge case**
3. **倒著填 → 不覆蓋未處理值**

> **一句話心法**: 「遇到 in-place 陣列擴展或收縮時，先用一次遍歷計算出最終長度和邊界，順便處理掉邊界的特殊情況，最後再從尾巴倒著填，保證操作的原子性和正確性。」
