# 數組問題解題策略

本文件提供常見數組問題的解題策略，幫助識別問題特徵並選擇合適的算法技巧。

## 快速查找與檢查

### 使用 Hash Map/Set 優化查找

當你的算法需要頻繁檢查一個元素是否存在於集合中時 (例如，常出現 `if ... in ...`)，考慮使用哈希表：

- 將線性查找（O(n)）優化為常數時間查找（O(1)）
- 特別適用於需要頻繁檢查元素存在性、查找配對元素或統計頻率的問題
- 詳細信息請參見 [Hash Tables 文檔](../../Data_Structures/Hash_Tables/README.md)

## Subarray vs Subsequence

### 關鍵差異

- **Subarray/Substring**：數組/字符串中連續的元素序列
- **Subsequence**：數組/字符串中保持相對順序但不需要連續的元素集合

### 算法選擇

- **Subarray/Substring 問題**：
  - 通常可以使用 **Sliding Window** 或 **Prefix Sum** 解決
  - 這些技術專門處理連續元素序列

- **Subsequence 問題**：
  - 最常見的解決方案是使用 **Two Pointers**，特別是當給定兩個輸入數組/字符串時
  - 由於 **Prefix Sum** 和 **Sliding Window** 代表連續的子數組/子字符串，它們在處理非連續的子序列時不適用

## Sliding Window vs Prefix Sum

### Sliding Window 適用場景

如果問題具有以下明確約束：

- 和大於或小於 k
- 對內容的限制，例如最多 k 個不同元素或不允許重複

以及/或者要求：

- 最小或最大長度
- 子數組/子字符串的數量
- 最大或最小和

考慮使用 **Sliding Window**。

> 注意：並非所有具有這些特徵的問題都應該用滑動窗口解決，也並非所有滑動窗口問題都具有這些特徵。這些特徵僅作為一般指導原則。

### Prefix Sum 適用場景

如果問題的輸入是整數數組，並且你發現需要計算多個子數組的和，考慮建立 **Prefix Sum**。

### 技術比較

**Sliding Window** 是一種在線性時間內解決子數組/子字符串問題的技術，通過維護一個「窗口」並根據條件擴展或縮小來避免重複計算。

**Prefix Sum** 是一種預處理技術，建立成本為 O(n)，但允許所有後續的子數組和查詢在 O(1) 時間內完成，因此通常可以將算法的時間複雜度提高 O(n) 倍。
