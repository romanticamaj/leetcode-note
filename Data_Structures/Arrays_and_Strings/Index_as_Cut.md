# 用切點設計子問題（Index as Cut）心法

字串／陣列的狀態設計，可以先問：**我在求「這一段」的答案，還是「必須使用這個元素」的答案？**
前者適合先試切點，後者適合先試元素 index。先決定子問題的意思，再決定如何編號。

這個表示法適用於 array、string 等序列，不限於 DP。當提問是「前半段是否合法、是否需要處理」，思考單位是**一段範圍**，空段也應納入表示；`[0,i)` 讓 `i = 0` 自然表示空的前半段，`i` 同時就是該段的元素數量。至於空段是否合法、是否需要處理，仍由問題語意決定。若提問是「當前元素的值是多少、與另一個值如何比較」，才需要定位實際元素，並確認該側有元素可讀。

## 🧠 從「這一段」開始問

1. **這一段的答案是什麼？** 是長度、可行性、方法數，還是最小成本？
2. **用哪兩個邊界描述這一段？** 例如前綴 `[0,i)`、剩餘 `[i,n)`、區間 `[l,r)`。
3. **這一段為空時，答案是什麼？** 讓空範圍成為合法子問題，推導 base case。
4. **拿掉邊界元素或切成更小的段，答案如何連結？** 據此設計 recurrence。

切點只解決「範圍如何表示」；若答案還依賴額度、前一次選擇等資訊，狀態仍須包含它們。

## 切點是縫，元素 index 是位置

長度為 n 的序列，有 n 個元素、n+1 個切點：

```text
元素：    a   b   c
切點：  0   1   2   3
```

切點 i 將序列分成 `[0,i)` 與 `[i,n)`。半開區間 `[l,r)` 包含滿足 `l <= index < r` 的元素，長度為 `r-l`。

| 範圍 | 內容 | 長度 |
| --- | --- | --- |
| `[0,0)` | 空範圍，沒有任何 index 滿足 `0 <= index < 0` | 0 |
| `[0,1)` | 第一個元素 | 1 |
| `[0,n)` | 整個序列 | n |
| `[n,n)` | 空的剩餘 | 0 |

**左右界相等，代表空範圍，不是錯誤區間。** `i == n` 是合法切點，但不能因此讀取 `s[n]` 作為序列元素。

## 🧩 比較設計：前綴答案 vs 指定末元素

| 設計 | 狀態意義 | 是否必須使用最後一個元素？ | 空範圍 |
| --- | --- | --- | --- |
| 切點前綴 `F(i)` | `[0,i)` 這一段的答案 | 由問題決定，不因編號而強制使用 | `F(0)` 可直接表示 |
| 元素結尾 `G(k)` | 必須以 `s[k]` 結尾的答案 | 是 | 沒有可指定的末元素，需另定義 |

這不只是差一格：**「前綴內的最佳答案」與「必須以末元素結尾的最佳答案」是不同子問題。**
前綴最佳答案可能跳過最後一個元素；指定結尾的答案則不能。
把 `G(k)` 改名為 `G(i-1)` 不會自動改變其語意。

口訣：**問這一段，先試切點；問必須選誰，先試元素 index。**

## 空範圍的答案，決定 base case

先用問題語意求答案，再填初始值；不要因為多開一列，就習慣性全部填 0。

| 子問題語意 | 空範圍可能的答案 | 理由 |
| --- | --- | --- |
| 兩段的共同子序列長度 | 任一段為空時為 0 | 沒有共同元素可選 |
| 空序列轉成另一段的編輯成本 | 另一段的長度（單位插入成本） | 必須逐一插入 |
| 完成空目標的方法數 | 常為 1，視選擇規則而定 | 不選任何東西也算一種完成方式 |
| 必須選至少一個元素的最大值 | 無效狀態，例如負無限大 | 不能讓空選擇參與最大值比較 |

雙序列 prefix 狀態若定義在切點上，完整表通常為 `(m+1) × (n+1)`。
第零列、欄表示一側為空；**不代表整列、整欄的值一定相同**。
若空狀態在遞迴入口直接回傳，memo 不一定需要配置該列／欄；空間壓縮也可減少實際儲存量。

## Prefix／Suffix 與 Top-down／Bottom-up 分開選

**Prefix／suffix 決定子問題代表哪一段；top-down／bottom-up 決定計算方式。** 兩者沒有固定綁定。

| 狀態表示 | 合法切點 | 空狀態 | 相鄰字元與更小範圍 |
| --- | --- | --- | --- |
| Prefix `[0,i)` | `0…n` | `i == 0` | `i > 0` 才讀 `s[i-1]`，去掉末字元得 `[0,i-1)` |
| Suffix `[i,n)` | `0…n` | `i == n` | `i < n` 才讀 `s[i]`，去掉首字元得 `[i+1,n)` |

- **Top-down**：從所求狀態出發，遞迴求依賴的子問題，空狀態可直接回傳。
- **Bottom-up**：先設好 base case，再按依賴順序填表；prefix 常由小到大，suffix 常由大到小。

例如 prefix 的 `i == 0` 與 suffix 的 `i == n`，都可能代表空字串，只是看切點的不同一側。
狀態有 `0…n` 共 n+1 種值，也不代表需要讀取 n+1 個字元，或每個狀態都必須實際走訪。

## ⚠️ Base case 與讀取守衛不要混

- **Base case** 問：「這個子問題是否已有直接答案？」空範圍是合法狀態。
- **讀取守衛** 問：「現在是否真的有這個元素可讀？」例如讀 `s[i]` 前確認 `i < n`。
- **計算順序** 問：「這個狀態依賴的答案是否已完成？」不能只看 index 的增減決定。

**狀態看切點，取字元才看 index；邊界由子問題語意決定。**

## ✅ 設計檢查

- [ ] 能用一句話說明這一段求的是什麼，不只寫 `dp[i]`。
- [ ] 分清楚「截至這裡」與「答案必須在這裡結尾」。
- [ ] 明確寫出 `[0,i)`、`[i,n)` 或 `[l,r)`，以及切點的合法範圍。
- [ ] 能解釋空範圍的答案，而不是背初始值。
- [ ] 元素存取有守衛，轉移維持狀態語意並指向更小的子問題。
