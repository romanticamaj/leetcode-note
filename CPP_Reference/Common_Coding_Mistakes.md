# C++ 常見編程錯誤與心法

本文件旨在記錄 C++ 編程中常見的錯誤類型與解決心法，幫助開發者建立更穩固的程式碼品質。

## 邏輯與演算法錯誤

### 遞迴函數名稱錯誤

- **問題**：在遞迴呼叫時，因大小寫或拼寫錯誤使用了不正確的函數名稱。
- **心法**：定義函數後，直接**複製函數名稱**進行遞迴呼叫，並保持一致的命名風格。

### 索引計算錯誤

- **問題**：在二分搜尋等演算法中，使用 `(left + right) / 2` 計算中間點，可能因 `left` 和 `right` 過大而導致整數溢位。
- **心法**：永遠使用 `left + (right - left) / 2` 的形式，此寫法在數學上等價且能有效**避免溢位**。

## 記憶體與資料管理錯誤

### 陣列越界存取

- **問題**：使用 `<=` 作為 `for` 迴圈的邊界條件，導致存取到陣列的 `size()` 位置，引發未定義行為。
- **心法**：迴圈條件堅持使用 `<`；優先考慮使用**範圍-based for 迴圈**，從語法層面消除越界可能。

### 未初始化變數

- **問題**：使用未經初始化的區域變數，其值是不確定的，會導致非預期的程式行為。
- **心法**：堅持**在宣告變數時立即初始化**，例如 `int sum = 0;`。

### 智能指標與原始指標轉換錯誤

- **問題**：在需要傳遞原始指標 (`Raw Pointer`, e.g., `Node*`) 的地方，直接傳遞了智能指標物件 (`Smart Pointer`, e.g., `std::unique_ptr<Node>`)，或者忘記使用 `.get()` 方法來提取其管理的原始指標。這會導致編譯錯誤，因為兩者型別不相容。
- **心法**：明確記住智能指標是一個**物件**，它**管理**著一個原始指標。當需要與接受原始指標的 C-style API 或舊函式互動時，必須使用 `.get()` 方法來取得被管理的指標。

**範例：**

```cpp
void processNode(ListNode* node) {
    // ...
}

auto dummy = std::make_unique<ListNode>();

// ❌ 錯誤：型別不匹配 (unique_ptr vs ListNode*)
// processNode(dummy);

// ✅ 正確：使用 .get() 提取原始指標
processNode(dummy.get());
```

## 資料結構操作心法

### 成對操作原則 (Add/Delete Pairing)

- **問題**：在遞迴（特別是 DFS）或狀態模擬中，向容器（如 `path` 向量）加入元素後，忘記在回溯時將其移除。
- **心法**：將 `push_back()` 和 `pop_back()` 視為一個**成對操作**。在遞迴呼叫之後，立即執行對應的清理操作，確保每一層的狀態都是乾淨的。

### 資料交互原則 (Value vs. Reference)

- **問題**：在處理樹或圖的節點時，將整個 `Node*` 物件指標存入結果容器，而非其值 `node->val`。
- **心法**：明確區分「過程容器」與「結果容器」。結果容器應只儲存題目要求的**最終值**（如 `int`, `string`），而非中間過程使用的複雜物件或指標，除非題目有特殊要求。

### Container 型別轉換不匹配

- **問題**：Container 間的型別轉換不匹配，通常發生在建構回傳值時，沒有用正確的 `value` 或是直接對 container 操作，導致編譯錯誤或非預期行為。
- **心法**：使用 `std::transform` 或範圍-based for 迴圈來逐一轉換元素。明確地從來源容器中提取所需的值（如 `node->val`），並將其插入目標容器。這確保了型別安全，也讓程式碼意圖更清晰。參見 [Container Conversion Techniques](Container/Container_Conversion_Techniques.md)。

## C++ 型別系統陷阱

### 型別不匹配與隱式轉換

- **問題**：混合使用 `int`、`unsigned int`、`long long` 等不同型別進行運算，或在 `vector.size()`（回傳 `size_t`，為無符號型別）與 `int` 之間進行比較，可能因隱式型別轉換規則導致非預期的結果（例如，`-1` 被轉為一個巨大的正整數）。
- **心法**：
  - 盡量**保持型別一致**，特別是在比較和算術運算中。
  - 在可能產生負數的場景，避免與 `size_t` 直接比較，可先將 `size()` 的結果強制轉型為 `int`。
  - 啟用編譯器警告 (`-Wconversion`, `-Wsign-compare`) 來幫助發現潛在的型別問題。

### 括號優先順序錯誤導致的除法錯誤

在使用 `+ - * /` 等運算時，常見錯誤是忽略括號的優先順序，導致整數除法結果錯誤。

#### 常見錯誤範例：取 ceiling 的 trick

```cpp
int ceil_div = x + divisor - 1 / divisor; // ❌ 錯誤：只有 1 被除以 divisor
```

上面這行實際執行的是：

```cpp
int ceil_div = x + (divisor - (1 / divisor)); // 優先順序錯誤
```

#### 正確寫法

```cpp
int ceil_div = (x + divisor - 1) / divisor; // ✅ 正確：整體加總後再除
```

#### 建議

- **務必加上括號**，確保加法與減法先執行，再進行除法
- 尤其在使用 ceiling trick `(x + d - 1) / d` 時，括號不可省略
- 可考慮將這類表達式封裝成 utility function 增加可讀性與安全性
