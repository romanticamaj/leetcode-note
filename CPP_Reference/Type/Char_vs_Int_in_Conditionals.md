# C++ 型別陷阱：字元 vs. 整數在條件判斷中的差異

在 C++ 中，一個微小但極其常見的錯誤來源，是在條件判斷中混淆字元 (character) 與整數 (integer) 的字面量。

## 核心問題：`'0'` 不等於 `0`

- **`'0'` (字元 '0')**: 這是一個 `char` 型別的字面量。在記憶體中，它儲存的是其對應的 **ASCII 值**，也就是 **48**。
- **`0` (整數 0)**: 這是一個 `int` 型別的字面量，其值就是數學上的零。

## 導致的後果

由於 C++ 的布林求值機制會將任何**非零值**視為 `true`，將**零值**視為 `false`，因此：

- `if ('0')` 這個條件判斷會被求值為 `if (48)`，因為 48 非零，所以條件永遠為 `true`。
- `if (0)` 這個條件判斷則永遠為 `false`。

```cpp
if ('0') {
    // 這個區塊永遠會執行
}

if (0) {
    // 這個區塊永遠不會執行
}
```

### 特殊情況：空字元 `'\0'`

值得注意的是，空字元 (null character) `'\0'` 的 ASCII 值恰好是 0。因此，`if ('\0')` 的行為與 `if (0)` 相同，條件會被求值為 `false`。

```cpp
if ('\0') {
    // 這個區塊永遠不會執行
}
```

## 最佳實踐與心法

為了避免這種混淆導致的邏輯錯誤，請遵循以下原則：

- **永不直接在布林條件中使用 `char`**，除非你的意圖是明確檢查它是否為空字元 `'\0'`。
- **永遠進行明確的比較**。

```cpp
char c = '0';

// 錯誤的檢查方式
if (c) { /* ... */ } // 邏輯上是問 "c 是否為空字元？"，而不是 "c 是否為 '0'？"

// 正確的檢查方式
if (c == '0') { /* ... */ }   // 檢查 c 是否等於字元 '0'
if (c != '\0') { /* ... */ }  // 檢查 c 是否為非空字元
```

## 總結對照表

| 表達式 | 求值結果 | 意義                  |
| :----- | :------- | :-------------------- |
| `'0'`  | `true`   | ASCII 值為 48 (非零)  |
| `'\0'` | `false`  | ASCII 值為 0 (空字元) |
| `0`    | `false`  | 整數零                |

這個看似微小的區別，在處理字元陣列、解析輸入或任何涉及字元與布林邏輯交互的場景中，都是保證程式正確性的關鍵。
