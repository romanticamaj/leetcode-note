### 時間複雜度分析的重要性

時間複雜度分析是解題過程中的關鍵步驟，尤其在面試情境中更為重要：

1. **驗證解法效率**：確保你的解法能在給定的時間限制內執行完成
2. **比較不同解法**：幫助選擇最優的解決方案
3. **展示分析能力**：向面試官展示你對算法效率的理解和分析能力
4. **避免超時錯誤**：在實際提交代碼時避免 Time Limit Exceeded (TLE) 錯誤

### 常見時間複雜度

| 複雜度     | 名稱         | 10 個元素 | 100 個元素 | 1000 個元素 | 特點                   |
| ---------- | ------------ | --------- | ---------- | ----------- | ---------------------- |
| O(1)       | 常數時間     | 1         | 1          | 1           | 與輸入大小無關         |
| O(log n)   | 對數時間     | ~3        | ~7         | ~10         | 每次迭代將問題規模減半 |
| O(n)       | 線性時間     | 10        | 100        | 1000        | 與輸入大小成正比       |
| O(n log n) | 線性對數時間 | ~30       | ~700       | ~10000      | 常見於高效排序算法     |
| O(n²)      | 平方時間     | 100       | 10000      | 1000000     | 嵌套循環               |
| O(2ⁿ)      | 指數時間     | 1024      | 10^30      | 10^301      | 通常需要優化或剪枝     |
| O(n!)      | 階乘時間     | 3628800   | 10^158     | 無法計算    | 生成所有排列           |

### 空間複雜度考量

- **輔助空間**：算法執行過程中使用的額外空間
- **輸入空間**：存儲輸入數據所需的空間
- **總空間複雜度**：輔助空間 + 輸入空間

### 分析技巧

1. **識別主要操作**：找出算法中的主要操作，計算其執行次數
2. **識別循環結構**：分析循環的次數和嵌套層級
3. **遞歸分析 (Recursive Analysis)**：使用遞歸樹 (Recursion Tree) 或主定理 (Master Theorem) 分析遞歸算法
4. **均攤分析 (Amortized Analysis)**：考慮操作的平均成本，而非最壞情況

### 常見錯誤

1. **忽略常數因子**：雖然漸進分析忽略常數，但在實際應用中可能很重要
2. **忽略空間複雜度**：只關注時間而忽略空間需求
3. **錯誤識別主導項**：在複合表達式中錯誤識別增長最快的項
4. **忽略特殊情況**：未考慮輸入特性對複雜度的影響

### 面試中的溝通

1. **先給出結論**：先明確說明時間和空間複雜度
2. **解釋分析過程**：簡要說明如何得出該複雜度
3. **討論優化可能**：提出可能的優化方向和權衡
4. **誠實表達**：如果不確定，誠實表達並嘗試推導，而非猜測

## 優化心法

### 建構與操作同步進行 (aka `邊建構，邊操作`)

一個超級重要的心法：通常在建構一些 additional space 的過程中，例如建構 **Prefix Sum** 或是 **HashMap**，就很有可能可以同時用它來做一些比較。

不需要"先建構"，再操作，可以 "邊建構，邊操作"。

這種方法可以：

- 減少代碼的複雜性
- 優化時間複雜度（通常可以將兩次遍歷合併為一次）
- 在某些情況下提前找到答案，避免不必要的計算

## 問題模式識別

### 常見問題類型與對應技巧

- **Subarray 問題**：當遇到子數組相關問題時，應該考慮使用 **Prefix Sum** 或 **Sliding Window** 技巧
  - Prefix Sum 適合需要快速計算任意子數組和的問題
  - Sliding Window 適合尋找滿足特定條件的連續子數組 (`連續`很重要)

## 使用不同的視角切入題目

有時候，重新表述或轉換問題的角度可以讓難題變得更容易解決。通過改變我們看待問題的方式，可以發現更直接的解決方案。

### 例子

**原始問題**：

```
You are given a binary string s (a string containing only "0" and "1").
You may choose up to one "0" and flip it to a "1".
What is the length of the longest substring achievable that contains only "1"?

For example, given s = "1101100111", the answer is 5.
If you perform the flip at index 2, the string becomes 1111100111.
```

**轉換視角**：
此問題可轉成 `what is the longest substring that contains at most one "0"?"`

通過這種轉換，我們可以使用 **Sliding Window** 技術來解決問題，維護一個最多包含一個"0"的窗口，並找出最長的這樣的窗口。

## 練習心法：設計 Test Case 很重要！！！

解題時遵循結構化的思考過程可以幫助我們更系統地解決問題，而設計良好的測試用例是確保解決方案正確性的關鍵。

### 思路步驟

1. **OBSERVATION**

   - 仔細觀察問題，理解問題的本質和特點
   - 尋找問題中的模式、規律或特殊情況
   - 注意回傳值的定義

2. **BRUTE FORCE + 時間分析**

   - 首先考慮最直接的解決方案
   - 分析暴力解法的時間和空間複雜度
   - 識別可能的瓶頸和優化機會

3. **使用技巧優化, 指出實作重點**

   - 應用適當的算法技巧（如 **Sliding Window**、**Prefix Sum**、**Two Pointers** 等）來優化解決方案
   - 強調實現中的關鍵點和潛在的陷阱
   - 考慮邊界情況和特殊輸入

4. **使用 test case 確認**
   - **TEST CASE 是你的守護神**
   - 設計多樣化的測試用例，包括：
     - 基本/簡單情況
     - 邊界情況（空輸入、最小/最大值等）
     - 特殊情況（重複元素、排序/未排序等）
   - 使用測試用例驗證解決方案的正確性
   - 通過測試用例找出並修復潛在問題

## 解題前的關鍵假設檢查

在開始解題之前，檢查和理解題目的隱含假設是非常重要的。忽略這些假設可能導致解法錯誤或不必要的複雜性。

### 1. 輸入數據特性假設

**問題描述**：許多算法題目對輸入數據有隱含假設，但這些假設可能沒有明確說明。

**需要考慮的關鍵假設**：

- 輸入是否包含重複元素（distinct vs. duplicate）
- 輸入是否已排序
- 輸入是否可能為空
- 輸入數據的範圍（可能影響溢出處理）
- 輸入是否包含負數（對於某些算法很重要）

**錯誤示例**：

```cpp
// 錯誤示例 - 假設輸入沒有重複元素
vector<int> nums = {1, 2, 2, 3, 4};
unordered_set<int> numSet(nums.begin(), nums.end());
if (numSet.size() != nums.size()) {
    // 這個條件會為真，因為有重複元素
    // 但如果算法假設輸入沒有重複，可能會導致錯誤
}
```

**正確示例**：

```cpp
// 正確示例 - 明確檢查重複元素
vector<int> nums = {1, 2, 2, 3, 4};
unordered_set<int> numSet;
bool hasDuplicates = false;
for (int num : nums) {
    if (!numSet.insert(num).second) {
        hasDuplicates = true;
        break;
    }
}
// 根據是否有重複元素選擇不同的算法
```

**避免方法**：

1. 仔細閱讀題目，識別明確和隱含的假設
2. 考慮極端情況和邊界條件
3. 在代碼中添加檢查，驗證關鍵假設
4. 如果假設不明確，考慮多種可能性或在解題前澄清

### 2. 其他常見假設

- **數據結構特性**：例如，二叉樹是否平衡，圖是否有環
- **操作限制**：是否有時間或空間複雜度要求
- **返回值要求**：返回實際值還是索引，多解時返回任意解還是特定解
- **修改輸入**：是否允許修改原始輸入數據

在解題過程中，明確這些假設可以幫助你選擇正確的算法和數據結構，避免不必要的錯誤和優化。

## ✅ 解題心法：避免「單一範例陷阱」

在解題時，一個常見的錯誤是看到題目給定的一個範例滿足某個特定條件，就立刻跳進去，假設所有情況都滿足該條件，從而設計出一個過於狹隘或完全錯誤的解法。

**核心思想**：**不要讓單一範例限制你的思路。**

### 如何避免這個陷阱？

1. **質疑範例**：

   - 問自己：「這個範例有什麼特殊之處？它是否代表了所有可能的輸入？」
   - 「如果換一個範例，這個條件還成立嗎？」

2. **主動構造反例**：

   - 在開始寫程式碼前，花一兩分鐘，嘗試構造一個不滿足該條件的 test case。
   - 例如，如果範例中的陣列是排序好的，嘗試一個未排序的陣列。如果範例中的樹是平衡的，嘗試一個偏斜的樹。

3. **回歸問題本質**：
   - 重新閱讀題目，找出「保證成立」的條件，而不是從範例中「推斷」條件。
   - 專注於問題的約束（constraints），而不是範例的特性。

### 範例情境：

- **題目**：給定一個陣列，找出...
- **範例**：`[1, 2, 3, 4, 5]`
- **陷阱**：看到範例是排序好的，就直接使用二分搜尋或雙指針。
- **正確心法**：先檢查題目是否保證輸入陣列已排序。如果沒有，就不能假設這個條件成立，需要考慮排序或使用其他方法。

### 結論

一個好的解法應該是**通用**的，能夠處理所有符合題目約束的輸入，而不僅僅是給定的那幾個範例。在動手寫程式碼前，花時間思考和驗證你的假設，是提升解題成功率的關鍵一步。
