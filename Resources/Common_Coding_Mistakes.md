# 常見編程錯誤記錄

這個文件用於記錄編程過程中常見的錯誤，以便日後參考和避免。

## 函數和遞歸相關錯誤

### 1. 遞歸函數名稱錯誤

**問題描述**：在編寫遞歸函數時，調用自身時使用了錯誤的函數名稱。

**錯誤示例**：
```cpp
// 錯誤示例
void dfs(TreeNode* node) {
    if (!node) return;
    
    // 處理當前節點
    cout << node->val << " ";
    
    // 遞歸調用 - 錯誤的函數名稱
    DFS(node->left);  // 大小寫錯誤
    dFs(node->right); // 大小寫錯誤
}
```

**正確示例**：
```cpp
// 正確示例
void dfs(TreeNode* node) {
    if (!node) return;
    
    // 處理當前節點
    cout << node->val << " ";
    
    // 遞歸調用 - 正確的函數名稱
    dfs(node->left);  // 正確複製函數名稱
    dfs(node->right); // 正確複製函數名稱
}
```

**避免方法**：
1. 使用 IDE 的自動完成功能
2. 定義函數後，複製函數名稱而不是重新輸入
3. 使用一致的命名規範（如全部小寫或駝峰式命名）
4. 代碼審查時特別注意函數名稱的一致性

### 2. 遞歸基本情況遺漏

**問題描述**：忘記處理遞歸的基本情況（終止條件），導致無限遞歸和棧溢出。

**錯誤示例**：
```cpp
// 錯誤示例 - 缺少基本情況
int factorial(int n) {
    return n * factorial(n - 1);  // 無終止條件
}
```

**正確示例**：
```cpp
// 正確示例
int factorial(int n) {
    if (n <= 1) return 1;  // 基本情況
    return n * factorial(n - 1);
}
```

**避免方法**：
1. 始終先考慮並處理基本情況
2. 確保基本情況能夠覆蓋所有可能的終止條件
3. 考慮邊界情況和特殊輸入

## 數組和索引相關錯誤

### 1. 數組越界訪問

**問題描述**：訪問數組範圍之外的元素。

**錯誤示例**：
```cpp
// 錯誤示例
vector<int> nums = {1, 2, 3};
for (int i = 0; i <= nums.size(); i++) {  // 使用 <= 而不是 <
    cout << nums[i] << " ";  // 當 i = 3 時越界
}
```

**正確示例**：
```cpp
// 正確示例
vector<int> nums = {1, 2, 3};
for (int i = 0; i < nums.size(); i++) {  // 使用 < 而不是 <=
    cout << nums[i] << " ";
}
```

**避免方法**：
1. 使用 `<` 而不是 `<=` 作為循環條件
2. 使用範圍基於的 for 循環 (range-based for loop)
3. 在訪問前檢查索引是否有效

### 2. 索引計算錯誤

**問題描述**：在計算數組索引時出錯，特別是在二分搜索或滑動窗口等算法中。

**錯誤示例**：
```cpp
// 錯誤示例 - 二分搜索中間點計算
int mid = (left + right) / 2;  // 可能導致整數溢出
```

**正確示例**：
```cpp
// 正確示例
int mid = left + (right - left) / 2;  // 避免整數溢出
```

**避免方法**：
1. 使用安全的索引計算方法
2. 注意整數溢出問題
3. 在複雜索引計算中添加註釋說明

## 邏輯和條件相關錯誤

### 1. 邏輯運算符使用錯誤

**問題描述**：混淆 `&&` (AND) 和 `||` (OR) 運算符，或者錯誤使用 `!` (NOT) 運算符。

**錯誤示例**：
```cpp
// 錯誤示例
if (x > 0 || x < 10) {  // 總是為真，應該使用 &&
    // 執行某些操作
}
```

**正確示例**：
```cpp
// 正確示例
if (x > 0 && x < 10) {  // 檢查 x 是否在 (0, 10) 範圍內
    // 執行某些操作
}
```

**避免方法**：
1. 仔細思考邏輯條件的含義
2. 對複雜條件進行分解和測試
3. 使用括號明確運算優先級

### 2. 條件語句中的賦值錯誤

**問題描述**：在條件語句中使用賦值運算符 `=` 而不是比較運算符 `==`。

**錯誤示例**：
```cpp
// 錯誤示例
if (x = 5) {  // 賦值而不是比較
    // 執行某些操作
}
```

**正確示例**：
```cpp
// 正確示例
if (x == 5) {  // 比較而不是賦值
    // 執行某些操作
}
```

**避免方法**：
1. 養成在條件語句中將常量放在左側的習慣 (如 `if (5 == x)`)
2. 使用支持警告此類錯誤的編譯器設置
3. 代碼審查時特別注意條件語句

## 記憶體和指針相關錯誤

### 1. 空指針解引用

**問題描述**：嘗試解引用空指針 (nullptr)。

**錯誤示例**：
```cpp
// 錯誤示例
TreeNode* node = nullptr;
int val = node->val;  // 解引用空指針
```

**正確示例**：
```cpp
// 正確示例
TreeNode* node = nullptr;
if (node) {
    int val = node->val;  // 在解引用前檢查
}
```

**避免方法**：
1. 在解引用前始終檢查指針是否為空
2. 使用智能指針減少空指針錯誤
3. 確保函數返回有效指針或明確處理空指針情況

### 2. 記憶體洩漏

**問題描述**：分配記憶體後未釋放，導致記憶體洩漏。

**錯誤示例**：
```cpp
// 錯誤示例
void processData() {
    int* data = new int[1000];
    // 處理數據
    // 忘記釋放記憶體
}
```

**正確示例**：
```cpp
// 正確示例
void processData() {
    int* data = new int[1000];
    // 處理數據
    delete[] data;  // 釋放記憶體
}
```

**避免方法**：
1. 使用智能指針 (如 `std::unique_ptr`, `std::shared_ptr`)
2. 遵循 RAII 原則 (Resource Acquisition Is Initialization)
3. 使用容器類代替原始數組
4. 使用記憶體洩漏檢測工具

## 其他常見錯誤

### 1. 未初始化變數

**問題描述**：使用未初始化的變數，導致未定義行為。

**錯誤示例**：
```cpp
// 錯誤示例
int sum;
for (int i = 0; i < 10; i++) {
    sum += i;  // sum 未初始化
}
```

**正確示例**：
```cpp
// 正確示例
int sum = 0;  // 初始化變數
for (int i = 0; i < 10; i++) {
    sum += i;
}
```

**避免方法**：
1. 在聲明變數時進行初始化
2. 使用編譯器警告檢測未初始化變數
3. 遵循變數最小作用域原則

### 2. 字符串比較錯誤

**問題描述**：使用 `==` 比較字符串對象而不是使用 `equals` 或 `compare` 方法。

**錯誤示例** (Java):
```java
// 錯誤示例
String s1 = new String("hello");
String s2 = new String("hello");
if (s1 == s2) {  // 比較引用而不是內容
    // 執行某些操作
}
```

**正確示例** (Java):
```java
// 正確示例
String s1 = new String("hello");
String s2 = new String("hello");
if (s1.equals(s2)) {  // 比較內容而不是引用
    // 執行某些操作
}
```

**避免方法**：
1. 了解不同語言中字符串比較的正確方法
2. 使用適當的字符串比較函數或方法
3. 注意字符串的大小寫敏感性

## C++ 資料結構選用心法

### 1. 有序 vs 無序容器的選擇

**問題描述**：在選擇容器類型時，經常默認使用有序容器（如 `set`、`map`），而忽略了無序容器（如 `unordered_set`、`unordered_map`）可能提供的性能優勢。

**心法**：
- 如果不需要元素有序，優先考慮使用無序容器
- 當看到需要使用 `set` 時，先問自己：「排序重要嗎？」如果不重要，立即考慮 `unordered_set`
- 同理，對於 `map` vs `unordered_map` 也是如此

**性能比較**：
- `set`/`map`: 插入、刪除、查找操作的時間複雜度為 O(log n)
- `unordered_set`/`unordered_map`: 平均情況下，這些操作的時間複雜度為 O(1)

**使用 `set`/`map` 的情況**：
- 需要元素按特定順序排列
- 需要範圍查詢（如找出所有大於 x 且小於 y 的元素）
- 需要使用自定義比較器
- 需要穩定的性能保證（無論數據分佈如何）

**使用 `unordered_set`/`unordered_map` 的情況**：
- 只需要快速查找、插入和刪除
- 不關心元素順序
- 數據分佈較為均勻（避免哈希衝突）
- 優先考慮平均性能而非最壞情況

**代碼示例**：
```cpp
// 不需要排序時，使用無序容器
unordered_set<int> seen;  // 而不是 set<int> seen;
unordered_map<string, int> counts;  // 而不是 map<string, int> counts;

// 需要排序時，使用有序容器
set<int> sortedNums;  // 元素自動排序
map<string, int> sortedCounts;  // 按鍵排序
```

### 2. 其他容器選擇心法

- **`vector` vs `list`**: 除非需要頻繁在中間插入/刪除元素，否則優先使用 `vector`
- **`deque` vs `vector`**: 需要在兩端高效插入/刪除時，考慮 `deque`
- **`priority_queue` vs 自行排序**: 需要維護「最大/最小元素」時，使用 `priority_queue`
- **`array` vs C 風格數組**: 優先使用 `std::array`，它提供了大小信息和邊界檢查

### 3. 處理重複元素的注意事項

**問題描述**：在使用 `set` 或 `unordered_set` 記錄狀態時，如果可能有重複元素，執行 `erase` 操作會移除所有相同的元素，因為這些容器不保存元素的數量信息。

**錯誤示例**：
```cpp
// 錯誤示例 - 使用 set 處理可能有重複元素的情況
set<int> elements = {1, 2, 3, 4, 5};
// ... 某些操作後可能添加了重複元素 ...
elements.insert(2);  // set 不允許重複，所以仍然只有一個 2
elements.erase(2);   // 移除了唯一的 2，而不是最近添加的那個
```

**正確示例**：
```cpp
// 正確示例 - 使用 multiset 處理重複元素
multiset<int> elements = {1, 2, 3, 4, 5};
elements.insert(2);  // 現在有兩個 2
elements.erase(elements.find(2));  // 只移除一個 2
// 或者使用 map/unordered_map 記錄元素出現次數
unordered_map<int, int> counter;
counter[2]++;  // 增加 2 的計數
counter[2]--;  // 減少 2 的計數
if (counter[2] == 0) counter.erase(2);  // 只在計數為 0 時移除
```

**避免方法**：
1. 如果需要處理重複元素，考慮使用 `multiset` 或 `multimap`
2. 或者使用 `map<Key, Count>` 手動記錄元素出現次數
3. 使用 `erase(iterator)` 而不是 `erase(value)` 來精確控制要移除的元素
4. 在算法題中，明確考慮是否需要處理重複元素的情況

**總結原則**：
1. 先考慮操作需求（查找、插入、刪除、排序等）
2. 再考慮性能需求（時間複雜度、空間複雜度）
3. 最後考慮特殊需求（如迭代器穩定性、內存布局等）
4. 特別注意數據中是否有重複元素，以及如何正確處理它們

## 解題前的關鍵假設檢查

在開始解題之前，檢查和理解題目的隱含假設是非常重要的。忽略這些假設可能導致解法錯誤或不必要的複雜性。

### 1. 輸入數據特性假設

**問題描述**：許多算法題目對輸入數據有隱含假設，但這些假設可能沒有明確說明。

**需要考慮的關鍵假設**：
- 輸入是否包含重複元素（distinct vs. duplicate）
- 輸入是否已排序
- 輸入是否可能為空
- 輸入數據的範圍（可能影響溢出處理）
- 輸入是否包含負數（對於某些算法很重要）

**錯誤示例**：
```cpp
// 錯誤示例 - 假設輸入沒有重複元素
vector<int> nums = {1, 2, 2, 3, 4};
unordered_set<int> numSet(nums.begin(), nums.end());
if (numSet.size() != nums.size()) {
    // 這個條件會為真，因為有重複元素
    // 但如果算法假設輸入沒有重複，可能會導致錯誤
}
```

**正確示例**：
```cpp
// 正確示例 - 明確檢查重複元素
vector<int> nums = {1, 2, 2, 3, 4};
unordered_set<int> numSet;
bool hasDuplicates = false;
for (int num : nums) {
    if (!numSet.insert(num).second) {
        hasDuplicates = true;
        break;
    }
}
// 根據是否有重複元素選擇不同的算法
```

**避免方法**：
1. 仔細閱讀題目，識別明確和隱含的假設
2. 考慮極端情況和邊界條件
3. 在代碼中添加檢查，驗證關鍵假設
4. 如果假設不明確，考慮多種可能性或在解題前澄清

### 2. 其他常見假設

- **數據結構特性**：例如，二叉樹是否平衡，圖是否有環
- **操作限制**：是否有時間或空間複雜度要求
- **返回值要求**：返回實際值還是索引，多解時返回任意解還是特定解
- **修改輸入**：是否允許修改原始輸入數據

在解題過程中，明確這些假設可以幫助你選擇正確的算法和數據結構，避免不必要的錯誤和優化。
