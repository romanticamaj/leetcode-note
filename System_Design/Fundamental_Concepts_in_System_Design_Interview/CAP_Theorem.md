# CAP 定理

CAP 定理是分散式系統設計中最重要的理論之一。它指出，任何一個分散式系統最多只能同時滿足以下三個特性中的兩個：

1. **一致性 (Consistency)**
2. **可用性 (Availability)**
3. **分區容錯性 (Partition Tolerance)**

由於現代分散式系統（如微服務、資料庫叢集）必須在網路上運行，而網路分區（Network Partition）是不可避免的，因此**分區容錯性 (P) 是一個必須滿足的前提**。

這意味著，在系統設計中，我們必須在**一致性 (C)** 和**可用性 (A)** 之間做出權衡。

---

## 核心概念詳解

### C - 一致性 (Consistency)

- **定義**：每次讀取操作都能讀取到**最近一次寫入**的資料，或者讀取失敗。
- **要求**：所有節點在同一時間看到的資料是完全一致的。
- **例子**：當你向一個 CP 系統寫入資料 `X=1` 後，任何後續的讀取請求，無論發送到哪個節點，都必須返回 `X=1`。如果某個節點還沒同步到最新資料，它必須拒絕讀取請求，返回錯誤。

### A - 可用性 (Availability)

- **定義**：每次請求都能收到一個**非錯誤**的回應，但不保證這個回應是最新寫入的資料。
- **要求**：系統中的每個非故障節點都能夠回應請求。
- **例子**：當你向一個 AP 系統發出讀取請求時，即使某個節點因為網路分區而無法取得最新資料，它仍然會回傳它目前擁有的舊版本資料，而不是返回錯誤。

### P - 分區容錯性 (Partition Tolerance)

- **定義**：即使系統中任意數量的訊息被延遲或丟失（即發生網路分區），系統仍然能夠繼續運行。
- **要求**：這是現代分散式系統的**基本要求**。網路是不可靠的，節點之間的通訊隨時可能中斷。系統必須能夠在這種情況下保持運作。

---

## C 與 A 的權衡 (Trade-off)

當網路分區 (P) 發生時，系統設計者必須做出選擇：

### 選擇 CP (Consistency over Availability)

- **策略**：為了保證資料一致性，系統會犧牲可用性。
- **行為**：當分區發生時，如果一個節點無法確定它擁有的是最新資料，它會**拒絕服務**（例如，拒絕讀取或寫入請求），直到分區問題解決，資料同步完成。
- **適用場景**：
  - **金融交易**：銀行系統不能容忍帳戶餘額不一致。
  - **訂單系統**：庫存數量必須是精確的。
- **代表系統**：
  - **傳統關聯式資料庫** (如 MySQL, PostgreSQL) 的主從同步模式。
  - **ZooKeeper**, **etcd**：用於分散式協調，強烈依賴一致性。
  - **HBase**

### 選擇 AP (Availability over Consistency)

- **策略**：為了保證系統總是可用的，系統會犧牲強一致性。
- **行為**：當分區發生時，節點會繼續回應請求，即使它回傳的可能是**過時的資料**。資料最終會透過非同步方式達成一致，這個概念被稱為「**最終一致性 (Eventual Consistency)**」。
- **適用場景**：
  - **社群媒體**：使用者看到幾秒鐘前的舊動態是可以接受的。
  - **電商網站的商品瀏覽**：短時間內商品評論數不一致不會造成嚴重問題。
- **代表系統**：
  - **Cassandra**, **DynamoDB**：設計初衷就是高可用性和高延展性。
  - **DNS**：域名解析系統，可用性至關重要。

---

## 視覺化理解

```
      Consistency (C)
         /       \
        /         \
      CP Systems   AP Systems
      (犧牲 A)     (犧牲 C)
     /               \
    /                 \
Availability (A) --- Partition Tolerance (P)
```

在一個穩定的網路中，系統可以同時達成 C 和 A。但一旦 P（網路分區）發生，系統必須沿著 `C-P` 或 `A-P` 的路徑走，無法同時擁有兩者。

---

## 🧠 總結

- **CAP 定理**是分散式系統設計的基石。
- **分區容錯性 (P)** 在現代系統中是**必須**的。
- 設計者必須在**一致性 (C)** 和**可用性 (A)** 之間做出權衡。
- **CP 系統**優先保證資料的精確性，犧牲了部分可用性。
- **AP 系統**優先保證服務的不中斷，接受資料的最終一致性。
