# AJAX Polling

**AJAX Polling** 是一種客戶端-伺服器通信技術，客戶端透過定期、重複地向伺服器發送 HTTP 請求來模擬伺服器推送 (Server Push) 的功能，以獲取最新的資料。

這種技術主要用於解決傳統 Web 應用中，伺服器無法主動將更新推送給客戶端的問題。

---

## 核心類型

Polling 主要分為兩種形式：短輪詢 (Short Polling) 和長輪詢 (Long Polling)。

### 1. 短輪詢 (Short Polling)

這是最直接的 Polling 形式。

**運作流程：**

1. **客戶端發送請求**：客戶端以固定的時間間隔（例如，每 2 秒）向伺服器發送一個 AJAX 請求。
2. **伺服器立即回應**：伺服器收到請求後，立即查詢是否有新的資料。
   - 如果有新資料，就將資料返回給客戶端。
   - 如果沒有新資料，也立即返回一個空的回應或表示沒有更新的狀態。
3. **客戶端處理回應**：客戶端收到回應後，處理資料（如果有的話），然後等待下一個固定的時間間隔，再次發送請求。

**優點：**

- 實現非常簡單。
- 對伺服器的負載相對穩定和可預測。

**缺點：**

- **高延遲**：資料更新的延遲最高可能等於輪詢間隔。如果輪詢間隔是 5 秒，那麼使用者最多可能需要等待 5 秒才能看到更新。
- **資源浪費**：大量的請求可能沒有任何有效資料返回，造成了不必要的網路流量和伺服器處理開銷。

### 2. 長輪詢 (Long Polling / Hanging GET)

長輪詢是短輪詢的一種變體和優化，旨在減少延遲和空請求。因為客戶端的 GET 請求會被伺服器「掛起 (hang)」直到有新資料為止，所以它也常被稱為 **Hanging GET**。

**運作流程：**

1. **客戶端發送請求**：客戶端向伺服器發送一個 AJAX 請求。
2. **伺服器保持連接**：伺服器收到請求後，**不會立即回應**。它會檢查是否有新資料。
   - 如果有新資料，立即將資料返回給客戶端。
   - 如果沒有新資料，伺服器會**保持 (hold) 這個請求打開**，直到有新資料可用或達到預設的超時時間。
3. **客戶端處理回應**：
   - 客戶端收到伺服器的回應後，立即處理資料。
   - 處理完畢後，客戶端會**立即**再次發起一個新的長輪詢請求，重複這個過程。
   - 如果請求因為超時而返回，客戶端也會立即發起新請求。

**優點：**

- **低延遲**：一旦有新資料，伺服器會立即將其推送給客戶端，即時性遠高於短輪詢。
- **減少空請求**：大大減少了沒有資料更新的無效請求，節省了網路頻寬。

**缺點：**

- **伺服器資源消耗**：長時間保持連接會消耗伺服器的資源（如記憶體、連接數）。在高併發場景下，這可能成為瓶頸。
- **實現複雜度**：相較於短輪詢，伺服器端的實現更為複雜。
- **訊息順序問題**：在某些情況下，如果網路不穩定，請求的返回順序可能無法保證。

## Polling vs. 其他技術

| 技術                         | 描述                         | 優點                      | 缺點                           |
| :--------------------------- | :--------------------------- | :------------------------ | :----------------------------- |
| **Short Polling**            | 客戶端固定間隔請求           | 簡單、可靠                | 延遲高、浪費資源               |
| **Long Polling**             | 客戶端請求，伺服器有資料才回 | 延遲低、效率較高          | 消耗伺服器連接資源             |
| **WebSocket**                | 全雙工通信，伺服器可主動推送 | 真實時、高效能            | 瀏覽器支援性、需要專門的伺服器 |
| **Server-Sent Events (SSE)** | 伺服器到客戶端的單向推送     | 簡單、基於 HTTP、自動重連 | 單向通信、有瀏覽器連接數限制   |

## 應用場景

- **即時聊天室**：早期的聊天室常用長輪詢來接收新訊息。
- **線上通知**：網站右上角的通知紅點，可以用長輪詢來檢查是否有新通知。
- **股票報價**：需要頻繁更新但對即時性要求不是極端嚴格的場景。
- **進度條更新**：當後端處理一個長時間任務時，前端可以透過 Polling 來獲取最新的進度狀態。
