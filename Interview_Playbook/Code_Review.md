# Code Review 心法：從口訣到實踐

在提交程式碼前進行自我檢查（Self-Review）是提升程式碼品質與正確性的關鍵一步。本文件提供一個從記憶口訣到詳細清單的系統性方法，幫助你建立高效的 Code Review 習慣。

---

## 記憶口訣：『名型邏界』

這四字口訣涵蓋了 Code Review 的核心面向，能幫助你快速進行第一輪心智掃描：

- **名 (Míng) - 命名**：變數、函式名稱是否清晰達意？
- **型 (Xíng) - 型別**：容器、參數、回傳值的型別是否正確且一致？
- **邏 (Luó) - 邏輯**：演算法流程、資料結構操作是否符合預期？
- **界 (Jiè) - 邊界**：迴圈條件、遞迴終止、極端輸入是否都已考慮？

默念「名、型、邏、界」，逐一檢視你的程式碼，就能捕捉到多數常見錯誤。

---

## 系統性 Code Review 詳細清單

當時間充裕時，可以使用以下清單進行更深入的檢查。清單圍繞『名型邏界』口訣展開。

### 1. 名 (命名與風格)

> **目標：程式碼是否易於閱讀與理解？**

- [ ] **函式命名**：名稱是否清晰地表達其**意圖**和**作用**？（例如，`isValidBST` 優於 `checkTree`）
- [ ] **變數命名**：名稱是否具備**描述性**？（例如，`currentIndex` 優於 `i`，`memo` 優於 `dp`）
- [ ] **風格一致性**：命名風格（如 `camelCase` vs. `snake_case`）是否在整個程式碼中保持一致？

### 2. 型 (語法與型別)

> **目標：語法是否正確？型別是否匹配？**

- [ ] **容器維度與型別**：`vector<vector<int>>` vs. `vector<int>`？`queue<TreeNode*>` vs. `queue<int>`？
- [ ] **函式參數**：
  - **型別**是否正確？（`int` vs. `long long`）
  - **傳遞方式**是否恰當？（傳值 `T`、傳參考 `T&`、`const T&`）
- [ ] **`std` 演算法參數**：
  - `std::sort` 的比較函式邏輯是否正確？
  - `std::min`/`std::max` 的參數型別是否匹配？（避免 `int` 和 `size_t` 的隱性轉換陷阱）
  - `std::accumulate` 的初始值型別和數值是否正確？（加法用 `0LL`，乘法用 `1LL`）
- [ ] **拼字與分號**：是否有拼字錯誤、缺少分號或括號不對稱？

### 3. 邏 (核心邏輯)

> **目標：演算法的每一步是否都如預期般運作？**

- [ ] **變數生命週期**：變數是否在**正確的時機**被初始化、讀取和更新？
- [ ] **資料結構操作**：
  - `push`/`pop`、`insert`/`erase` 是否成對、平衡出現？
  - 操作前是否有**空容器檢查**？（如 `if (!q.empty())`）
- [ ] **回傳值**：
  - 回傳的**變數**和**型別**是否都符合題目要求？
  - 在所有邏輯分支中是否都有 `return` 語句？
- [ ] **狀態重設**：在遞迴（特別是 Backtracking）中，狀態是否在回溯時被正確重設？

### 4. 界 (邊界條件)

> **目標：程式碼能否處理所有極端情況？**

- [ ] **迴圈條件**：`i < n` vs. `i <= n` 是否邊界清晰？
- [ ] **遞迴終止**：Base Case 是否明確且能處理所有終止情況？
- [ ] **輸入邊界**：
  - 空輸入（如空陣列、空字串、`nullptr`）
  - 單元素輸入
  - 最大/最小值輸入
- [ ] **算術邊界**：是否考慮整數溢位？（參考 [Arithmetic Overflow Prevention Playbook](./Arithmetic_Overflow_Prevention_Playbook.md)）

## LeetCode 錯誤類型與『名型邏界』的對應關係

你可以利用這個口訣快速定位錯誤來源：

| 錯誤類型          | 主要關聯口訣                 | 檢查點                                        |
| :---------------- | :--------------------------- | :-------------------------------------------- |
| **Compile Error** | **名** (命名)、**型** (型別) | 拼字、分號、函式簽名、`std` 演算法參數        |
| **Runtime Error** | **界** (邊界)、**邏** (邏輯) | 空指標、陣列越界、非法操作（如 `pop` 空佇列） |
| **Wrong Answer**  | **邏** (邏輯)、**界** (邊界) | 演算法流程、回傳值、狀態更新、邊界處理        |

透過這套從口訣到清單，再到錯誤定位的系統性方法，你可以大幅提升 Code Review 的效率與品質，有效降低錯誤率。
