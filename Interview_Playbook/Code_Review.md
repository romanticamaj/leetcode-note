# Code Review 心法與檢查清單

## Review Code 的通用心法

在提交程式碼前進行自我檢查（self-review）是提升正確性與品質的關鍵步驟。以下是幾個實用的檢查心法：

### 1. 檢查所有額外資料結構的操作是否完整

- 是否有成對的 `add` / `remove` 操作？（如 `push_back` / `pop_back`、`insert` / `erase`）
- 是否有遞迴後清除狀態？（特別是在 DFS / backtracking 中）
- 是否有初始化與清空的時機？

### 2. 檢查 return value 的正確性

- 回傳的型別是否正確？（如 `bool`、`int`、`vector<int>`）
- 回傳的值是否符合題目要求？
- 是否有遺漏 return？（特別是在遞迴或條件分支中）

### 3. 檢查終止條件是否正確

- 遞迴的 base case 是否明確？
- 是否涵蓋所有邊界情況？（如空輸入、單節點、極端值）
- 是否可能進入無限遞迴或死循環？

### 4. 檢查型別是否一致

- 每個資料結構的元素型別是否正確？（如 `vector<int>` 中是否誤用 `string`）
- return 的型別是否與函式宣告一致？
- 是否有隱性型別轉換導致錯誤？（如 `int` 被當成 `bool` 使用）

### 5. 追蹤變數的生命週期與使用

這是一個基本但極其強大的檢查方法，能幫助你理清程式的資料流並發現潛在問題。

1. **找到每個變數宣告的地方**：

   - 確認變數的**作用域 (scope)** 是否是最小且必要的。全域變數或類別成員變數是否真的有必要？
   - 變數的**初始化**是否正確？有沒有未初始化的變數？

2. **確認每個變數被使用的情況**：
   - 從宣告處開始，往下追蹤該變數所有被讀取和寫入的地方。
   - 這個變數是否在預期的地方被修改？
   - 有沒有「只寫未讀」的無用變數？
   - 有沒有在還沒賦值前就被讀取？

這個簡單的兩步驟能有效幫助你發現如變數遮蔽 (shadowing)、作用域混亂、非預期修改等難以察覺的 bug。

### 建議流程

1. **從資料結構開始檢查**：確認每個 `push` 是否有對應的 `pop`，每個 `insert` 是否有 `erase`
2. **檢查每個 return 的型別與值**：是否符合題目預期？是否有遺漏？
3. **逐層檢查終止條件**：從最外層到最內層，確認每個遞迴或迴圈都有正確的結束條件
4. **模擬一組輸入**：手動 trace 一次流程，觀察資料結構與 return 的變化

這些心法能幫助你在提交前發現潛在錯誤，提升程式碼的正確性與穩定性。

## 降低 LeetCode 提交錯誤率的實戰心法

在實作方向正確的前提下，若仍常見 Compile Error、Runtime Error、Wrong Answer，代表在「提交品質」上仍有優化空間。以下是針對不同錯誤類型的具體心法：

---

### 1. Compile Error：語法錯誤

**心法：提交前，逐行檢查一次**

- 檢查每一行是否有：
  - 少打 `;`、括號不對稱、拼錯變數名
  - 型別錯誤（如 `TreeNode` vs `TreeNode*`）
  - 函式簽名與 return 型別不一致
- **特別注意**：LeetCode 的函式簽名與 class 名稱是否照抄正確

建議流程：

- 實作完畢後，**從上到下`逐行掃描`一次**
- 對每個變數、函式、return，**問自己：型別正確嗎？拼對了嗎？**

---

### 2. Runtime Error：執行時錯誤

**心法：模擬一組輸入，觀察資料結構與邊界行為**

- 常見原因：
  - 空指標解引用（如 `node->val` 沒有先檢查 `node`）
  - 陣列越界（如 `i <= nums.size()`）
  - 除以 0、無效操作（如 `pop()` 空佇列）
- 建議流程：
  - 手動 trace 一組輸入（特別是邊界：空、單元素、極端值）
  - 檢查每個資料結構操作是否有前置條件（如 `if (!dq.empty())`）

---

### 3. Wrong Answer：邏輯錯誤

**心法：先寫出預期輸入輸出，再對照 trace**

- 常見原因：
  - return 條件錯誤（如 return 錯誤的變數）
  - 遞迴 return 沒有正確聚合子結果
  - 忘記更新全域變數或答案容器
- 建議流程：
  - 在草稿紙上寫出 1~2 組輸入與預期輸出
  - 手動 trace 程式，對照每一步的變數與 return 值

---

### 總結：降低錯誤率的三層檢查

| 錯誤類型      | 提交前檢查點                     |
| ------------- | -------------------------------- |
| Compile Error | 語法、型別、拼字、函式簽名       |
| Runtime Error | 空指標、越界、非法操作、邊界條件 |
| Wrong Answer  | return 值、答案更新、邏輯分支    |

這些心法能幫助你在「實作方向正確」的前提下，大幅降低 LeetCode 的 reject rate，提升一次通過率。
